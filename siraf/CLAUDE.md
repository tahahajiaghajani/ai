# «سیراف» (Siraf) — notes for Claude

Fully independent project in a sub-folder of this repository (own package.json, Vercel project with Root Directory `siraf`, own Supabase project). Persian (RTL) accounting and business app with three modules — goods (inventory/commerce), gold & jewellery, currency exchange & crypto — that runs as a **web app** (Vercel + Supabase) and a **Windows app** (Electron + embedded PostgreSQL/PGlite) kept in sync. Read `docs/ARCHITECTURE_FA.md`, `docs/SETUP_FA.md`, `docs/DESKTOP_FA.md`, `docs/BRAND_FA.md` and `docs/RESEARCH_FA.md` before larger changes, and `docs/CONNECTIONS_FA.md` (every outside service, the recommended free ones, exact UI labels) before changing a connection.

- **Name.** The product is «سیراف» / Siraf (until Nov 2026 «تراز» / Taraz). Use `APP_NAME`/`APP_NAME_EN`/`APP_TAGLINE` from `src/shared/constants.ts`; never hard-code it. «تراز» stays only in its accounting senses (تراز آزمایشی، ترازنامه، تراز افتتاحیه…). Internal identifiers keep the old name on purpose so existing data and installs keep working: `tz_*` tables, `TARAZ_*` env vars, `taraz:*` IPC channels and `window.taraz`, the `taraz.*` PostgreSQL settings and older `taraz.*` storage keys.
- **One codebase, two runtimes.** UI: `src/ui` (React 19, Ant Design 6 RTL, Tailwind 4; the Siraf design system in `src/ui/siraf` — read `src/ui/siraf/README.md` before touching UI: `--sf-*` tokens only, no raw hex, Dusk used sparingly, type in Arad (the wordmark's face) with every digit from «Siraf Num» and weights only from `--sf-weight-*` (450/540/600), tabular numbers that never ellipsize, `lucide-react` icons, Vite → `public/`). API: one Hono app (`src/server/app.ts`) mounted by Next.js on Vercel (`src/server/cloud.ts`, postgres.js) and by the desktop local server (`src/desktop/server.ts`, PGlite). Shared logic in `src/shared` (money with decimal.js — never floats; Jalali dates; gold formulas; validators; entity definitions; permissions).
- **Database:** tables `tz_*`, RLS on with no policies. Migrations are TS modules in `src/server/db/migrations` (idempotent SQL; never edit a shipped one, add a new file and register it in `index.ts`), applied automatically on both runtimes; `npm run schema` regenerates `supabase/schema.sql` + `supabase/migrations/*.sql` (CI checks with `npm run check:schema`).
- **Cloud database client** (`src/server/db/postgres.ts`): postgres.js through Supabase's transaction pooler with `prepare: false` and `max_pipeline: 1`. The pooler loses pipelined queries (sent on a connection while an earlier one there is unanswered), and postgres.js 4 pipelines by default whenever more queries are in flight than the pool holds, so never remove it. `tests/cloud-pipeline.test.ts` counts pipelined queries through a proxy. Parallel reads (`Promise.all`) are fine: extra queries wait for a free connection, at most `queue_timeout`.
- **Sync:** aggregate roots carry `rev/updated_at/deleted_at/origin`; trigger `tz_sync_touch` assigns per-org revisions (cloud) or queues `tz_outbox` (desktop). New synced roots need a trigger in a migration and an entry in `src/server/sync/registry.ts`. Changing children must update the root row. Soft-delete roots.
- **Writes** only inside `ctx.write(async (tx) => …)` using `tx` (PGlite is single-connection). Check permissions with `ctx.need(area, level)`. Auto vouchers via `postAuto` (`src/server/modules/accounting/vouchers.ts`) using account roles (`accountByKey`).
- **UI conventions:** every page starts with `PageHeader`; use the kit in `src/ui/components/*` (`ServerTable`, `EntityPage`, `MoneyInput`, `DateInput` (Jalali), `RefSelect`/`PartySelect`/`AccountSelect`, `Money`, `JDate`, `StatusTag`); all text Persian; Persian digits via `faDigits`/`formatNumber`; logical spacing utilities; AntD v6 props (`Drawer size`, `destroyOnHidden`, `Alert title`, `Tag variant`).
- **Printing** (`src/ui/lib/print.ts`): an antd table with a sticky header passes `sticky={printing ? undefined : …}` (`usePrinting()`), or its header prints as a separate, misaligned table; a sheet with a paper of its own prints through `printWithPage(size, margin)` (it also tells the Windows app the paper). A table of nine columns or more, or `.sf-print-wide`, prints on A4 landscape (kit.css); invoices are A4 landscape like the official form. Check prints with a sweep at the real printable width (A4 portrait 718 px, landscape 1031 px, A5 498–506 px).
- **Modules** register nav + routes in `src/ui/modules/<module>/index.tsx` (assembled in `registry.tsx`) and API routes in `src/server/routes/<module>.ts` (mounted in `routes/modules.ts`).
- **Desktop:** Electron main/preload/splash in `desktop/src` (`splash.html` is the 520×320 frameless splash driven from `main.ts` through `siraf.step/status/ready`; window background follows the theme reported by the preload), Windows art in `desktop/build` (from the brand package via `npm run icons -- <brand/final>`), packaging config `desktop/electron-builder.yml` (NSIS, Persian, `Siraf-Setup-x.y.z.exe`), build `node scripts/build-desktop.mjs` then `cd desktop && npx electron-builder --win`. CI `.github/workflows/siraf.yml` builds on Windows, smoke-tests (`Siraf.exe --smoke-test`) and publishes to Releases (`siraf-vX.Y.Z` from `main`, `siraf-preview` otherwise).
- **Access levels:** platform super admin (`is_platform_admin`) and, inside a business, CORE_ROLES owner/accountant/viewer plus PRESET_ROLES (src/shared/permissions.ts; area `ai` for AI). A platform admin who is not a member has NO access except through an audited support session (src/server/modules/platform, context.ts); business status (read_only/suspended) is enforced in ctx.write and sync. Record security-relevant actions with `securityEvent()`.
- **AI** (docs/AI_FA.md): per-business connections and keys (encrypted, never returned) in `src/server/modules/ai`; Claude only through `@anthropic-ai/sdk` 1.x (no temperature/top_p/top_k, adaptive thinking, no forced tool_choice, replay native content unchanged, append-only history); never call a model inside ctx.write/db.tx. Assistant tools (`modules/ai/tools`) must repeat their route's permission and module checks, return bounded data with units and Jalali periods, and never write — writes are proposals confirmed by a person (`tools/proposals.ts`). Numbers come from code (`analytics`), the model only narrates. AI tables are LOCAL_ONLY (each runtime has its own keys). Shared contracts: `src/shared/ai/{types,api}.ts`. Test mode: `SIRAF_AI_FAKE=1`.
- **Live prices** (docs/CONNECTIONS_FA.md): every outbound call goes through `ctx.cfg.fetch` with a timeout and a Persian message naming the service. The tgju feed (`src/server/modules/fx/tgju.ts`) has two copies, `call1.tgju.org` in Iran (asked first on the desktop) and `call.tgju.org` abroad (first on the web); it feeds the gold board and, for rial/toman bases, the exchange board. Custom sources read values with `@shared/json-path` (`a.b`, `a[0]`, `a[field=value]`). The live ticker never asks quota-limited sources (custom, tgju) while a stored USD rate exists.
- **Gold coins and bars:** coins are `tz_items` (kind coin) with `rate_key` + `gold_meta`; bars are the synced root `tz_gold_bars` (serial register, specific cost) and line kind `bar`; pure pricing in src/shared/gold*.ts (preview = posting).
- Commands: `npm run typecheck` · `npm test` · `npm run build` (must pass with no env vars) · `npm run start:local` (desktop flavour without Electron) · `node scripts/ui-shots.mjs` (screenshots of every page in light/dark/mobile with an error report).
