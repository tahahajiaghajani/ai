# راه‌اندازی «سیراف» (GitHub + Supabase + Vercel + نسخهٔ ویندوز)

«سیراف» یک پروژهٔ **کاملاً مستقل** در پوشهٔ `siraf` همین مخزن است (کد، پایگاه داده و تنظیماتش با پروژه‌های دیگر مخزن مشترک نیست). دو شکل دارد که با هم **هم‌گام** می‌مانند:

| نسخه | کجا اجرا می‌شود | داده کجاست |
|---|---|---|
| **وب** | Vercel (همان روش همیشگی) | Supabase |
| **ویندوز** | روی رایانهٔ کاربر، با یک فایل نصب | PostgreSQL داخلی خود برنامه (بدون نصب جداگانه) |

هر کاربر (کسب‌وکار) در نسخهٔ وب حساب می‌سازد؛ نسخهٔ ویندوز را با همان ایمیل و رمز به حسابش وصل می‌کند و از آن به بعد هر تغییر در هر طرف، ظرف چند ثانیه به طرف دیگر می‌رسد. بدون اینترنت هم نسخهٔ ویندوز کامل کار می‌کند و تغییرات در صف می‌مانند تا اینترنت وصل شود.

**بدون هیچ متغیر محیطی هم build می‌شود.** فقط برای اجرا به `DATABASE_URL` نیاز دارد.

---

## ۱. پایگاه داده (Supabase)

1. در [supabase.com](https://supabase.com) ← **New project**. نام: `siraf` (پروژه‌ای که پیش‌تر با نام `taraz` ساخته‌اید همان‌طور کار می‌کند)، یک رمز قوی برای پایگاه داده (یادداشت کنید)، **Region: Central EU (Frankfurt)** — نزدیک‌ترین به ایران و به سرور Vercel در فرانکفورت.
2. منوی **SQL Editor** ← **New query** ← کل محتوای فایل [`siraf/supabase/schema.sql`](../supabase/schema.sql) را بچسبانید ← **Run**.
   - اجرای دوباره بی‌خطر است (همهٔ دستورها idempotent هستند).
   - اگر این کار را فراموش کنید هم مشکلی نیست: برنامه هنگام اولین اجرا خودش جدول‌ها را می‌سازد (`AUTO_MIGRATE`). فایل `schema.sql` برای کسی است که می‌خواهد کنترل کامل داشته باشد.
   - همهٔ جدول‌ها با پیشوند `tz_` ساخته می‌شوند، RLS روشن است و هیچ دسترسی‌ای از کلیدهای عمومی Supabase (anon/authenticated) ندارند؛ فقط سرور خود برنامه به پایگاه داده وصل می‌شود.
3. **رشتهٔ اتصال** را بردارید: بالای داشبورد دکمهٔ **Connect** ← بخش **Transaction pooler** (پورت `6543`) ← نشانی را کپی کنید و به‌جای `[YOUR-PASSWORD]` رمز مرحلهٔ ۱ را بگذارید. چیزی شبیه این:
   ```
   postgresql://postgres.abcdefghijklmnop:رمز@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
   ```
   > اگر رمز نویسه‌های خاص مثل `@`، `#` یا `/` دارد، آن را URL-encode کنید (مثلاً `@` ← `%40`) یا رمز ساده‌تری بگذارید.

> **به‌روزرسانی‌های بعدی:** وقتی نسخهٔ تازه‌ای از کد منتشر شود که جدول تازه‌ای بخواهد، برنامه خودش migrationهای جاافتاده را اعمال می‌کند. اگر `AUTO_MIGRATE=false` گذاشته‌اید، فقط فایل‌های تازهٔ پوشهٔ [`siraf/supabase/migrations`](../supabase/migrations) را به‌ترتیب در SQL Editor اجرا کنید.

## ۲. انتشار روی Vercel

1. کد این شاخه را در GitHub به `main` ادغام کنید (پوشهٔ `siraf` باید در `main` باشد).
2. [vercel.com/new](https://vercel.com/new) ← مخزن GitHub (`ai`) را **Import** کنید. این یک **پروژهٔ تازه** در Vercel است (نام پیشنهادی: `siraf`)؛ به پروژه‌های موجود دست نزنید.
3. **Root Directory** را روی `siraf` بگذارید (مهم). اگر پروژهٔ Vercel را پیش از تغییر نام ساخته‌اید، همین‌جا `taraz` را به `siraf` تغییر دهید و یک بار Redeploy کنید. Framework خودکار **Next.js** تشخیص داده می‌شود؛ Build Command از `vercel.json` خوانده می‌شود (`npm run build` = ساخت رابط کاربری با Vite + Next.js برای API). بقیه را دست نزنید.
4. **Environment Variables**:

| نام | مقدار |
|---|---|
| `DATABASE_URL` | **لازم.** رشتهٔ اتصال Transaction pooler از مرحلهٔ ۱ (پورت 6543). |
| `APP_SECRET` | **برای هوش مصنوعی لازم است.** یک رشتهٔ تصادفی ۳۲ نویسه‌ای یا بیشتر (مثلاً خروجی `openssl rand -hex 32`). کلیدهای هوش مصنوعی و اتصال‌ها (فروشگاه اینترنتی و …) با آن رمزنگاری می‌شوند؛ بدون آن کلید هوش مصنوعی ذخیره نمی‌شود. پس از گذاشتن، عوضش نکنید؛ کلیدهای ذخیره‌شده دیگر خوانده نمی‌شوند و باید دوباره وارد شوند. |
| `PLATFORM_ADMIN_EMAILS` | پیشنهادی. ایمیل خودتان (مدیر کل سامانه)؛ چند ایمیل را با ویرگول جدا کنید. این حساب‌ها **کنسول مدیریت سامانه** (`/admin`) را دارند. اگر خالی باشد، اولین حسابی که ساخته شود مدیر کل سامانه است. |
| `ALLOW_SIGNUP` | اختیاری. پیش‌فرض باز است؛ با `false` ثبت‌نام عمومی بسته می‌شود و فقط شما (یا مدیران کسب‌وکارها از «تنظیمات ← کاربران») حساب می‌سازید. |
| `CRON_SECRET` | اختیاری. یک رشتهٔ تصادفی تا فقط خود Vercel نشانی بیدار نگه داشتن Supabase را صدا بزند. |
| `AUTO_MIGRATE` | اختیاری. پیش‌فرض `true`. با `false` برنامه خودش جدول نمی‌سازد. |
| `DATABASE_POOL_MAX` | اختیاری. حداکثر اتصال هم‌زمان هر نمونهٔ سرور (پیش‌فرض ۳). |

5. **Deploy**. چند دقیقه بعد برنامه روی زیردامنهٔ Vercel آماده است. پاسخ‌های دستیار هوش مصنوعی از مسیر جداگانه‌ای با حداکثر زمان ۳۰۰ ثانیه می‌آیند. این تنظیم در خود کد است و کاری لازم ندارد.
6. **منطقهٔ اجرا:** پروژه ← **Settings ← Functions ← Function Region** ← **Frankfurt, Germany (fra1)** را انتخاب و یک بار Redeploy کنید تا سرور کنار پایگاه داده باشد (هر درخواست چند برابر سریع‌تر می‌شود).
7. **اولین حساب:** نشانی سایت را باز کنید ← «ساخت حساب تازه» (با همان ایمیل `PLATFORM_ADMIN_EMAILS`، اگر گذاشته‌اید؛ وگرنه اولین حسابی که ساخته شود مدیر سامانه است). **کد بازیابی** را که نمایش داده می‌شود یادداشت کنید (تنها راه بازیابی رمز بدون ایمیل). بعد کسب‌وکار را با ویزارد بسازید (نوع فعالیت ← ماژول‌ها ← مشخصات).

> **بیدار ماندن Supabase:** پروژهٔ رایگان Supabase پس از یک هفته بی‌استفاده‌ماندن متوقف می‌شود. `vercel.json` هر روز نشانی `/api/cron/keepalive` را صدا می‌زند؛ کار دیگری لازم نیست.
>
> **چند پروژهٔ Vercel روی یک مخزن:** هر پروژهٔ Vercel که به این مخزن وصل است با هر push ساخته می‌شود. برای این‌که پروژهٔ سیراف فقط با تغییر پوشهٔ خودش ساخته شود: Vercel ← پروژه ← Settings ← Git ← **Ignored Build Step** ← Custom: `git diff HEAD^ HEAD --quiet -- .` و در پروژهٔ Task Flow (ریشهٔ مخزن) پوشهٔ `siraf` را هم مثل بقیه کنار بگذارید: `git diff HEAD^ HEAD --quiet -- . ':(exclude)pars-website' ':(exclude)celin-website' ':(exclude)siraf'`.
>
> **پلن Vercel:** پلن رایگان Hobby طبق قوانین Vercel برای استفادهٔ غیرتجاری است؛ برای ارائه به مشتریان، پلن Pro را در نظر بگیرید.

### مدیریت سامانه و سطح‌های دسترسی

- **مدیر کل سامانه** (`PLATFORM_ADMIN_EMAILS`): کنسول `/admin` با پیشخوان، کسب‌وکارها (وضعیت فعال / فقط‌خواندنی / معلق، یادداشت، خاموش کردن هوش مصنوعی)، کاربران (غیرفعال کردن، خروج از همهٔ دستگاه‌ها، رمز موقت با ذکر دلیل، دادن یا گرفتن مدیریت سامانه)، هوش مصنوعی (سیاست و مصرف هر کسب‌وکار، هرگز کلید)، رویدادهای امنیتی و سلامت سامانه.
- مدیر کل سامانه دادهٔ کسب‌وکاری را که عضوش نیست مستقیم نمی‌بیند. برای پشتیبانی، از صفحهٔ همان کسب‌وکار **«حالت پشتیبانی»** را با ذکر دلیل، سطح (مشاهده یا ویرایش) و حداکثر ۴ ساعت شروع می‌کند. هر کاری در این حالت با برچسب پشتیبانی در «گزارش رویدادها»ی همان کسب‌وکار ثبت می‌شود و مالک می‌تواند جلسه را زودتر تمام کند.
- **داخل هر کسب‌وکار** سه سطح اصلی هست: **مالک** (همه چیز)، **حسابدار** (همهٔ عملیات و گزارش‌ها، اتصال‌ها و کلیدهای هوش مصنوعی؛ کاربران را فقط می‌بیند)، **ناظر** (فقط مشاهده و پرسش از دستیار). نقش‌های بیشتر (مدیر، فروشنده، صندوقدار، انباردار) آماده‌اند و دسترسی هر عضو را می‌توان بخش‌به‌بخش تغییر داد.

### هوش مصنوعی

هر کسب‌وکار کلید سرویس دلخواهش را در «تنظیمات ← هوش مصنوعی» وارد می‌کند (مالک و حسابدار). راهنمای کامل: [AI_FA.md](AI_FA.md).

## ۳. دامنهٔ اختصاصی و دسترسی از داخل ایران

- Vercel ← پروژه ← Settings ← **Domains** ← دامنهٔ خودتان (مثلاً `app.example.ir`) را اضافه و رکوردهای DNS گفته‌شده را بسازید.
- دامنه‌های `vercel.app` گاهی در ایران محدود می‌شوند؛ با دامنهٔ اختصاصی وضعیت بهتر است. مرورگر کاربر **فقط با دامنهٔ خود برنامه** حرف می‌زند (فونت‌ها و همهٔ فایل‌ها از همان‌جا) و Supabase فقط از سمت سرور صدا زده می‌شود.
- برای پایداری بیشتر یک CDN داخلی (مثل ابرآروان) جلوی دامنه بگذارید، یا برنامه را روی یک سرور داخلی اجرا کنید (همان کد Next.js به‌صورت `standalone` ساخته می‌شود):
  ```bash
  cd siraf && npm ci && npm run build
  DATABASE_URL=... node .next/standalone/server.js   # پوشه‌های public و .next/static را کنار آن کپی کنید
  ```
- **قیمت‌های زنده:** سرویس‌های ایرانی (مثل نوبیتکس و tgju) فقط از داخل ایران پاسخ می‌دهند و بعضی سرویس‌های خارجی ایران را مسدود می‌کنند. نسخهٔ ویندوز قیمت‌ها را از اینترنت خود فروشگاه می‌گیرد و نسخهٔ وب از سرور Vercel؛ در تنظیمات هر ماژول می‌توانید منبع قیمت را عوض کنید یا «منبع سفارشی» (هر نشانی JSON) بگذارید.

## ۴. نسخهٔ ویندوز (فایل نصب)

**دریافت فایل نصب:** صفحهٔ **Releases** مخزن در GitHub ← آخرین «سیراف … نسخهٔ ویندوز» (برچسب `siraf-vX.Y.Z`؛ پیش‌نمایش شاخه‌های دیگر: `siraf-preview`) ← فایل `Siraf-Setup-x.y.z.exe`. این فایل را هر بار که در شاخهٔ `main` (یا شاخهٔ پیش‌نمایش) تغییری در پوشهٔ `siraf` push شود، GitHub Actions روی یک ویندوز واقعی می‌سازد، نصب و آزمایش می‌کند و منتشر می‌کند (workflow: `.github/workflows/siraf.yml`). همان فایل در بخش **Actions ← اجرای آخر ← Artifacts** هم هست.

**نصب:** فایل را روی فلش کپی کنید، روی هر رایانهٔ ویندوز ۱۰ یا ۱۱ (۶۴ بیتی) اجرا کنید ← «بعدی» ← «موافقم» ← محل نصب ← «نصب». همه‌چیز (برنامه، پایگاه دادهٔ PostgreSQL داخلی، فونت‌ها) در همین یک فایل است و به اینترنت یا نصب چیز دیگری نیاز ندارد. جزئیات: [`DESKTOP_FA.md`](DESKTOP_FA.md).

> **هشدار SmartScreen:** چون فایل نصب امضای دیجیتال تجاری ندارد، ویندوز ممکن است پیغام «Windows protected your PC» نشان دهد ← **More info** ← **Run anyway**. برای حذف این پیغام باید یک گواهی Code Signing بخرید و در workflow تنظیم کنید (`CSC_LINK` و `CSC_KEY_PASSWORD` در GitHub Secrets).

**وصل کردن به نسخهٔ وب:**
- اگر از قبل در وب کسب‌وکار دارید: در اولین اجرا گزینهٔ «اتصال به حساب ابری» ← نشانی سایت (مثلاً `https://app.example.ir`)، ایمیل و رمز ← انتخاب کسب‌وکار. همهٔ اطلاعات دریافت می‌شود و با همان ایمیل و رمز وارد می‌شوید.
- اگر روی ویندوز شروع کرده‌اید: «تنظیمات ← نسخهٔ ویندوز ← اتصال به حساب ابری» ← جهت «بارگذاری کسب‌وکار همین رایانه». کسب‌وکار در وب ساخته می‌شود و از آن به بعد هم‌گام می‌ماند.

## ۵. امنیت و نگهداری

- **پشتیبان‌گیری وب:** پلن رایگان Supabase پشتیبان قابل‌دانلود ندارد. هر چند وقت یک بار با `pg_dump` (رشتهٔ اتصال Session pooler، پورت 5432) پشتیبان بگیرید، یا روی یک رایانه نسخهٔ ویندوز را وصل نگه دارید: نسخهٔ ویندوز هر ۶ ساعت از کل داده‌ها پشتیبان می‌گیرد (۳۰ نسخهٔ آخر).
- رمزها با scrypt هش می‌شوند؛ نشست‌ها توکن تصادفی‌اند و فقط هش آن‌ها ذخیره می‌شود؛ «خروج از همهٔ دستگاه‌ها» در «حساب کاربری من».
- هر کسب‌وکار کاربران خودش را با نقش‌های مالک، مدیر، حسابدار، فروشنده، صندوقدار، انباردار و ناظر دارد و دسترسی هر بخش (مشاهده/ثبت/کامل) قابل تنظیم است. همهٔ تغییرات در «گزارش رویدادها» ثبت می‌شوند.

## ۶. توسعهٔ محلی

```bash
cd siraf
npm ci
npm run build:ui                      # رابط کاربری در public/
npm run start:local                   # نسخهٔ «ویندوزی» بدون Electron روی http://127.0.0.1:3939 (پایگاه داده در .local-data)
DATABASE_URL=postgres://… npm run dev # نسخهٔ وب (Next.js) — npm run dev:ui برای رابط کاربری با Vite
npm run typecheck && npm test && npm run build
npm run schema                        # پس از تغییر migrationها: supabase/schema.sql را به‌روز می‌کند
```

ساخت فایل نصب ویندوز روی رایانهٔ خودتان (روی ویندوز؛ روی لینوکس به Wine نیاز دارد):

```bash
cd siraf && npm ci && (cd desktop && npm ci)
node scripts/build-desktop.mjs
cd desktop && npx electron-builder --win nsis --x64
```
