# راه‌اندازی سایت سلین (GitHub + Supabase + Vercel)

سایت سلین یک پروژه‌ی **کاملاً مستقل** است: کد آن فقط در پوشه‌ی `celin-website` همین مخزن است و هیچ کد، پایگاه داده یا تنظیمی با Task Flow یا سایت پارس مشترک ندارد. فقط روش ساخت همان است: کد در GitHub، داده و تصاویر در یک پروژه‌ی Supabase مخصوص سلین، اجرا روی یک پروژه‌ی Vercel مخصوص سلین.

**بدون هیچ تنظیمی هم build می‌شود و بالا می‌آید** (با محصولات و تصاویر نمونه). هر قابلیت با تنظیم مربوط روشن می‌شود:

| قابلیت | نیازمند |
|---|---|
| همه‌ی صفحه‌های سایت، فارسی و انگلیسی، با محصولات نمونه | هیچ |
| محصولات واقعی، تصاویر سایت، حساب کاربری، اشتراک Pro، سفارش | Supabase (مرحله‌ی ۱) |
| پنل مدیریت (`/admin`) | Supabase و `ADMIN_PASSWORD` (بخش ۳) |
| پیامک کد Pro و وضعیت سفارش | پنل مدیریت ← تنظیمات ← پیامک (SMS.ir) |
| اعلان سفارش و درخواست تازه به مدیر | پنل مدیریت ← تنظیمات ← اعلان به مدیر (تلگرام یا بله) |
| ایمیل | `RESEND_API_KEY` و `MAIL_FROM` یا پنل مدیریت ← تنظیمات ← ایمیل (اختیاری) |

---

## ۱. پایگاه داده و فضای تصاویر (Supabase)

برای سلین یک پروژه‌ی **تازه و جدا** در Supabase بسازید (از پروژه‌ی دیگری مثل پارس استفاده نکنید).

1. در [supabase.com](https://supabase.com) وارد شوید ← **New project**. نام: `celin`، یک رمز قوی برای پایگاه داده (جایی نگهش دارید)، **Region: Central EU (Frankfurt)** (نزدیک‌ترین به ایران و به سرور Vercel در فرانکفورت).
2. پس از ساخته شدن پروژه: منوی **SQL Editor** ← **New query** ← محتوای **همه‌ی فایل‌های** پوشه‌ی `celin-website/supabase/migrations` را **به‌ترتیب نام**، هر کدام جدا، بچسبانید ← **Run**. اجرای دوباره بی‌خطر است (فایل‌ها idempotent هستند). پس از هر به‌روزرسانی کد که فایل تازه‌ای به این پوشه اضافه کند، فقط همان فایل تازه را اجرا کنید.
   **ساده‌ترین راه:** پس از انتشار سایت (مرحله‌ی ۲) وارد پنل مدیریت شوید ← **اتصالات**. اگر جدولی ساخته نشده باشد قرمز می‌شود و دکمه‌ی «کپی SQL» دقیقاً همان SQL لازم را کپی می‌کند؛ «باز کردن SQL Editor» مستقیم به Supabase می‌رود.
3. همین SQL فضای تصاویر را هم می‌سازد: در منوی **Storage** باید یک bucket به نام `celin-media` با برچسب **Public** ببینید. اگر Public نبود: روی آن ← **Edit bucket** ← Public را روشن کنید.
4. منوی **Project Settings ← API Keys** (یا **API**):
   - **Project URL** ← متغیر `SUPABASE_URL`
   - کلید **service_role** (یا کلید Secret جدید `sb_secret_…`) ← متغیر `SUPABASE_SERVICE_ROLE_KEY`

> کلید service_role فقط روی سرور استفاده می‌شود و هرگز به مرورگر نمی‌رسد. همه‌ی جدول‌ها RLS فعال و بدون Policy دارند؛ یعنی با کلید عمومی (anon) هیچ داده‌ای خوانده نمی‌شود. قیمت‌ها و موجودی فقط پس از بررسی نشست عضو Pro، از سرور خوانده می‌شوند و هیچ‌وقت در HTML صفحه‌ها نیستند.
>
> حساب‌های کاربری سایت در جدول `celin_users` همین پایگاه داده‌اند (ورود با موبایل و رمز، یا با کد Pro) و **به Supabase Auth کاری ندارند**.

## ۲. انتشار روی Vercel

1. کد این شاخه را در GitHub به `main` ادغام (Merge) کنید (پوشه‌ی `celin-website` باید در `main` باشد تا Vercel آن را ببیند).
2. [vercel.com/new](https://vercel.com/new) ← مخزن GitHub (`ai`) را **Import** کنید. این یک **پروژه‌ی تازه** در Vercel است (نام پیشنهادی: `celin`)؛ به پروژه‌های موجود دست نزنید.
3. **Root Directory** را روی `celin-website` بگذارید (مهم). Framework خودکار Next.js تشخیص داده می‌شود؛ بقیه‌ی تنظیمات ساخت را دست نزنید.
4. در **Environment Variables** این‌ها را اضافه کنید:

| نام | مقدار |
|---|---|
| `SUPABASE_URL` | **لازم.** از مرحله‌ی ۱. بدون آن ثبت‌نام و ورود اعضا خاموش است (بازدیدکننده فقط «ثبت‌نام به‌زودی فعال می‌شود» می‌بیند). |
| `SUPABASE_SERVICE_ROLE_KEY` | **لازم.** از مرحله‌ی ۱. |
| `ADMIN_PASSWORD` | **لازم برای پنل مدیریت.** یک رمز قوی («رمز مدیریت»). یک بار در `/admin` روی حساب خودتان وارد می‌کنید تا حساب مدیر شود (بخش ۳)؛ به‌تنهایی هم ورود اضطراری به پنل است. |
| `APP_SECRET` | پیشنهادی. یک رشته‌ی تصادفی ۳۲ نویسه‌ای یا بیشتر (مثلاً خروجی `openssl rand -hex 32`). نشست‌ها را امضا می‌کند، کدهای Pro را هش و کلیدهای ذخیره‌شده (پیامک، ربات، ایمیل) را رمزنگاری می‌کند؛ اگر نباشد از کلید service_role استفاده می‌شود. **پیش از صدور اولین کد Pro بگذارید و دیگر عوضش نکنید** (برای تعویض، بخش ۸). |
| `NEXT_PUBLIC_SITE_URL` | پیشنهادی. نشانی نهایی سایت، مثلاً `https://celin-xxx.vercel.app` (بعداً دامنه‌ی اصلی) |
| `ADMIN_PHONES` | اختیاری؛ فهرست مجاز. اگر بگذارید (مثلاً `09121234567`، چند شماره با ویرگول)، فقط حساب‌هایی با این شماره‌ها می‌توانند مدیر شوند، چه با رمز مدیریت و چه با «مدیر کردن» در پنل. شماره به‌تنهایی هیچ دسترسی‌ای نمی‌دهد. |
| `TRUSTED_IP_HEADER` و `TRUSTED_PROXY_SECRET` | فقط اگر CDN داخلی (مثل ابرآروان) جلوی سایت گذاشته‌اید یا سایت را روی سرور خودتان اجرا می‌کنید؛ بخش ۷. |
| `SUPABASE_BUCKET` | اختیاری؛ فقط اگر نام bucket چیزی جز `celin-media` است |
| `CRON_SECRET` | اختیاری؛ یک رشته‌ی تصادفی تا فقط خود Vercel نشانی بیدار ماندن Supabase را صدا بزند |
| `RESEND_API_KEY` و `MAIL_FROM` | اختیاری؛ ایمیل. ساده‌تر: از پنل مدیریت ← تنظیمات ← ایمیل |

5. **Deploy**. چند دقیقه بعد سایت روی زیردامنه‌ی Vercel آماده است.
6. **منطقه‌ی اجرا:** پروژه ← **Settings ← Functions ← Function Region** ← **Frankfurt, Germany (fra1)** را انتخاب و یک بار Redeploy کنید تا سرور کنار پایگاه داده باشد.

> **بیدار ماندن Supabase:** پروژه‌ی رایگان Supabase پس از یک هفته بی‌استفاده‌ماندن متوقف می‌شود. فایل `vercel.json` هر روز یک بار نشانی `/api/keepalive` را صدا می‌زند؛ کار دیگری لازم نیست.
>
> **چند پروژه‌ی Vercel روی یک مخزن:** هر پروژه‌ی Vercel که به این مخزن وصل است با هر push ساخته می‌شود، حتی اگر پوشه‌ی خودش تغییر نکرده باشد (برای همین زیر PR سلین نام پروژه‌های دیگر هم دیده می‌شود؛ این به معنی وابستگی کد نیست). برای این‌که هر پروژه فقط با تغییر پوشه‌ی خودش ساخته شود، در Vercel ← پروژه ← Settings ← Git ← **Ignored Build Step** ← Custom:
> - پروژه‌ی سلین (Root Directory = `celin-website`): `git diff HEAD^ HEAD --quiet -- .`
> - (اختیاری) پروژه‌ی دیگری که Root Directory آن پوشه‌ی خودش است، مثل `pars-website`: همان دستور `git diff HEAD^ HEAD --quiet -- .`
> - (اختیاری) پروژه‌ی Task Flow (ریشه‌ی مخزن): `git diff HEAD^ HEAD --quiet -- . ':(exclude)pars-website' ':(exclude)celin-website'`
>
> **پلن Vercel:** پلن رایگان Hobby طبق قوانین Vercel برای استفاده‌ی غیرتجاری است. برای فروشگاه در حال کار، پلن Pro (ماهانه حدود ۲۰ دلار) یا میزبانی داخلی (بخش ۷) را در نظر بگیرید.

## ۳. اولین ورود به پنل مدیریت

پنل با **حساب کاربری خودتان در سایت** باز می‌شود؛ رمز مدیریت فقط یک بار، برای فعال کردن آن روی حسابتان، لازم است:

1. در Vercel ← پروژه ← **Settings ← Environment Variables** این‌ها را بگذارید (جدول بخش ۲): `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY`، `ADMIN_PASSWORD` (یک رمز قوی)، `APP_SECRET` (پیشنهادی) و `NEXT_PUBLIC_SITE_URL`؛ و اگر بخواهید `ADMIN_PHONES` (شماره‌ی موبایل خودتان، تا فقط همین شماره بتواند مدیر شود).
2. **Redeploy** کنید (Deployments ← آخرین Deploy ← Redeploy). متغیرها فقط پس از Deploy تازه خوانده می‌شوند.
3. در سایت ← «ورود» ← «ساخت حساب» با شماره‌ی موبایل خودتان ثبت‌نام کنید (اگر از قبل حساب دارید، فقط وارد شوید).
4. به `https://<سایت>/admin` بروید. صفحه می‌گوید «این حساب هنوز مدیر نیست»؛ **رمز مدیریت** (`ADMIN_PASSWORD`) را یک بار وارد کنید و «فعال کردن پنل روی این حساب» را بزنید. حساب شما برای همیشه مدیر می‌شود (و از دستگاه‌های دیگر خارج می‌شود).
5. از این پس فقط در سایت وارد شوید: در بالای سایت (و در منوی حساب) پیوند **«پنل مدیریت»** را می‌بینید و پنل بدون ورود دوم باز است. در `/admin/login` هم می‌توانید با همان شماره و رمز وارد شوید.

> شماره‌ی موبایل به‌تنهایی هیچ دسترسی‌ای نمی‌دهد (شماره با پیامک تأیید نمی‌شود): مدیر شدن همیشه یک بار رمز مدیریت می‌خواهد، تلاش‌های اشتباه محدود و ثبت می‌شوند و اگر «اعلان به مدیر» را تنظیم کرده باشید، هر فعال‌سازی به شما خبر داده می‌شود. حسابی که فقط با کد Pro وارد شده باشد هرگز پنل را باز نمی‌کند. برای بازدیدکننده‌ها هیچ پیوندی به پنل نیست و موتورهای جستجو آن را ایندکس نمی‌کنند. در **اتصالات ← ورود مدیر** فهرست حساب‌های مدیر را ببینید.
>
> اگر هنوز چیزی تنظیم نشده باشد، صفحه‌ی `/admin/login` دقیقاً نام متغیرهای جاافتاده را نشان می‌دهد. `ADMIN_PASSWORD` به‌تنهایی (بدون حساب) هم پنل را در همان مرورگر باز می‌کند (ورود اضطراری) و هیچ حسابی را مدیر نمی‌کند.

پس از ورود:

1. **اتصالات**: همه‌ی ردیف‌ها باید سبز باشند (پایگاه داده، فضای تصاویر، ورود مدیر، نشانی سایت). ردیف‌های زرد (پیامک، اعلان، ایمیل) اختیاری‌اند. اگر ردیف پایگاه داده می‌گوید فایل تازه‌ی SQL اجرا نشده، «کپی SQL» را بزنید و در SQL Editor اجرا کنید.
2. **محصولات، دسته‌ها و مجموعه‌ها**: با اولین ورود به پنل، همان محصولات، دسته‌ها و مجموعه‌هایی که سایت نشان می‌دهد خودکار به پایگاه داده آورده می‌شوند (یک بار)؛ از این پس در پنل ویرایش، حذف یا با محصولات واقعی جایگزین می‌شوند. (اگر پیش‌تر خودتان محصولی ساخته باشید، این کار انجام نمی‌شود و دکمه‌ی «ورود محصولات نمونه برای ویرایش» در صفحه‌ی محصولات همان کار را می‌کند.)
3. **تصاویر سایت**: هر تصویر طراحی سایت (سرآغاز صفحه‌ی اصلی، طاق‌ها، بخش‌های داستان، هنر ساخت، Pro و …) یک «جایگاه» است با شکل مشخص و متن‌های همراهش. روی هر جایگاه بزنید ← عکس را بارگذاری کنید یا از کتابخانه انتخاب کنید ← نقطه‌ی کانونی (جایی که جواهر هست) را بزنید ← متن‌ها را ویرایش ← ذخیره. «بازگشت به پیش‌فرض» تصویر و متن اصلی را برمی‌گرداند. چهار جایگاه ویدئو هم می‌پذیرند (سرآغاز صفحه‌ی اصلی، پنجره‌ی طاق، سرآغاز «درباره‌ی سلین» و سرآغاز «هنر ساخت»): در بخش «ویدئو (اختیاری)» یک فایل MP4 (کدک H.264) یا WebM تا ۲۵ مگابایت بارگذاری کنید و ذخیره بزنید. ویدئو بی‌صدا و حلقه‌ای پخش می‌شود و عکس همان جایگاه تصویر پیش‌نمایش و جایگزین آن می‌ماند (برای کسی که «کاهش حرکت» یا صرفه‌جویی داده را روشن کرده، یا مرورگرش آن نوع ویدئو را پخش نمی‌کند). برای اینترنت ایران ویدئوی ۶ تا ۱۲ ثانیه‌ای، حداکثر ۱۰۸۰p و ۴ تا ۸ مگابایت پیشنهاد می‌شود. فایل از مرورگر مدیر مستقیم به Supabase فرستاده می‌شود، پس هنگام بارگذاری ویدئو مرورگر مدیر باید به `*.supabase.co` دسترسی داشته باشد (برای عکس‌ها لازم نیست). این امکان به فایل مهاجرت `20261023180000_celin_slot_video.sql` نیاز دارد.
4. **دسته‌ها و مجموعه‌ها**: نام، تصویر، ترتیب و نمایش هر دسته و مجموعه.
5. **تنظیمات**: اطلاعات تماس (تلفن، واتس‌اپ، اینستاگرام، تلگرام، نشانی، ساعات)، نوار اطلاعیه‌ی بالای سایت، تنظیمات سفارش (حداقل مبلغ، نمایش موجودی)، اعتبار پیش‌فرض کد Pro، پیامک، اعلان به مدیر، ایمیل و توضیح سئو.

**مدیران دیگر:** پس از ثبت‌نام‌شان در پنل ← **کاربران** ← حساب ← «مدیر کردن این حساب» ← در پنجره‌ی تأیید «بله، مدیر شود» (یا رمز مدیریت را به آن‌ها بدهید تا خودشان در `/admin` فعال کنند). همان قواعد فعال‌سازی برقرار است: اگر `ADMIN_PHONES` گذاشته‌اید، شماره‌شان باید در آن باشد؛ و حساب باید رمز عبور خودش را داشته باشد (حساب مدیر هرگز با کد Pro وارد نمی‌شود، پس حسابی که فقط با کد وارد می‌شود یا رمزش را در نشستِ کد ساخته، اول از همان صفحه رمز تازه می‌گیرد). هر «مدیر کردن» و «برداشتن دسترسی» با نام انجام‌دهنده در لاگ سرور ثبت می‌شود و اگر «اعلان به مدیر» تنظیم باشد خبرش می‌رسد. تا وقتی `ADMIN_PASSWORD` تنظیم نشده، دسترسی آخرین حساب مدیر برداشته نمی‌شود. «خروج» در پنل از حساب هم خارج می‌کند (در همه‌ی دستگاه‌ها). پس از فعال شدن حساب‌ها می‌توانید `ADMIN_PASSWORD` را عوض کنید.

تصاویر هنگام بارگذاری در خود مرورگر به اندازه‌های مختلف (تا ۲۰۴۸ پیکسل) و WebP تبدیل می‌شوند؛ عکس‌ها را با بیشترین کیفیت موجود بارگذاری کنید (ترجیحاً عمودی ۳:۴، دست‌کم ۱۶۰۰ پیکسل عرض).

## ۴. اشتراک Pro و کدها

- همه همه‌چیز را می‌بینند، جز **قیمت و موجودی**. بازدیدکننده با دکمه‌ی **Pro** (بالای سایت و بالای هر فهرست محصول) کد Pro را وارد می‌کند یا درخواست اشتراک می‌دهد (پس از ثبت‌نام).
- درخواست در پنل ← **اشتراک Pro** دیده می‌شود ← «تأیید» ← مدت اعتبار ← کد ۱۲ رقمی صادر می‌شود. کد در پیام‌های حساب کاربر قرار می‌گیرد (قابل خاموش کردن در تنظیمات)، اگر پیامک تنظیم باشد پیامک می‌شود، و در همان پنجره دکمه‌های کپی و ارسال با واتس‌اپ، پیامک و تلگرام هست.
- کاربر کد را در صفحه‌ی ورود، در پنجره‌ی Pro یا در حساب خود وارد می‌کند و بی‌درنگ قیمت‌ها و موجودی را می‌بیند. **خود کد هم برای ورود کافی است** (برای اعضایی که رمز ندارند یا رمز را فراموش کرده‌اند)؛ فقط حساب مدیر هرگز با کد وارد نمی‌شود و همیشه شماره و رمز می‌خواهد.
- کد در پیام‌های حساب ذخیره نمی‌شود: هر پیام فقط نشانی همان کدی را دارد که برایش نوشته شده و هنگام خواندن، همان کد را نشان می‌دهد (پیام قدیمی هرگز کد تازه‌تر را نشان نمی‌دهد)؛ پس از باطل یا تمام شدن آن کد، «این کد دیگر فعال نیست» نوشته می‌شود. اگر «نمایش کد در پیام‌های حساب عضو» را خاموش کنید، هیچ پیامی (قدیمی یا تازه) کد را نشان نمی‌دهد.
- با **باطل کردن** کدی که استفاده شده (یا صدور کد تازه به جای آن، حتی اگر کد قبلی تمام شده باشد — یعنی تمدید با کد تازه)، عضو از همه‌ی دستگاه‌ها خارج می‌شود و اگر با همان کد برای حساب رمز گذاشته بود، آن رمز هم پاک می‌شود؛ این‌طور کدی که به دست دیگری افتاده، با باطل شدن کاملاً بی‌اثر می‌شود. عضوی که اشتراکش تمام یا باطل شده، در حسابش تاریخ و علت پایان را می‌بیند و می‌تواند درخواست تازه بدهد.
- **ساخت دستی عضو:** پنل ← **کاربران** ← «کاربر جدید» ← نام و موبایل (رمز اختیاری) ← «صدور کد Pro».
- مدیر هر زمان می‌تواند کد را ببیند، تمدید یا باطل کند، یا کد تازه بدهد (کد قبلی خودکار باطل می‌شود).

**پیامک (اختیاری):**
- **SMS.ir** پیشنهاد می‌شود، چون از سرورهای Vercel (خارج از ایران) در دسترس است؛ کاوه‌نگار معمولاً اتصال از خارج را نمی‌پذیرد.
- در پنل SMS.ir:
  1. یک کلید API بسازید.
  2. دو قالب «ارسال سریع» (verify) ثبت کنید و منتظر تأیید بمانید:
     - **قالب کد:** باید پارامتر `#CODE#` داشته باشد، مثلاً «کد Pro سلین شما: #CODE#».
     - **قالب وضعیت سفارش:** باید پارامترهای `#ORDER#` و `#STATUS#` داشته باشد.
- در پنل سایت ← **تنظیمات ← پیامک**:
  1. سرویس، کلید API و شناسه‌ی هر دو قالب را وارد کنید.
  2. ذخیره را بزنید.
  3. «پیامک آزمایشی» را بزنید.

**اعلان به مدیر (اختیاری):**
1. ربات بسازید:
   - **تلگرام:** با @BotFather.
   - **بله:** از «بازو»ی بله (همان API تلگرام).
2. ربات را به گروه یا کانال خود اضافه کنید و `chat_id` را بردارید.
3. در پنل ← **تنظیمات ← اعلان به مدیر** وارد کنید، ذخیره را بزنید و «پیام آزمایشی» را امتحان کنید.

**ایمیل (اختیاری):**
1. در [resend.com](https://resend.com) دامنه را تأیید کنید.
2. کلید و فرستنده را (مثلاً `سلین <hello@your-domain.ir>`) در پنل ← **تنظیمات ← ایمیل** یا در متغیرهای Vercel وارد کنید.

## ۵. سفارش‌ها

- عضو Pro سبد سفارش را از صفحه‌ی محصول پر می‌کند ← «ثبت سفارش» (بدون پرداخت آنلاین). موجودی در همان لحظه کم می‌شود؛ اگر کالایی تمام شده باشد، سفارش ثبت نمی‌شود و به کاربر نشان داده می‌شود کدام قلم مشکل دارد.
- در پنل ← **سفارش‌ها**، وضعیت را دستی جلو ببرید: «در انتظار تأیید فروشگاه» ← «در حال جمع‌آوری و بسته‌بندی» ← «آماده‌ی ارسال» ← «ارسال شد» (با روش ارسال و کد رهگیری). لغو سفارش پیش از ارسال، موجودی را برمی‌گرداند. سفارش «ارسال شد» دیگر به عقب برنمی‌گردد و فقط قابل لغو است، آن هم **بدون** برگشت موجودی (اگر بسته به فروشگاه برگشت، موجودی را در صفحه‌ی محصول اصلاح کنید).
- اگر هنگام ویرایش یک محصول سفارشی برای آن ثبت شود، ذخیره‌ی شما آن را خنثی نمی‌کند: تغییری که در عدد موجودی می‌دهید به‌صورت «افزایش/کاهش» روی موجودی واقعی اعمال می‌شود.
- اگر قیمت کالایی میان دیدن سبد و ثبت سفارش تغییر کند، سفارش ثبت نمی‌شود و به عضو گفته می‌شود مبلغ تازه را ببیند و دوباره تأیید کند.
- کاربر وضعیت لحظه‌ای، سفارش‌های قبلی و جمع مبلغ آن‌ها را در حساب خود می‌بیند؛ با هر تغییر وضعیت پیام (و اگر تنظیم باشد پیامک) می‌گیرد. هزینه‌ی ارسال و تخفیف در صفحه‌ی سفارش در پنل قابل ثبت است (عضو مبلغ نهایی تازه را در پیام‌هایش می‌گیرد؛ مبلغ سفارش لغوشده تغییر نمی‌کند) و پیش‌فاکتور چاپی دارد.

## ۶. دامنه‌ی اختصاصی

1. پروژه در Vercel ← **Settings ← Domains** ← **Add** ← دامنه را وارد کنید (مثلاً `celin.ir` و `www.celin.ir`).
2. رکوردهایی را که Vercel نشان می‌دهد در پنل DNS ثبت‌کننده‌ی دامنه وارد کنید (معمولاً `A` برای دامنه‌ی اصلی و `CNAME` برای `www`). گواهی SSL خودکار صادر می‌شود.
3. `NEXT_PUBLIC_SITE_URL` را به دامنه‌ی جدید تغییر دهید ← **Redeploy**.

## ۷. دسترسی از داخل ایران

- دامنه‌های `vercel.app` گاهی در ایران محدود می‌شوند؛ با دامنه‌ی اختصاصی وضعیت بهتر است، اما تضمینی نیست. برای دسترسی پایدار داخلی، یک CDN داخلی (مثل ابرآروان) جلوی دامنه بگذارید یا سایت را روی سرور داخلی اجرا کنید؛ سایت به‌صورت `standalone` هم ساخته می‌شود:
  ```bash
  cd celin-website && npm ci && npm run build
  node .next/standalone/server.js   # پورت 3000؛ پوشه‌های public و .next/static را کنار آن کپی کنید
  ```
  (روی لیارا یا هر سرور Node.js، همین متغیرهای محیطی را تنظیم کنید.)
- **IP بازدیدکننده (برای محدودیت تلاش‌های ورود، ثبت‌نام و کد Pro):** سایت فقط به سرآیندی اعتماد می‌کند که پراکسیِ مطمئن نوشته باشد؛ بازدیدکننده می‌تواند `X-Forwarded-For` را خودش بفرستد و Next.js آن را همان‌طور نگه می‌دارد. وضعیت در پنل ← **اتصالات ← IP بازدیدکننده** دیده می‌شود.
  - **فقط Vercel:** کاری لازم نیست (سرآیند خود Vercel خوانده می‌شود).
  - **سرور خودتان پشت nginx/Caddy:** در nginx `proxy_set_header X-Real-IP $remote_addr;` بگذارید و `TRUSTED_IP_HEADER=x-real-ip`؛ یا `proxy_set_header X-Forwarded-For $remote_addr;` (جایگزین کردن، نه افزودن با `$proxy_add_x_forwarded_for`) و `TRUSTED_IP_HEADER=x-forwarded-for` (سایت آخرین مقدار آن را می‌خواند). برنامه را فقط روی `127.0.0.1` یا پشت دیوار آتش اجرا کنید تا کسی مستقیم به آن نرسد، یا `TRUSTED_PROXY_SECRET` را هم بگذارید (پایین).
  - **سرور خودتان پشت ابرآروان (یا CDN جلوی Vercel):** `TRUSTED_IP_HEADER=ar-real-ip` و یک رشته‌ی تصادفی در `TRUSTED_PROXY_SECRET` (مثلاً خروجی `openssl rand -hex 24`). در پنل CDN یک سرآیند درخواست به مبدأ (origin) به نام `x-celin-proxy` با همان مقدار اضافه کنید (در nginx: `proxy_set_header X-Celin-Proxy "<همان مقدار>";`). سرآیند IP فقط در درخواستی پذیرفته می‌شود که این رمز را داشته باشد؛ **روی Vercel این رمز اجباری است**، چون هر کسی می‌تواند مستقیم به نشانی `*.vercel.app` درخواست با `ar-real-ip` دلخواه بفرستد (بدون رمز، Vercel همان سرآیند خودش را می‌خواند و همه‌ی بازدیدکننده‌هایی که از یک گره‌ی CDN می‌آیند یک IP حساب می‌شوند).
  - **سرور خودتان بدون `TRUSTED_IP_HEADER`:** برای امنیت، IP هیچ درخواستی پذیرفته نمی‌شود و محدودیت‌ها میان همه‌ی بازدیدکننده‌ها مشترک است (سخت‌گیرانه؛ لاگ سرور و «اتصالات» هشدار می‌دهند)؛ پس یکی از روش‌های بالا را تنظیم کنید.
- بازدیدکننده فقط به خود سایت درخواست می‌فرستد: فونت‌ها، تصاویر و ویدئوها از نشانی خود سایت سرو می‌شوند و Supabase فقط از سمت سرور صدا زده می‌شود (تنها استثنا بارگذاری ویدئو در پنل مدیریت است که از مرورگر مدیر مستقیم به Supabase می‌رود).

## ۸. امنیت و نگهداری

- **تعویض `APP_SECRET`:**
  1. مقدار فعلی را در `APP_SECRET_PREVIOUS` بگذارید.
  2. مقدار تازه را در `APP_SECRET` بگذارید.
  3. Redeploy کنید.

  کدهای Pro و کلیدهای ذخیره‌شده‌ی قبلی خوانا می‌مانند. همه‌ی کاربران و مدیر باید دوباره وارد شوند.
- **پشتیبان‌گیری:** پلن رایگان Supabase پشتیبان قابل‌دانلود ندارد. هر چند وقت یک بار از **Database ← Backups** (پلن‌های پولی) یا با `pg_dump` یک نسخه بگیرید. عکس‌ها در Storage ← `celin-media` هستند.
- `ADMIN_PASSWORD` را قوی نگه دارید و به کسی ندهید؛ هر کس آن را بداند می‌تواند پنل را روی حساب خودش فعال کند (اگر `ADMIN_PHONES` گذاشته باشید، فقط روی همان شماره‌ها). تلاش‌های ناموفق محدود می‌شوند (به ازای هر IP، هر حساب، و یک سقف مشترک برای تلاش‌های اشتباه از همه‌جا؛ مرورگری که پیش‌تر رمز مدیریت را درست وارد کرده از سقف مشترک رد می‌شود). اگر لو رفت، عوضش کنید و در «کاربران» حساب‌های مدیر را بررسی کنید.
- **خروج از پنل** حساب مدیر را در همه‌ی دستگاه‌ها خارج می‌کند؛ کوکی کپی‌شده از یک دستگاه مشترک دیگر پنل را باز نمی‌کند.
- **به‌روزرسانی اکتبر ۲۰۲۶:** پنل ← **اتصالات** فایل‌های SQL اجرانشده را از اثرشان تشخیص می‌دهد (مثلاً اگر مشخصات محصولات هنوز نام جنس نگین را دارند) و ردیف پایگاه داده را قرمز می‌کند: «کپی SQL» دقیقاً همان فایل‌ها را کپی می‌کند؛ در SQL Editor اجرا کنید. فایل‌های این به‌روزرسانی، به‌ترتیب: `20261024090000_celin_hardening.sql` (قواعد وضعیت سفارش و پاک شدن رمزهای ساخته‌شده با کد باطل‌شده)، `20261024100000_celin_no_stone_material.sql` (حذف نام جنس نگین از مشخصات محصولات)، فایل پاک‌سازی متن‌ها با پیشوند `20261024110000` (اگر در پوشه هست) و `20261024120000_celin_admin_fixes.sql` (پیام‌های کد Pro، تصاویر سفارش‌ها و ثبت نام فایل‌های اجراشده). همه idempotent هستند و سایت پیش از اجرای آن‌ها هم کار می‌کند. از این پس هر فایل تازه نام خودش را در جدول `celin_migrations` ثبت می‌کند.

## ۹. توسعه‌ی محلی

```bash
cd celin-website
npm install
cp .env.example .env.local   # مقادیر را پر کنید (اختیاری)
npm run dev                   # http://localhost:3000  (انگلیسی: /en)
npm run typecheck && npm test && npm run build
```

با هر Pull Request که پوشه‌ی `celin-website` را تغییر دهد، GitHub Actions (`.github/workflows/celin-website.yml`) typecheck، تست‌ها و build بدون متغیر محیطی را اجرا می‌کند.
