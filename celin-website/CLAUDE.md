# CELIN website — notes for Claude

Fully independent Next.js 16 app (no code, data or settings shared with Task Flow or the Pars site) in a sub-folder of this repository (deployed as its own Vercel project with Root Directory `celin-website`). Luxury bilingual site of the jewellery brand **CELIN / سلین** (Etemad Gallery): Persian (RTL) at `/`, English at `/en`. Read `README.md`, `docs/SETUP_FA.md`, `docs/BRAND_BOOK_FA.md` and `docs/DESIGN_SYSTEM.md` before larger changes.

- **Languages:** two root layouts in route groups `(fa)` and `(en)`. Page bodies are shared components in `src/components/pages/*` that take `lang`; route files are thin wrappers. UI copy lives in `src/content/copy/*.ts` (`fa` / `en`, same shape); the brand's own story and lines are in `src/content/copy/story.ts` (use them, never invent claims). Persian digits via `num()` / `formatPrice()` (`src/lib/format.ts`); logical Tailwind utilities (`ms-`, `pe-`, `start-`, `end-`). No `letter-spacing` on Persian text; tracking only on Latin labels.
- **Brand:** tokens in `src/app/globals.css` (`@theme`: layered mesh grounds, `--metal-*` gradients), never raw hex in components. Persian type is **Nazli** (Sharif FarsiWeb, GPL-2+; our web cut in `src/fonts/`, loaded by `next/font/local` in `src/lib/fonts.ts`) — the free twin of Nazanin, the face of «گالری اعتماد» in the logo, chosen by the owner: headings 700, text and UI 400; Vazirmatn only for dense numeric tables (`font-dense`). Inner pages use the quiet scale (`title-page`, `title-section`, `title-card`, `title-quote`, `lede`, `numeral`, `title-mark`; no ad-hoc `text-4xl…8xl`); only the home page keeps large display sizes. Never name the stone material (no «کیوبیک زیرکونیا» / zirconia) except in the owner's own craft chapter (story.ts), never use «رواق», and never state a warranty («ضمانت») anywhere. The round **arch** is the signature frame (`<Arch>`, `ArchLines`). The logo files in `public/brand/` are vectorised 1:1 from the official logo — never redraw, recolour outside the documented variants, or distort them.
- **Effects:** `src/components/fx/*` (Lenis + GSAP smooth scroll, `useGsap`, `SplitWords` — words, never letters — `Sparkles`, `Aura` WebGL, `Reel`, `Magnetic`, `Cursor`, `Intro`; bands meet on clean straight edges — only the home hero melts into the statement (`bg-dawn`); no gradient strips between bands, no marquee ribbons; a rounded frame with a moving picture gets `arch-clip` for Safari; the home opening's arches turn (`HeroArcade`, poses in `home/hero-pose.ts`) and must keep the fixed arcade's exact rest geometry; a new page always opens at its top — `SmoothScroll` does it, since Next alone leaves a short page at its foot). Everything must stay readable without JS and honour reduced motion (OS setting and the footer toggle). Custom CSS classes live in `@layer components` so utilities win (unlayered CSS beats Tailwind utilities); an IntersectionObserver ignores a target hidden by its own clip-path, so reveal triggers sit on an unclipped wrapper.
- **Data:** server-only service-role client `db()` (`src/lib/db.ts`); tables `celin_*` with RLS on and no policies; one idempotent SQL file per change in `supabase/migrations/` (never edit a shipped one). Stock and prices change only through `celin_place_order` / `celin_set_order_status` or the admin.
- **Prices are private:** public pages are static and identical for everyone, so public catalogue objects (`src/lib/catalog-types.ts`) never carry price or stock. Members get them from `/api/pro/prices` (session checked on every call) through `usePriceBook()`; never put a price into HTML, RSC payloads, JSON-LD, metadata or alt text.
- **Membership and Pro (`src/lib/pricing.ts`):** visitors see no prices or stock; an approved member (membership code) sees no stock (`/api/pro/prices` sends members only orderable-or-not, never counts) and every price at `settings.pro.memberPct` (200%) of the admin's price, and the invoice steps down by pieces in one order (`steps`, shown as «تخفیف تعداد»); while choosing and in the basket a member sees the original price struck through with the price at the order's step under it (`PriceSlot` counts the basket's pieces plus the quantity being chosen), Pro accounts see one price only; an account whose accepted orders reach `proThreshold` within `proDays` becomes Pro (`celin_users.pro_at`, `members.ts checkPro`, run when the admin accepts or re-prices an order), gets a separate Pro code, sees stock and pays the admin's price. Every piece of the order counts towards the step, whichever design: `src/lib/basket.ts` is the one place that turns basket lines into the invoice's pieces and per-piece prices (`linePieces`, `invoiceLines`; PriceSlot, the basket and the order action all use it), and the step is always shown with its percentage off the list price (`offPct`, floored) and «روی کل سفارش» (`pro/step-note.tsx` while buying, `account/discount-ladder.tsx` on /pro and /account/pro from the settings). The special-day discount (Settings → «نوار تخفیف روزهای خاص», `src/lib/sale.ts`) takes `sale.pct` off every piece after the step, for members and — unless the admin excludes them — Pro accounts: the server's clock decides the price (`liveSale` in `/api/pro/prices` and the order action), the browser's clock only whether the static bar shows (`html[data-sale]`); never write «تخفیف ویژه» / «حراج» ourselves. The browser, `actions/orders.ts` and `celin_place_order(…, p_pricing, p_expect)` compute the same invoice — list → step → sale, rounded once per piece (`unitAt`, BigInt) — and the database refuses an order whose total differs from the one the action computed (`price_changed`); orders keep `list_price` / `list_subtotal` (what the member saw) beside `unit_price` / `subtotal` (charged), and `pricing` keeps `{level, list, pct, pieces}` plus `{sale, stepped}` when a sale applied (`orderDiscounts` in `order-meta.ts` reads them for every invoice). Wording: «عضویت» / «کد عضویت» for the approval-based level, «Pro» / «کد Pro» only for the automatic one.
- **Packs (round six, `src/lib/packs.ts`):** per product the admin sells any non-empty set of single («تک», 1) and packs of 2–5 sizes (`celin_products.packs`; a pack of N = N pieces of the model and option in N sizes at N × the piece price). Packs are public terms (catalogue, cards, product page); a pack's price is worked out in the browser from the price book. A basket line is product + option + pack with `qty` = packs (`CartLine.pack`, old baskets read as 1); everything that counts — steps, stock, invoice, `p_items` (qty = pieces, plus `pack`) — counts pieces through `linePieces`. Order lines keep pieces in `qty` and the pack in `celin_order_items.pack`; every order view and the team's message write «۳ بسته‌ی ۴ سایزی · ۱۲ عدد» (`common.pack.line`). Reads of `packs` / `pack` fall back while round six's SQL has not run (single).
- **Colour options (round six, `src/lib/options.ts`):** plating, stone and leather colours come from lists the admin keeps in Settings → «رنگ‌های گزینه‌ها» (`celin_settings` key `options`: name fa/en, swatch, SKU code, shop-filter facet; keys never change; only the stone's material is refused in a name). A product uses up to three axes, always plating → stone → leather; each `celin_variants` row is one combination (`options` jsonb by key, `{}` = the older plain list, which keeps working and converts per product with «تبدیل به رنگ‌ها») with its own price override, stock, SKU and picture, at most 100. The server composes a combination's `name_fa/en` and swatch from the lists («طلایی · نگین سفید · چرم مشکی»), so orders, the basket and notifications read variant names as before; saving the lists writes a rename into every stored combination and refuses to delete a colour in use. The public catalogue carries `Product.axes` (words, dots, facets — never price or stock); the product page picks one colour per axis (`findVariant`, `valueState`, `pickValue`), dimming what is not made and, for members/Pro, what cannot be ordered; the shop filters read the axes' facets (plating, stone and a «رنگ چرم» group). Reads of `options` fall back while round six's SQL has not run (plain lists); colours ask for the file before anything is written.
- **Pictures:** every design picture is a slot (`src/content/slots.ts`; a `gallery` slot — the home opening `home.hero.a` — holds an ordered list in `celin_slots.gallery`, its former `home.hero.b`/`c` are `legacy` fallbacks never listed in the admin), every product/category picture a `celin_media` row; render them with `<Picture>` (`src/components/ui/picture.tsx`, plain `<img srcset>`, blur placeholder, focal point). Uploads are resized in the browser (`src/components/admin/resize.ts`) and stored via `/api/admin/upload`.
- **Auth:** accounts in `celin_users` (phone + password, or the membership/Pro code as sign-in — never for admin accounts), signed cookie recording how it was opened (`src/lib/auth.ts`); admin = account with role admin signed in with its password, or the `ADMIN_PASSWORD`-only session (`src/lib/admin-auth.ts`). An account becomes admin only by entering `ADMIN_PASSWORD` once at `/admin/login`, or by another admin in Users → «مدیر کردن» — both under the same rules (`promotionBlock()`: optional allow-list `ADMIN_PHONES`, the account must have its own password, not disabled); a phone number alone never grants anything. Each new SQL file records itself in `celin_migrations`; «اتصالات» lists what is missing (`pendingMigrations()`). Every admin Server Action goes through `guard()`; every admin page calls `requireAdminPage()`; every `src/lib/admin-*.ts` / `members.ts` function calls `assertAdmin()` itself.
- **Collections:** a public collection's `media` is its own picture, else its first published piece's (`withCovers`, `src/lib/catalog-types.ts`). Every public list of collections — home arcade, /collections, the other collections under a collection, header menu and phone drawer, search chips and index, sitemap, 404, /craft — filters with `listed()` (shown and with a picture), so a collection with no picture of its own and no pictured published piece is listed nowhere and no arch stands empty; the catalogue still carries it, so its page and its pieces' collection name resolve. `soon` (no published pieces) only adds «به‌زودی» under its name when it has no tagline.
- **Admin lists:** a switch or button on a list row (a category/collection's «نمایش», a product's «انتشار») shows its new state at once and goes back if the action fails (`usePending`, `src/components/admin/pending.ts`): a Server Action's toast arrives before its refreshed page. A row control writes only its own field (`setTaxonVisible`), never the whole row from a copy that may be older. Admin actions refresh the panel page with `refresh()` from `next/cache`; the public pages follow through the lib's `revalidateTag` / `revalidatePath`.
- **Performance:** member pages have a `loading.tsx` frame (a tap answers at once; Next prefetches the frame); keep public pages static (catalogue and slots are cached with tags `catalog` / `slots`, invalidated by admin changes); no third-party requests at runtime (Iran); fonts are self-hosted by `next/font`.
- **Vercel:** `vercel.json` holds the Ignored Build Step (it overrides the dashboard). Keep its `git cat-file -e` guard: Vercel's clone is shallow, and when the last deployed commit is missing `git diff` exits 128, which Vercel counts as a failed deployment, not a build.
- Commands: `npm run typecheck` · `npm test` · `npm run build` (must pass with no env vars).
