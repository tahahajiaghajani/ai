# راه‌اندازی «تراز» (GitHub + Supabase + Vercel + نسخه‌ی ویندوز)

«تراز» یک پروژه‌ی **کاملاً مستقل** در پوشه‌ی `taraz` همین مخزن است (کد، پایگاه داده و تنظیماتش با پروژه‌های دیگر مخزن مشترک نیست). دو شکل دارد که با هم **هم‌گام** می‌مانند:

| نسخه | کجا اجرا می‌شود | داده کجاست |
|---|---|---|
| **وب** | Vercel (همان روش همیشگی) | Supabase |
| **ویندوز** | روی رایانه‌ی کاربر، با یک فایل نصب | PostgreSQL داخلی خود برنامه (بدون نصب جداگانه) |

هر کاربر (کسب‌وکار) در نسخه‌ی وب حساب می‌سازد؛ نسخه‌ی ویندوز را با همان ایمیل و رمز به حسابش وصل می‌کند و از آن به بعد هر تغییر در هر طرف، ظرف چند ثانیه به طرف دیگر می‌رسد. بدون اینترنت هم نسخه‌ی ویندوز کامل کار می‌کند و تغییرات در صف می‌مانند تا اینترنت وصل شود.

**بدون هیچ متغیر محیطی هم build می‌شود.** فقط برای اجرا به `DATABASE_URL` نیاز دارد.

---

## ۱. پایگاه داده (Supabase)

1. در [supabase.com](https://supabase.com) ← **New project**. نام: `taraz`، یک رمز قوی برای پایگاه داده (یادداشت کنید)، **Region: Central EU (Frankfurt)** — نزدیک‌ترین به ایران و به سرور Vercel در فرانکفورت.
2. منوی **SQL Editor** ← **New query** ← کل محتوای فایل [`taraz/supabase/schema.sql`](../supabase/schema.sql) را بچسبانید ← **Run**.
   - اجرای دوباره بی‌خطر است (همه‌ی دستورها idempotent هستند).
   - اگر این کار را فراموش کنید هم مشکلی نیست: برنامه هنگام اولین اجرا خودش جدول‌ها را می‌سازد (`AUTO_MIGRATE`). فایل `schema.sql` برای کسی است که می‌خواهد کنترل کامل داشته باشد.
   - همه‌ی جدول‌ها با پیشوند `tz_` ساخته می‌شوند، RLS روشن است و هیچ دسترسی‌ای از کلیدهای عمومی Supabase (anon/authenticated) ندارند؛ فقط سرور خود برنامه به پایگاه داده وصل می‌شود.
3. **رشته‌ی اتصال** را بردارید: بالای داشبورد دکمه‌ی **Connect** ← بخش **Transaction pooler** (پورت `6543`) ← نشانی را کپی کنید و به‌جای `[YOUR-PASSWORD]` رمز مرحله‌ی ۱ را بگذارید. چیزی شبیه این:
   ```
   postgresql://postgres.abcdefghijklmnop:رمز@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
   ```
   > اگر رمز نویسه‌های خاص مثل `@`، `#` یا `/` دارد، آن را URL-encode کنید (مثلاً `@` ← `%40`) یا رمز ساده‌تری بگذارید.

> **به‌روزرسانی‌های بعدی:** وقتی نسخه‌ی تازه‌ای از کد منتشر شود که جدول تازه‌ای بخواهد، برنامه خودش migrationهای جاافتاده را اعمال می‌کند. اگر `AUTO_MIGRATE=false` گذاشته‌اید، فقط فایل‌های تازه‌ی پوشه‌ی [`taraz/supabase/migrations`](../supabase/migrations) را به‌ترتیب در SQL Editor اجرا کنید.

## ۲. انتشار روی Vercel

1. کد این شاخه را در GitHub به `main` ادغام کنید (پوشه‌ی `taraz` باید در `main` باشد).
2. [vercel.com/new](https://vercel.com/new) ← مخزن GitHub (`ai`) را **Import** کنید. این یک **پروژه‌ی تازه** در Vercel است (نام پیشنهادی: `taraz`)؛ به پروژه‌های موجود دست نزنید.
3. **Root Directory** را روی `taraz` بگذارید (مهم). Framework خودکار **Next.js** تشخیص داده می‌شود؛ Build Command از `vercel.json` خوانده می‌شود (`npm run build` = ساخت رابط کاربری با Vite + Next.js برای API). بقیه را دست نزنید.
4. **Environment Variables**:

| نام | مقدار |
|---|---|
| `DATABASE_URL` | **لازم.** رشته‌ی اتصال Transaction pooler از مرحله‌ی ۱ (پورت 6543). |
| `APP_SECRET` | پیشنهادی. یک رشته‌ی تصادفی ۳۲ نویسه‌ای یا بیشتر (مثلاً خروجی `openssl rand -hex 32`). برای رمزنگاری کلیدهای ذخیره‌شده‌ی اتصال‌ها (فروشگاه اینترنتی و …). |
| `PLATFORM_ADMIN_EMAILS` | پیشنهادی. ایمیل خودتان (مالک سامانه)؛ چند ایمیل را با ویرگول جدا کنید. این حساب‌ها همه‌ی کسب‌وکارها را می‌بینند. |
| `ALLOW_SIGNUP` | اختیاری. پیش‌فرض باز است؛ با `false` ثبت‌نام عمومی بسته می‌شود و فقط شما (یا مدیران کسب‌وکارها از «تنظیمات ← کاربران») حساب می‌سازید. |
| `CRON_SECRET` | اختیاری. یک رشته‌ی تصادفی تا فقط خود Vercel نشانی بیدار نگه داشتن Supabase را صدا بزند. |
| `AUTO_MIGRATE` | اختیاری. پیش‌فرض `true`. با `false` برنامه خودش جدول نمی‌سازد. |
| `DATABASE_POOL_MAX` | اختیاری. حداکثر اتصال هم‌زمان هر نمونه‌ی سرور (پیش‌فرض ۳). |

5. **Deploy**. چند دقیقه بعد برنامه روی زیردامنه‌ی Vercel آماده است.
6. **منطقه‌ی اجرا:** پروژه ← **Settings ← Functions ← Function Region** ← **Frankfurt, Germany (fra1)** را انتخاب و یک بار Redeploy کنید تا سرور کنار پایگاه داده باشد (هر درخواست چند برابر سریع‌تر می‌شود).
7. **اولین حساب:** نشانی سایت را باز کنید ← «ساخت حساب تازه». اولین حسابی که ساخته شود مدیر سامانه است. **کد بازیابی** را که نمایش داده می‌شود یادداشت کنید (تنها راه بازیابی رمز بدون ایمیل). بعد کسب‌وکار را با ویزارد بسازید (نوع فعالیت ← ماژول‌ها ← مشخصات).

> **بیدار ماندن Supabase:** پروژه‌ی رایگان Supabase پس از یک هفته بی‌استفاده‌ماندن متوقف می‌شود. `vercel.json` هر روز نشانی `/api/cron/keepalive` را صدا می‌زند؛ کار دیگری لازم نیست.
>
> **چند پروژه‌ی Vercel روی یک مخزن:** هر پروژه‌ی Vercel که به این مخزن وصل است با هر push ساخته می‌شود. برای این‌که پروژه‌ی تراز فقط با تغییر پوشه‌ی خودش ساخته شود: Vercel ← پروژه ← Settings ← Git ← **Ignored Build Step** ← Custom: `git diff HEAD^ HEAD --quiet -- .` و در پروژه‌ی Task Flow (ریشه‌ی مخزن) پوشه‌ی `taraz` را هم مثل بقیه کنار بگذارید: `git diff HEAD^ HEAD --quiet -- . ':(exclude)pars-website' ':(exclude)celin-website' ':(exclude)taraz'`.
>
> **پلن Vercel:** پلن رایگان Hobby طبق قوانین Vercel برای استفاده‌ی غیرتجاری است؛ برای ارائه به مشتریان، پلن Pro را در نظر بگیرید.

## ۳. دامنه‌ی اختصاصی و دسترسی از داخل ایران

- Vercel ← پروژه ← Settings ← **Domains** ← دامنه‌ی خودتان (مثلاً `app.example.ir`) را اضافه و رکوردهای DNS گفته‌شده را بسازید.
- دامنه‌های `vercel.app` گاهی در ایران محدود می‌شوند؛ با دامنه‌ی اختصاصی وضعیت بهتر است. مرورگر کاربر **فقط با دامنه‌ی خود برنامه** حرف می‌زند (فونت‌ها و همه‌ی فایل‌ها از همان‌جا) و Supabase فقط از سمت سرور صدا زده می‌شود.
- برای پایداری بیشتر یک CDN داخلی (مثل ابرآروان) جلوی دامنه بگذارید، یا برنامه را روی یک سرور داخلی اجرا کنید (همان کد Next.js به‌صورت `standalone` ساخته می‌شود):
  ```bash
  cd taraz && npm ci && npm run build
  DATABASE_URL=... node .next/standalone/server.js   # پوشه‌های public و .next/static را کنار آن کپی کنید
  ```
- **قیمت‌های زنده:** سرویس‌های ایرانی (مثل نوبیتکس و tgju) فقط از داخل ایران پاسخ می‌دهند و بعضی سرویس‌های خارجی ایران را مسدود می‌کنند. نسخه‌ی ویندوز قیمت‌ها را از اینترنت خود فروشگاه می‌گیرد و نسخه‌ی وب از سرور Vercel؛ در تنظیمات هر ماژول می‌توانید منبع قیمت را عوض کنید یا «منبع سفارشی» (هر نشانی JSON) بگذارید.

## ۴. نسخه‌ی ویندوز (فایل نصب)

**دریافت فایل نصب:** صفحه‌ی **Releases** مخزن در GitHub ← آخرین «تراز … نسخه‌ی ویندوز» ← فایل `Taraz-Setup-x.y.z.exe`. این فایل را هر بار که در شاخه‌ی `main` (یا شاخه‌ی پیش‌نمایش) تغییری در پوشه‌ی `taraz` push شود، GitHub Actions روی یک ویندوز واقعی می‌سازد، نصب و آزمایش می‌کند و منتشر می‌کند (workflow: `.github/workflows/taraz.yml`). همان فایل در بخش **Actions ← اجرای آخر ← Artifacts** هم هست.

**نصب:** فایل را روی فلش کپی کنید، روی هر رایانه‌ی ویندوز ۱۰ یا ۱۱ (۶۴ بیتی) اجرا کنید ← «بعدی» ← «موافقم» ← محل نصب ← «نصب». همه‌چیز (برنامه، پایگاه داده‌ی PostgreSQL داخلی، فونت‌ها) در همین یک فایل است و به اینترنت یا نصب چیز دیگری نیاز ندارد. جزئیات: [`DESKTOP_FA.md`](DESKTOP_FA.md).

> **هشدار SmartScreen:** چون فایل نصب امضای دیجیتال تجاری ندارد، ویندوز ممکن است پیغام «Windows protected your PC» نشان دهد ← **More info** ← **Run anyway**. برای حذف این پیغام باید یک گواهی Code Signing بخرید و در workflow تنظیم کنید (`CSC_LINK` و `CSC_KEY_PASSWORD` در GitHub Secrets).

**وصل کردن به نسخه‌ی وب:**
- اگر از قبل در وب کسب‌وکار دارید: در اولین اجرا گزینه‌ی «اتصال به حساب ابری» ← نشانی سایت (مثلاً `https://app.example.ir`)، ایمیل و رمز ← انتخاب کسب‌وکار. همه‌ی اطلاعات دریافت می‌شود و با همان ایمیل و رمز وارد می‌شوید.
- اگر روی ویندوز شروع کرده‌اید: «تنظیمات ← نسخه‌ی ویندوز ← اتصال به حساب ابری» ← جهت «بارگذاری کسب‌وکار همین رایانه». کسب‌وکار در وب ساخته می‌شود و از آن به بعد هم‌گام می‌ماند.

## ۵. امنیت و نگهداری

- **پشتیبان‌گیری وب:** پلن رایگان Supabase پشتیبان قابل‌دانلود ندارد. هر چند وقت یک بار با `pg_dump` (رشته‌ی اتصال Session pooler، پورت 5432) پشتیبان بگیرید، یا روی یک رایانه نسخه‌ی ویندوز را وصل نگه دارید: نسخه‌ی ویندوز هر ۶ ساعت از کل داده‌ها پشتیبان می‌گیرد (۳۰ نسخه‌ی آخر).
- رمزها با scrypt هش می‌شوند؛ نشست‌ها توکن تصادفی‌اند و فقط هش آن‌ها ذخیره می‌شود؛ «خروج از همه‌ی دستگاه‌ها» در «حساب کاربری من».
- هر کسب‌وکار کاربران خودش را با نقش‌های مالک، مدیر، حسابدار، فروشنده، صندوقدار، انباردار و ناظر دارد و دسترسی هر بخش (مشاهده/ثبت/کامل) قابل تنظیم است. همه‌ی تغییرات در «گزارش رویدادها» ثبت می‌شوند.

## ۶. توسعه‌ی محلی

```bash
cd taraz
npm ci
npm run build:ui                      # رابط کاربری در public/
npm run start:local                   # نسخه‌ی «ویندوزی» بدون Electron روی http://127.0.0.1:3939 (پایگاه داده در .local-data)
DATABASE_URL=postgres://… npm run dev # نسخه‌ی وب (Next.js) — npm run dev:ui برای رابط کاربری با Vite
npm run typecheck && npm test && npm run build
npm run schema                        # پس از تغییر migrationها: supabase/schema.sql را به‌روز می‌کند
```

ساخت فایل نصب ویندوز روی رایانه‌ی خودتان (روی ویندوز؛ روی لینوکس به Wine نیاز دارد):

```bash
cd taraz && npm ci && (cd desktop && npm ci)
node scripts/build-desktop.mjs
cd desktop && npx electron-builder --win nsis --x64
```
