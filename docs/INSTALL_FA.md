# راهنمای نصب Task Flow — فقط مالک اپ (یک بار)

> این راهنما برای **مالک** است که اپ مشترک را یک بار روی Vercel و Supabase راه می‌اندازد. بقیه‌ی کاربران چیزی نصب نمی‌کنند؛ راهنمای آن‌ها [`SETUP_USER_FA.md`](SETUP_USER_FA.md) است.
>
> همه‌چیز روی پلن‌های **رایگان** اجرا می‌شود: **Vercel Hobby** (اپ) · **Supabase Free** (دیتابیس، ورود، فایل‌ها، زمان‌بند). کلیدهای هوش مصنوعی و GitHub را هر کاربر (از جمله خود مالک) داخل اپ وصل می‌کند.

## امنیت و حریم خصوصی

- هیچ کلید، توکن یا رمزی را داخل مخزن ننویسید؛ فقط در Environment Variables ی Vercel.
- کلیدهای کاربران با `APP_SECRET_KEY` رمزنگاری می‌شوند. این متغیر را **قبل از اینکه کسی کلیدی وصل کند** تنظیم کنید و بعداً عوضش نکنید (وگرنه کاربران باید دوباره وصل کنند).
- تنظیمات Vercel/Supabase، کاربران و ارتقای اپ فقط برای مالک است و در مخزن چیزی از آن‌ها نیست. پروژه‌ها و فایل‌های شخصی مالک هم مثل بقیه‌ی کاربران در مخزن کاری **خودِ** مالک (جدا از مخزن اپ) ذخیره می‌شوند؛ بنابراین مخزن اپ قابل اشتراک است و چیزی از اطلاعات شخصی در آن نیست.

## ۱) Supabase

1. <https://supabase.com> ← **New project** (Plan: Free، منطقه‌ی نزدیک، رمز دیتابیس را امن نگه دارید).
2. **SQL Editor ← New query** و فایل‌های پوشه‌ی [`supabase/migrations`](../supabase/migrations) را **به ترتیب نام** اجرا کنید:
   1. `20260925000000_init.sql`
   2. `20260926000000_avatars.sql`
   3. `20261003000000_multi_tenant.sql` ← نسخه‌ی چندکاربره
   - هر فایل را کامل کپی، پیست و **Run** کنید؛ باید `Success. No rows returned` ببینید.
   - **اگر نسخه‌ی قبلی اپ را دارید:** فقط فایل سوم (`20261003000000_multi_tenant.sql`) را اجرا کنید. این فایل یک بار داده‌های آزمایشی قبلی (تسک‌ها، صف، فایل‌ها، دانش) را پاک می‌کند؛ کاربران و حساب‌ها می‌مانند. اجرای دوباره‌ی آن بی‌خطر است. فایل‌های قدیمی را دوباره اجرا نکنید.
   - اگر secret `SUPABASE_DB_URL` در مخزن اپ تنظیم باشد، ادغام Pull Request در `main` این migration را خودکار اجرا می‌کند (ورکفلوی «Database migrations»).
3. **Project Settings ← API Keys**: `Project URL` (فقط `https://<ref>.supabase.co`)، کلید **anon/publishable** و کلید **service_role/secret** را بردارید.
4. **Authentication ← Sign In / Providers ← Email**: Email provider روشن، **Confirm email خاموش**.
5. بعد از قدم ۲: **Authentication ← URL Configuration** ← Site URL = آدرس اپ، Redirect URLs = `https://<آدرس>/**`.

## ۲) Vercel

1. <https://vercel.com> ← با GitHub وارد شوید ← **Add New… → Project** ← مخزن اپ را Import کنید.
2. **Environment Variables:**

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://<ref>.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | کلید anon/publishable |
| `SUPABASE_SERVICE_ROLE_KEY` | کلید service_role/secret |
| `OWNER_EMAIL` | ایمیل خودتان (نام قدیمی `ADMIN_EMAIL` هم کار می‌کند) |
| `CRON_SECRET` | رشته‌ی تصادفی طولانی (`openssl rand -hex 32`) |
| `APP_SECRET_KEY` | رشته‌ی تصادفی طولانی دیگر (`openssl rand -hex 32`) |
| `APP_URL` | (پیشنهادی) آدرس نهایی اپ، مثلاً `https://my-tasks.vercel.app` |

   اختیاری — فقط برای «ارتقای اپلیکیشن» (Claude Code روی مخزن کد همین اپ): `GITHUB_TOKEN` (classic با `repo` و `workflow`)، `GITHUB_OWNER`، `GITHUB_APP_REPO`.
   اختیاری: `WORKSPACE_REPO_NAME` (نام پیش‌فرض مخزن کاری کاربران). راهنمای کاربران داخل خود اپ است (منوی «راهنما»).

3. **Settings ← Functions**: **Fluid compute** روشن باشد (برای پروژه‌های جدید پیش‌فرض است) — ورکر هر بار تا ۳۰۰ ثانیه کار می‌کند تا مجری داخل اپ کارهای بزرگ را بی‌وقفه پیش ببرد. Function Region را هم‌منطقه‌ی Supabase بگذارید (مثلاً Frankfurt ← `fra1`).
4. **Deploy**. سپس **Settings ← Domains** ← یک زیردامنه‌ی رایگان `….vercel.app` انتخاب کنید و در صورت تغییر، `APP_URL` را به‌روز و Redeploy کنید.

## ۳) اولین ورود و راه‌اندازی

1. بلافاصله به `/signup` بروید و با **همان `OWNER_EMAIL`** ثبت‌نام کنید ← **مالک** می‌شوید.
2. **مدیریت ← سیستم** (`/system`):
   - همه‌ی موارد «وضعیت سرویس‌ها» باید سبز باشند.
   - **زمان‌بند ورکر** ← «هر ۳۰ ثانیه» ← **فعال‌سازی** (Supabase با pg_cron ورکر اپ را صدا می‌زند).
   - **ثبت‌نام**: اگر می‌خواهید هر کسی بدون تایید شما فعال شود، «کاربران جدید بدون تایید مالک فعال شوند» را روشن کنید؛ وگرنه در **کاربران** تایید می‌کنید.
   - **ظرفیت اجرا**: پیش‌فرض‌ها (۶ اجرای هم‌زمان مدل برای همه، ۱ برای هر کاربر؛ GitHub Actions تا ۳ برای هر کاربر) برای پلن رایگان مناسب‌اند.
3. مثل هر کاربر دیگری کلید هوش مصنوعی و GitHub **خودتان** را در **تنظیمات** وصل کنید ([راهنمای کاربران](SETUP_USER_FA.md)).
4. لینک اپ را به همکاران بدهید: `https://<آدرس>/signup`. همه در حالت ساده شروع می‌کنند و با آیکون «تجربه‌ی کامل» (موشک) خودشان فعالش می‌کنند.
5. (اختیاری) **مدیریت ← اطلاعیه**: متنی که همه‌ی کاربران بالای صفحه می‌بینند؛ هر بار که متن را عوض کنید دوباره برای همه نمایش داده می‌شود.

## ۴) (اختیاری) ارتقای خودکار اپ

با `GITHUB_TOKEN`، `GITHUB_OWNER` و `GITHUB_APP_REPO`: در **مدیریت ← سیستم ← Secrets مخزن اپ** توکن Claude Code (`claude setup-token`) یا کلید API را ثبت کنید (و برای اجرای خودکار migrationها، `SUPABASE_DB_URL` از Supabase ← Connect ← Session pooler). سپس **مدیریت ← ارتقا**: فقط پرامپت بنویسید؛ Claude Code تغییر را پیاده، build را بررسی و Pull Request می‌سازد؛ پیش‌نمایش Vercel و ادغام از همان صفحه.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| صفحه‌ی «اپ هنوز تنظیم نشده است» | متغیرهای محیطی را کامل و Redeploy کنید. |
| «Invalid path specified in request URL» | `NEXT_PUBLIC_SUPABASE_URL` دقیقاً `https://<ref>.supabase.co` باشد. |
| «اتصال به Supabase و اسکیمای چندکاربره» قرمز است | `20261003000000_multi_tenant.sql` را در SQL Editor اجرا کنید. |
| کارها در صف می‌مانند | مدیریت ← سیستم ← زمان‌بند را دوباره فعال کنید؛ صف اجرا ← «اجرای فوری». |
| «کلید ذخیره‌شده قابل بازگشایی نیست» | `APP_SECRET_KEY` یا کلید سرویس Supabase عوض شده؛ کاربران باید کلیدها را دوباره ثبت کنند. |
| ورکر وسط کار بزرگ قطع می‌شود | Fluid compute را روشن کنید؛ در غیر این صورت `WORKER_BUDGET_SECONDS=50` بگذارید. |
| Claude Code یک کاربر اجرا نمی‌شود | آن کاربر در تنظیمات ← GitHub «همگام‌سازی» بزند و تب Actions مخزن کاری‌اش را فعال کند. |

## محدودیت‌های پلن‌های رایگان

| سرویس | محدودیت | راهکار در اپ |
|---|---|---|
| Vercel Hobby | ۳۰۰ ثانیه برای هر تابع (Fluid compute)؛ cron فقط روزانه | ورکر کارها را گام‌به‌گام و قابل ادامه اجرا می‌کند؛ زمان‌بند با pg_cron در Supabase |
| Supabase Free | ۵۰۰MB دیتابیس، ۱GB فایل | فایل‌های پروژه‌ها در GitHub کاربران است نه در Supabase؛ لاگ‌های قدیمی خودکار پاک می‌شوند |
| کلیدهای کاربران | سقف درخواست هر سرویس | صف جدا برای هر کاربر؛ توقف و ادامه‌ی خودکار فقط برای همان کلید |
| GitHub Free | ۲۰۰۰ دقیقه Actions در ماه برای هر حساب | از سهمیه‌ی حساب خود هر کاربر مصرف می‌شود |
