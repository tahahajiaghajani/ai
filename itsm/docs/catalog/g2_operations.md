# Incident, problem, event/AIOps/on-call and continuity

Group `g2_operations`: modules `incident`, `problem`, `event` (monitoring, event management, AIOps, on-call) and `continuity` (availability, capacity/performance, service continuity/BCM, resilience). Consolidated and deduplicated from the research reports itil, standards, servicenow, jsm, freshservice, bmc_manageengine, others, ai, access and analytics_ux.

**Entry format:** `ID Name` (Persian name) · tier · AI — what it does and how. The "AI" tag means ai = yes; entries without it are ai = no. **Src:** tools/frameworks. **Impl:** hint for our metadata engine. Tiers: **P0** must for an enterprise v1 · **P1** strong differentiator to build · **P2** later/optional. "→ x" means module x owns or shares the capability.

**Abbreviations:** SN ServiceNow · JSM Jira Service Management · FS Freshservice · BMC BMC Helix · SDP ManageEngine ServiceDesk Plus · PD PagerDuty · ITIL4/ITIL5 (ITIL 4 practice guides / ITIL Version 5) · ISO20k ISO/IEC 20000-1 · SRE Google SRE book/workbook · KCS KCS v6 · MI major incident · KE known error · CI configuration item · CAPA corrective/preventive action.

## Module: incident — مدیریت رخداد

### Features

#### Record, intake and classification
- **INC-001 Incident record** (رکورد رخداد) · P0 — One record with ITIL PG Table 5.1 content plus tool fields: caller, affected user, opened_by, channel, company/org unit/location, service, offering, CI and affected CIs, category→subcategory→item, impact, urgency, priority, state + reason, group, assignee, owner group, first-symptom and last-good times, current/future impact, comparable unaffected item, workaround, resolution/cause codes and notes, parent, problem, KE, caused-by change, model, VIP/major/security/regulatory flags, reassignment/reopen counters, supplier ref, auto-resolved and detected-by-monitoring flags, CSAT. **Src:** ITIL4 PG, ISO20k §8.6, FitSM PR9, COBIT DSS02, SN, FS, BMC, SDP, JSM. **Impl:** `incident` extends `task`; store every milestone time (detected, registered, accepted, diagnosis start/end, resolved, closed) for KPIs.
- **INC-002 Lifecycle, reasons and transition rules** (چرخهٔ عمر، دلیل وضعیت و قواعد گذار) · P0 — New → Assigned → In Progress ⇄ On Hold → Resolved → Closed, plus Canceled; every state has a reason list (awaiting caller/supplier/change/problem/evidence, client hold, automated resolution) with an agent label, a requester label, an SLA-pause flag and a "counts in statistics" flag; transitions carry guards (required fields, roles); per-profile transition matrices and option-level limits (allowed states/priorities per context); Closed is immutable. **Src:** SN, BMC, FS, SDP, GLPI, Znuny ACLs, ISO20k, FitSM PR9.5. **Impl:** engine state model with categories; reason drives SLA pause.
- **INC-003 Priority matrix** (ماتریس اولویت) · P0 — Versioned impact × urgency matrix (default 3×3 → 5 levels, optional service-tier or VIP dimension) computes a read-only priority; override needs a permission and a reason; computed priority, final priority and matrix version are stored and audited; priority drives SLA targets and paging. **Src:** ITIL4, SN, FS, SDP, BMC, ISO20k, FitSM PR9.1. **Impl:** engine lookup table; recompute on change unless overridden.
- **INC-004 Omnichannel intake** (ثبت چندکاناله) · P0 — Incidents from portal "report an issue", email (OAuth mailboxes, threading, unknown sender → contact, spam/trash with restore), phone/CTI, chat, walk-up, mobile, Teams/Slack, virtual agent, monitoring, API and "raise from this CI/asset"; Bale, Eitaa, Telegram and SMS short codes are first-class channels; channel recorded, custom sources allowed. **Src:** SN, FS, SDP, JSM, BMC, Halo; Iran market. **Impl:** channel adapters feed one record-producer pipeline; dedupe inbound by message id.
- **INC-005 Email commands** (فرمان‌های ایمیلی) · P2 · AI — Agents act by email: a marker phrase plus commands (assign, pick up, add note, resolve, close, add task/worklog), several per email; AI parses free-form command text. **Src:** SDP Zia Parser. **Impl:** parser on inbound mail; actions run as the sender with permission checks.
- **INC-006 Incident models and templates** (مدل‌ها و الگوهای رخداد) · P0 — Templates pre-fill any field, assignment, tasks and checklists; ITIL incident models add a model-specific SLA, task flow, communications, supplier involvement and an optional self-healing runbook; visibility per group; the model used is stored. **Src:** ITIL4, BMC, SDP, FS, JSM. **Impl:** `incident_model` config + flow; feeds KPI "% resolved with models".
- **INC-007 Forms and form rules** (فرم‌ها و قواعد فرم) · P0 — Per-workspace agent and portal forms with dynamic sections, dependent category lists, mandatory-on-resolve fields and client rules (show/hide, mandatory, set/clear, filter options, validation messages). **Src:** FS business rules, SN UI policies, SDP. **Impl:** engine layouts + condition-based UI policies.
- **INC-008 Decision trees** (درخت تصمیم برای ثبت) · P1 — Admin-built question trees fill category, CI, template and description; chosen from the typed text; reusable as guided self-help on the portal. **Src:** BMC, EasyVista Self Help. **Impl:** questionnaire flow whose answers map to fields.
- **INC-009 AI capture from text, voice and screenshots** (ثبت هوشمند از متن، صدا و تصویر) · P1 · AI — Formless entry: typed or spoken text, an email or an error screenshot (OCR) becomes a structured draft with caller, CI, template, category and priority, plus similar incidents and KB before save; also a chat "create incident" agent. **Src:** BMC Smart Recorder, SMAX Smart Ticket, Ivanti Incident Agent, SN Create Incident agent, FS image support. **Impl:** AI skill with JSON schema; local OCR and Persian speech-to-text.
- **INC-010 Caller verification** (احراز هویت تماس‌گیرنده) · P1 — Security questions (masked, regex rules, required correct answers, lockout) or a one-time code by SMS/messenger before sensitive actions; the result is saved on the record. **Src:** Halo, SN assisted password reset. **Impl:** hashed answer store; verification event in the journal.
- **INC-011 AI triage** (تریاژ هوشمند) · P0 · AI — On create, suggests category, service/offering, CI (from the caller's assets), impact, urgency and group with top-3 options, confidence and reason; auto-applies above a governed threshold, otherwise suggests, and writes "Not determined" when unsure; accept/override is training feedback. **Src:** SN Predictive Intelligence and triage workflow, FS autofill, SDP Zia, TOPdesk, SysAid, Ivanti, InvGate, Zendesk, BMC, ITIL4 PG. **Impl:** per-tenant classifier (embeddings + kNN/logistic) with LLM fallback; `ai_suggestion`; nightly retrain.

#### Assignment, escalation and work
- **INC-012 Assignment and routing** (ارجاع و مسیریابی) · P0 — Ordered rules (conditions → group/user), lookups (category/CI/location → group), CI support group auto-fill, round-robin, load- and skill-ranked routing gated by shift, online status and leave (end-of-shift guard), push offers with accept timers, "assign to me" and a policy-preview explainer. **Src:** SN AWA, FS assignment policies, SDP, JSM. **Impl:** shared routing service (→ workforce); each decision explained in history.
- **INC-013 Functional and hierarchical escalation** (ارتقای وظیفه‌ای و سلسله‌مراتبی) · P0 · AI — Time- and rule-based escalation to the next tier, provider or manager by priority and SLA risk; escalation level on the record; an AI label (critical/high/medium) with its reason from remaining SLA time, impact and urgency. **Src:** ISO20k, FitSM PR9.3, COBIT DSS02.04, SN escalation workflow. **Impl:** SLA-risk events + rules; AI label is a suggestion.
- **INC-014 Reassignment governance** (کنترل ارجاع‌های پیاپی) · P1 — Mandatory reason, reassignment counter, alert above 2 hops, bounce-back to the previous group only with lead approval, and "request assist/pairing" instead of reassigning. **Src:** ITIL4 PG §4.2, SIAM BoK. **Impl:** guard on group change; hop count in facts.
- **INC-015 Incident tasks** (وظایف رخداد) · P0 — Child tasks for other groups with own state, SLA/OLA, assignee, dependencies and templates; closed tasks are locked; resolving the parent is blocked while mandatory tasks are open. **Src:** SN, FS, SDP, BMC. **Impl:** generic task child table.
- **INC-016 Checklists** (چک‌لیست) · P1 · AI — Ordered items from templates or CSV, verification ticks and a closure rule; AI generates a checklist from the description and KB. **Src:** SDP checklist generator, Zammad, JSM. **Impl:** `checklist_item` rows.
- **INC-017 Parent and child incidents** (رخداد والد و فرزند) · P0 — Many children link to one parent; resolving the parent cascades resolution code, notes and state; comment/work-note propagation is configurable; "create child" and "copy incident". **Src:** SN, FS, BMC, JSM. **Impl:** `parent_incident_id`; async cascade with notification de-dupe.
- **INC-018 Merge and split** (ادغام و تفکیک) · P0 — Merge duplicates into a primary (conversations, attachments, time and watchers move; secondaries close as Duplicate with `merged_into_id`; later replies redirect); split a reply raising a new issue into a linked incident. **Src:** FS, SDP, Zendesk. **Impl:** engine merge operation; merged rows excluded from KPIs.
- **INC-019 Similar, duplicate and cluster-matched incidents** (رخدادهای مشابه، تکراری و هم‌خوشه) · P0 · AI — Panel of similar open/resolved incidents (semantic, Persian-normalised), duplicate hints (same requester ±14 days, same CI), a "cluster matched" tab with the cluster's AI description and fix, and suggested links; one click links or merges. **Src:** SN, FS, Zendesk, Halo, InvGate, JSM, Ivanti. **Impl:** hybrid vector + lexical search with ACL filter; nearest-centroid cluster (→ PRB-012).
- **INC-020 "Me too" affected users** (ثبت کاربر متأثر) · P1 · AI — When a portal draft matches an open incident on the same service (cosine ≥ 0.9), the user is offered "add me as affected" instead of a new ticket; the count feeds impact and MI criteria. **Src:** ai.md pattern, SN service disruptions. **Impl:** `incident_affected_user`.
- **INC-021 Affected services, CIs and computed impact** (سرویس‌ها و CIهای متأثر و اثر محاسبه‌شده) · P0 — Affected services, CIs and impacted areas (company/site/org unit); a CMDB walk adds upstream/downstream CIs, services and contacts flagged "computed"; optional rule blocks Resolve while an impacted area is Draft; dependency graph view. **Src:** iTop, BMC impacted areas and impact analysis, JSM affected services, IFS assyst. **Impl:** `incident_affected_ci` (manual/computed/alert); graph API (→ cmdb).
- **INC-022 Business and financial impact** (اثر کسب‌وکاری و مالی) · P1 — Structured impact (users, customers, transactions affected, revenue per hour, penalties, perceived lost time) yields a cost-of-downtime estimate for prioritising, PIR and problem ranking. **Src:** BMC, standards (cost of failure, EU DORA economic impact), HappySignals. **Impl:** computed fields; rates per service (→ financial).

#### Collaboration on the record
- **INC-023 Journal and activity stream** (یادداشت‌ها و جریان فعالیت) · P0 — Append-only journal with public/internal/restricted visibility, @mentions, attachments, mail in/out and back-dated notes, merged at read time with field diffs, system and AI events; filter chips; internal notes visibly distinct. **Src:** SN, JSM, FS, Zendesk, ISO20k. **Impl:** engine journal + audit; requester APIs never read internal rows.
- **INC-024 Composer, canned responses and macros** (ویرایشگر پاسخ، پاسخ آماده و ماکرو) · P0 — Public/internal toggle with warning, "/" inserts canned responses with placeholders, KB insert (link or content), signature, "send and set status", shared drafts, and macros that apply fields, notes and mails to one or many incidents. **Src:** FS, Zendesk, SN, SDP, Zammad. **Impl:** template engine with Persian placeholders and Jalali dates.
- **INC-025 Watchers and sharing** (ناظران و اشتراک) · P0 — Watch list, CC, participants and explicit sharing with users/groups; each gets notifications and participant visibility. **Src:** SN, FS, JSM, SDP. **Impl:** participant keys in the access model.
- **INC-026 Collision and presence** (نمایش حضور هم‌زمان) · P1 — Live avatars of viewers and typists (public vs internal), "record changed" prompt, optional block of a public reply right after a colleague's; AI agents show presence too. **Src:** FS, Zammad, analytics_ux. **Impl:** WebSocket presence, 30 s TTL.
- **INC-027 Notifications and progress** (اعلان‌ها و اطلاع از پیشرفت) · P0 — Templates per event (created, assigned, commented, state change, SLA warning/breach, resolved, reopened) for requester, CC, watchers and agents; reply-to-update; requester timeline on the portal. **Src:** FitSM PR9.4, FS, SN. **Impl:** engine notifications, multichannel, Persian templates.
- **INC-028 Time tracking and cost** (ثبت زمان و هزینه) · P1 — Timers (one running per agent) and manual entries with work type, billable flag and task; effort × rate gives incident cost; optional resolution price for chargeback. **Src:** FS, SDP, ITIL4 PG. **Impl:** generic `time_entry`; partial unique index on the running timer.

#### SLA, resolution and closure
- **INC-029 SLA timers** (زمان‌سنج‌های SLA) · P0 — Response and resolution timers (plus OLA and supplier UC) per priority/service on business calendars, paused by hold reasons, with at-risk (≥ 75%) warnings, breach escalations and SLA chips (running, paused, at risk, breached, met). **Src:** SN, FS, SDP, JSM, BMC, ISO20k. **Impl:** engine SLA service (→ slm); the server computes deadlines.
- **INC-030 SLA breach prediction** (پیش‌بینی نقض SLA) · P1 · AI — Scores open incidents for breach risk with confidence and the drivers (queue load, history, missing data) so leads can act before the at-risk threshold. **Src:** SDP Zia (2026). **Impl:** gradient-boosted model on time-in-state facts.
- **INC-031 Resolution and cause codes** (کدهای حل و علت) · P0 — Controlled lists (solution provided, workaround, known error, resolved by change/problem/request, resolved by caller, user error, duplicate, no response) plus cause codes. **Src:** SN, BMC, ITIL4. **Impl:** choice lists required by closure rules.
- **INC-032 Closure rules and wizard** (قواعد و راهنمای بستن) · P0 — Resolve/close is blocked until required fields, tasks, checklists, approvals or attachments are complete; a wizard lists what is missing. **Src:** SDP, FS, standards. **Impl:** validation set bound to transitions.
- **INC-033 User confirmation and auto-close** (تأیید کاربر و بستن خودکار) · P0 — On Resolved the caller confirms or rejects by link (email, SMS, messenger); rejection returns the incident to work; silence → Closed after N business days on the Jalali calendar. **Src:** SN, FS, SDP, BMC, ITIL4. **Impl:** scheduled job on the business-time service.
- **INC-034 Reopen policy** (سیاست بازگشایی) · P0 · AI — Reopen within a window (counter, landing state, notice) or open a linked successor (BMC style), per tenant setting; recurrence after Closed opens a linked follow-up; AI checks whether a reply needs reopening (ignores thanks and auto-replies). **Src:** SN, BMC, SDP Zia. **Impl:** reopen action + reply intent classifier.
- **INC-035 Awaiting-caller follow-ups** (پیگیری خودکار در انتظار کاربر) · P1 · AI — Reminders at business-day intervals (default 3) then auto-resolve "no response"; AI screens replies so acknowledgements do not restart the clock and writes the caller what is still needed. **Src:** SN, BMC. **Impl:** scheduled job + reply classifier.
- **INC-036 Satisfaction and experience survey** (نظرسنجی رضایت و تجربه) · P0 — On resolve/close: CSAT or 0–10 rating, perceived lost time and influencing factors, stored on the incident and in XLA analytics. **Src:** ITIL4, FS, HappySignals, HDI. **Impl:** engine survey (→ analytics).

#### Knowledge, problem and change links
- **INC-037 KCS knowledge use** (بهره‌گیری از دانش به روش KCS) · P0 — Search from the form, link articles (resolved_by/related/created_from + version), flag or fix an article in place, "report knowledge gap", create an article from the incident in any state. **Src:** KCS, SN, FS, SDP, JSM. **Impl:** `kb_usage` feeds link rate (→ knowledge).
- **INC-038 KB draft from resolved incidents** (پیش‌نویس مقاله از رخداد حل‌شده) · P1 · AI — On close, if no article was linked and the fix is novel (low similarity to the KB), AI drafts a KCS article for review. **Src:** SN, BMC, FS, SDP. **Impl:** AI skill + similarity gate.
- **INC-039 Known-error matching and "apply workaround"** (تطبیق خطای شناخته‌شده و اعمال راه‌حل موقت) · P0 · AI — Triage retrieves matching KEs (symptoms, CI) and shows the workaround; "apply workaround" links the KE, sets the code and counts usage for the technical-debt score. **Src:** ITIL4, ISO20k §8.6.3, FitSM PR9.2, SN. **Impl:** hybrid search on `known_error` (→ PRB-019).
- **INC-040 Create problem, change or request** (ایجاد مشکل، تغییر یا درخواست) · P0 — Pre-filled creation and links: problem (M:N), fix change, caused-by change; convert a misfiled incident to a request and back. **Src:** SN, FS, SDP, JSM, BMC. **Impl:** typed relations; conversion copies the journal.
- **INC-041 Change correlation** (یافتن تغییر عامل) · P1 · AI — Investigation view of what changed on affected and upstream CIs since the last good time (changes, deployments, config, feature flags); AI ranks changes closed in the last 14 days; "mark as potential cause" sets caused-by. **Src:** FS Find initiating changes, JSM investigation view, SN. **Impl:** CI-graph + time-window query and ranking (→ change).

#### Self-service and proactive communication
- **INC-042 Portal intake with deflection** (ثبت در پورتال با پیشنهاد راه‌حل) · P0 · AI — While typing, the form offers KB answers, known outages and similar open incidents; email-created incidents may get a KB-grounded answer with a "this solved it" option; deflections are logged. **Src:** SN, BMC, SysAid Emailbot, FS. **Impl:** semantic search on the draft; `deflection_event`.
- **INC-043 Broadcasts and outage announcements** (اطلاعیه و اعلان قطعی) · P0 — Targeted banners (company, group, location, service subscribers) with start/expiry for outages and MIs on portal, agent workspace and bots; known-outage answers in the virtual agent. **Src:** BMC broadcasts, SDP announcements, SN, JSM. **Impl:** `announcement` with audience.
- **INC-044 Interactions** (تعامل‌ها) · P1 — Phone/chat/walk-up interaction with transcript and wrap-up, linked to the incident and closed with it. **Src:** SN. **Impl:** `interaction` (→ portal).

#### Major incidents
- **INC-045 MI criteria and lifecycle** (معیار و چرخهٔ رخداد عمده) · P0 — Versioned criteria (priority, service tier, affected users, regulatory flag) flag candidates; agents propose; the MI manager accepts, rejects, demotes or closes; overlay none → candidate → proposed → accepted → resolved → PIR done; accepted MI becomes the parent; MI queue; top-management notice; criteria separate MIs from disasters (→ CON-028). **Src:** ITIL4 PG, ISO20k, FitSM PR9.6, SN MIM, FS, JSM. **Impl:** overlay field + rules; criteria snapshot stored.
- **INC-046 MI workbench (war room)** (اتاق عملیات رخداد عمده) · P0 — One pane for MI manager, comms lead and resolvers: overview, live timeline, tasks, children, affected services/CIs, communications, bridges and decision log; incident-command roles (commander, ops, comms, planning, scribe) with logged handover. **Src:** SN workbench, JSM, FS, SRE, ITIL4. **Impl:** special UI + `mi_role_assignment`.
- **INC-047 AI MI detection** (تشخیص هوشمند رخداد عمده) · P1 · AI — 60-minute sliding window; incidents join when similarity ≥ 0.82 (or same CI/service and ≥ 0.70); ≥ 5 incidents, ≥ 3 callers and a significant burst (Poisson p < 0.01) make a candidate with an AI title; similar incidents become children after human confirmation. **Src:** SN, InvGate, Ivanti, standards. **Impl:** streaming job → `ai_suggestion`.
- **INC-048 Communication plans and cadence** (برنامهٔ ارتباطات و آهنگ به‌روزرسانی) · P0 — Plans attach by type/priority/audience and create comm tasks with offsets and recurrence (e.g. P1 every 30 min), stage templates, overdue-update warnings, approval for public statements, and channels: email, SMS, banner, status page, messengers, Teams/Slack; every message logged. **Src:** SN TCM, FS Collaborate, JSM, NIST CSF RS.CO, ISO20k. **Impl:** `comm_plan`, `comm_task`, `communication`.
- **INC-049 AI stakeholder updates** (پیش‌نویس هوشمند به‌روزرسانی ذی‌نفعان) · P1 · AI — Drafts internal and external emails, executive notes and status-page text from the incident, SLA and timeline; a human reviews before sending. **Src:** SN MI email recommendation, JSM ICC, FS Freddy. **Impl:** AI skill filling template variables.
- **INC-050 Stakeholders and groups** (ذی‌نفعان و گروه‌های ذی‌نفع) · P0 — Licence-free internal/external stakeholders (verified email/phone), groups linked to services so they join automatically, subscribe/unsubscribe, "notify stakeholders" action. **Src:** JSM, FS, SN. **Impl:** `stakeholder`, `stakeholder_group`; audience-only access.
- **INC-051 Responder paging** (فراخوان پاسخ‌دهندگان) · P0 — Add users, teams, schedules or escalation policies as responders; pages go through on-call routing (priority → P1–P5), idempotent per responder; the owner team of an affected service is paged automatically. **Src:** JSM, SN, FS. **Impl:** creates `page` via EVT-035.
- **INC-052 Bridges and chat channels** (پل ارتباطی و کانال گفتگو) · P1 — One click opens a bridge (Jitsi, BigBlueButton, Skyroom, Teams, Zoom) and a war-room channel (built-in chat, Bale, Eitaa, Telegram, Slack, Teams); responders auto-added; chat lines pushed to the incident as notes; channel archived after resolution and inactivity; ChatOps commands. **Src:** JSM ChatOps, SN Notify/Sidebar, BMC Ops Swarmer, FS. **Impl:** collaboration adapters; one channel per incident.
- **INC-053 Key-event timeline** (خط زمانی رویدادهای کلیدی) · P0 — Flag journal/system entries as key events; the curated timeline (alerts, states, comms, decisions, chat excerpts, status posts) feeds PIR and executive view; back-dating allowed. **Src:** SN PIR timeline, JSM, SRE. **Impl:** `is_key_event` flag + projection.
- **INC-054 Change lockdown during MI** (قفل تغییرات هنگام رخداد عمده) · P1 — Declaring an MI on a service can freeze or pause in-flight changes on it and its dependencies until stand-down, with an exemption for the fix. **Src:** SN change lockdown. **Impl:** event to change module (→ change).
- **INC-055 Post-incident review (PIR)** (بازبینی پس از رخداد) · P0 — Record linked to the primary incident: templates (summary, impact, timeline, root causes and trigger, detection, resolution, went well/wrong/lucky, typed action items), policy triggers (MI, data loss, on-call intervention, MTTR or error-budget threshold), co-authors, Draft → Review → Published with restricted revert, blameless wording, PDF/DOCX export, searchable repository; actions become CAPA, problem tasks or changes. **Src:** ITIL4, SRE ch.15, SN, FS, JSM, BMC, ISO20k. **Impl:** `pir` + `corrective_action` (→ PRB-016).
- **INC-056 AI PIR and MIR drafting** (پیش‌نویس هوشمند گزارش رخداد) · P1 · AI — Drafts the PIR or executive MI report from timeline, journal, chat and comms with citations and blameless-language linting. **Src:** FS, BMC MIR, JSM, SN, SDP, Xurrent Recap. **Impl:** sectioned AI skill (Persian and English).
- **INC-057 Playbooks** (پلی‌بوک‌ها) · P1 · AI — SOPs shown on matching incidents: instructional and automation steps with input prompts, logged outputs and an execution log (who, when, status, duration); MI response playbook; AI suggests or drafts playbooks. **Src:** JSM, SN, Halo. **Impl:** `playbook`, `playbook_run`; automation steps call runbooks (→ EVT-026).
- **INC-058 Swarming and expert finder** (همیاری گروهی و یافتن خبره) · P1 · AI — "Start swarm": AI recommends experts by skill, history, on-call and availability; swarm channel with hypothesis, experiment and decision log; back to single owner; swarm board instead of tiers; a complexity field (simple/complicated/complex) chooses model, specialist or swarm handling. **Src:** ITIL4 PG, Intelligent Swarming, BMC, InvGate, SDP, SN. **Impl:** `swarm`; expert score = Σ skill match × availability.
- **INC-059 Supplier and SIAM incidents** (رخداد چندتأمین‌کننده و SIAM) · P1 — Supplier ticket ref, awaiting-supplier pause, UC timers; e-bonding (correlation id, field ownership, retries, reconciliation); integrator keeps end-to-end ownership; time-with-provider vs OLA; hop caps; dispute log. **Src:** ITIL4 PG §6, SIAM BoK, Xurrent. **Impl:** outbound queue with idempotency (→ supplier).

#### Security, regulation and access
- **INC-060 Security incident path** (مسیر رخداد امنیتی) · P0 — A security flag routes to a restricted security group, hides the record, prioritises by information-security risk and hands over to the security workflow (ISO 27035 / NIST 800-61r3). **Src:** ISO20k §8.7.3.3, ISO27001 A.5.24–28, ISO27035, NIST. **Impl:** restriction + conversion (→ security).
- **INC-061 Regulatory notification clocks** (ساعت گزارش به نهادهای ناظر) · P1 · AI — A regulatory case per regime with user-confirmed aware/classified times, deadlines (EU DORA 4 h/24 h → 72 h → 1 month, NIS2 24 h/72 h/1 month, GDPR 72 h), templates, submission log and countdowns; regimes are data so Iranian bodies (e.g. Maher CERT, Afta, Central Bank) can be added; AI pre-fills criteria for confirmation. **Src:** standards (EU DORA, NIS2, GDPR, SEC 8-K). **Impl:** `regulatory_case`; deadline rules on timestamps.
- **INC-062 Evidence and chain of custody** (شواهد و زنجیرهٔ نگهداری) · P2 — SHA-256 hashed attachments, append-only custody log, legal hold, export with integrity proof. **Src:** ISO27001 A.5.28, NIST CSF RS.AN. **Impl:** shared (→ security).
- **INC-063 Confidential incidents** (رخدادهای محرمانه) · P0 — Security levels and restricted groups hide incidents from non-members (including other admins); company/unit/location anchors snapshotted at create; after reassignment access remains only through another grant. **Src:** JSM, FS, BMC, SN, access.md. **Impl:** access restrictions (→ access).
- **INC-064 Roles and permissions** (نقش‌ها و مجوزها) · P0 — Read/write/admin, MI manager, comms manager, outage admin, tier-1 bundle; scopes own/group/site/workspace/all; granular actions (resolve, close, merge, reopen, edit due date, override priority, take over, delete others' notes). **Src:** SN, BMC, SDP, FS, GLPI. **Impl:** capability × scope.

#### Workspace and AI
- **INC-065 Queues and list views** (صف‌ها و نماهای فهرست) · P0 — Default and saved views (mine, unassigned, MI, breached), query filters (also from natural language), SLA columns, table/card/kanban, bulk actions, export, "new since last visit" flags. **Src:** FS, JSM, SN, Ivanti. **Impl:** engine lists.

### Data model
- **`incident`** (INC, extends `task`) — fields of INC-001 plus `priority_computed`, `priority_matrix_version`, `state_reason`, `major_incident_state`, `incident_model_id`, `complexity`, `security_level`, `restricted_group_id`, `domain_id`, `workspace_id`. States: New (new) · Assigned, In Progress (active) · On Hold + reason (waiting) · Resolved (resolved) · Closed (closed) · Canceled (canceled). MI overlay: none → candidate → proposed → accepted/rejected → resolved → pir_done.
- **`incident_task`** (ITASK): New · In Progress · Pending/Blocked (waiting) · Closed complete/incomplete · Canceled.
- **Links:** `incident_affected_ci` (source manual/computed/alert), `incident_affected_service`, `incident_impacted_area` (draft/validated), `incident_affected_user`, `kb_usage` (article version, link type), `deflection_event`.
- **MI and comms:** `mi_role_assignment` (role, user, from, to), `comm_plan` (config), `comm_task` (CTASK: Planned · Due · Sent · Skipped), `communication` (channel, template, recipients, payload, approved_by, sent_at), `stakeholder`, `stakeholder_group` (+ services), `announcement` (ANN: Draft · Scheduled (waiting) · Active · Expired (closed) · Canceled), `swarm` (SWM: Open · Closed), `playbook`, `playbook_run`.
- **`pir`** (PIR): Draft (new) · In review (active) · Published (resolved) · Archived (closed) · Canceled; primary_incident_id, template, sections, trigger.
- **`regulatory_case`** (REG): Assessing (new) · Reporting (active) · Awaiting authority (waiting) · Final submitted (resolved) · Closed · Withdrawn (canceled); `regulatory_submission` (snapshot, submitted_at, reference, ack).
- **Other:** `interaction` (IMS: New · Work in progress · Closed), `incident_model`, `priority_matrix` (versioned), `resolution_code`, `cause_code`, `custody_log` (P2); engine tables `journal_entry`, `audit_log`, `time_entry`, `checklist_item`, `sla_instance`, `survey_response`, `ai_suggestion`, `ai_invocation`.
- **Relationships:** incident ↔ problem (M:N `problem_incident`, primary `problem_id`), → change (caused_by, fix), ↔ alert (`alert_incident`), ↔ outage, → known_error, parent/child, merged_into, interaction → incident, incident ↔ request conversion, pir 1:1 primary incident, pir → `corrective_action`.
- **Access scoping:** own = caller, affected user, opened_by, watch list, participants; group = assignment group and owner group (+ parents); unit = company, org-unit path, location path snapshotted at create; domain = `domain_id` (MSP); workspace = `workspace_id`; restrictions = security level, restricted group, security flag; MI comms use a service audience share without opening the record.

### KPIs
- **Detection:** MTTD = avg(detected_at − first_symptom_at); % detected by monitoring = count(source = monitoring) / count(all); % resolved before user report.
- **Response:** MTTA = avg(first ack or acceptance − created); first response time (business time, median and p90); time to diagnosis acceptance = avg(accepted_at − detected_at); diagnosis time = avg(diag_end − diag_start).
- **Resolution:** MTTR/MTRS = avg(resolved_at − created_at − paused) per priority (median, p90; first vs final resolution); FCR = resolved at first contact without handoff ÷ FCR-eligible (goal 70–80%); FLR = resolved by L1 ÷ total; first-time fix = resolved and not reopened in N days ÷ resolved; reopen rate = reopened within 7–14 days ÷ resolved (< 5%).
- **Flow:** reassignments per incident = Σ reassignments ÷ count; ping-pong share = count(reassign > 2) ÷ count (mean < 1.5 hops); functional and hierarchical escalation rates; % waiting = Σ waiting time ÷ Σ handling time; backlog; net flow = created − resolved; ageing buckets (0–1, 1–3, 3–7, 7–30, > 30 days); % older than target.
- **SLA and experience:** SLA compliance = met ÷ (met + breached) per SLA instance; at-risk share (≥ 75% elapsed); CSAT = avg or % satisfied; lost time per incident; volume heatmap (weekday × hour) for staffing.
- **Quality:** KCS link rate = resolved with KB/KE link ÷ resolved; % resolved with models; % auto-resolved; AI resolution rate = closed by AI ÷ resolved; AI suggestion acceptance = accepted ÷ shown; repeat incidents (same CI + category within 30 days); change-caused % = caused_by_change set ÷ total; CI-populated rate (≥ 90%); cost per incident = Σ(effort × rate) ÷ count.
- **Major incidents:** MI count and share; MTTR(MI); time to declare = mi_accepted_at − detected_at; time to first stakeholder update; cadence adherence = updates on time ÷ updates due; PIR within 5 business days %; PIR action closure rate; regulatory deadline compliance = on-time submissions ÷ required.
- **Delivery link (→ devops):** failed deployment recovery time = avg(restored_at − failure_at) for change-caused incidents.

### Data model
- **`problem`** (PRB, extends `task`): New (new) · Assess, Root Cause Analysis, Fix in Progress (active) · Pending + reason (awaiting vendor/change/info) (waiting) · Resolved (resolved) · Closed: fixed, risk accepted, duplicate (closed) · Canceled (canceled). Fields of PRB-001 plus `tech_debt_score`, `monitoring_until`, `confidentiality`.
- **`problem_task`** (PTASK; type general/rca): New · Work in progress · Closed · Canceled.
- **`known_error`** (KE): Draft (new) · Active, Fix scheduled, Assigned to vendor, No action planned (active) · Fixed (resolved) · Retired (closed) · Canceled; problem_id, symptoms, root_cause, workaround, effectiveness, review_at, kb_article_id, matched_incident_count.
- **`problem_candidate`** (PCN): New · Under review · Promoted (resolved) · Dismissed/Merged (closed); source rule/ml, cluster_run_id, score, members, label, draft_statement.
- **RCA:** `rca_analysis` (RCA: method, status), `rca_step` (seq, question, answer, evidence_refs, author, ai_suggested), `rca_hypothesis` (cause, evidence_refs, confidence, status).
- **Shared:** `corrective_action` (ACT: New · In progress · Blocked (waiting) · Done (closed) · Canceled; type, source_ref, owner, due_at, evidence), `lesson_learned` (LSN), `cluster_run`, `cluster_member`.
- **Links:** `problem_incident` (link type, linker, time), `problem_ci`, `problem_service`, `problem_change` (fix/caused_by), problem → `risk` on acceptance.
- **Access scoping:** own = coordinator, manager, watch list; group = assignment group (write) with agent-wide read; unit/domain = company, `domain_id`; workspace; restriction = confidentiality (security problems internal only; KE article audience never wider than the problem).

### KPIs
- Proactive share = proactive problems ÷ all; proactive-to-reactive ratio.
- Problem coverage = incidents linked to a problem ÷ incidents; MIs with a problem record (target 100%).
- Mean time to root cause = avg(rca_identified_at − registered_at) (≤ 30 days for P1/P2); mean time to KE = avg(ke_published_at − registered_at); time to permanent fix = fix_implemented_at − rca_identified_at.
- % KEs with workaround; % KEs published to the KB; % problems resolved within target; problems closed via change ÷ closed.
- Recurrence rate = incidents linked after fix_deployed_at within N days ÷ linked incidents; incident reduction = (incidents N days before fix − after) ÷ before, normalised by CI population; recurring-incident rate = incidents linked to KEs ÷ incidents.
- Backlog: open problems and KEs by age; technical-debt index = Σ(active KE × incident volume or cost); CAPA closure rate and age.
- AI candidate precision = promoted ÷ reviewed candidates.

### Beyond the market
- **Persian- and mixed-language clustering:** Persian normalisation and multilingual embeddings so Persian, English and Finglish tickets about one fault fall into one cluster.
- **Evidence-cited RCA:** every AI claim cites an incident, change or log; "insufficient evidence" instead of guesses; a blameless-language check for Persian text.
- **Iran-specific external causes:** scheduled power cuts per site, national internet disruptions, ISP and domestic-cloud outages and sanctions-driven vendor cut-offs are tagged as external causes so they do not create false problems, and are reported separately.
- **Technical debt in Rial:** cost of related incidents and workarounds shown in Rial/Toman with the tenant's rates.
- **KEDB offline:** published KEs and workarounds in Persian are part of the Windows offline replica.

### Data model
- **`event`** (no prefix; append-only, day-partitioned, short retention): integration_id, source, node, resource, metric/check, severity, message, fingerprint, payload (restricted), occurred_at, received_at, decision (policy ids + versions), alert_id.
- **`alert`** (ALR + rolling short id): Open (new) · Acknowledged, Flapping (active) · Snoozed, In maintenance (waiting) · Cleared (resolved) · Closed (closed) · Suppressed/Ignored (canceled); fingerprint, message, source, integration_id, ci_id, service_id, metric, severity, priority, tags, extra properties, count, first/last seen, severity history, owner, team_id, responders, acked/closed by and at, noise_label + confidence, group_id, closed_by_ai, reopened_at.
- **`alert_group`** (SIT, situation): Open (new) · Active · Resolved · Closed; AI title/summary, priority, probable_causes, grouping reason (rule/ML); `alert_group_member`, `alert_incident`.
- **Config:** `integration` (key secret, mapping, severity map, incoming/outgoing rules), `event_policy`, `alert_policy`, `notification_policy`, `routing_rule` (all ordered and versioned), `monitoring_plan`, `heartbeat` (Pending · Responsive · Unresponsive · Off), `relay_agent` (status, version, last_seen).
- **`maintenance_window`** (MNT, shared with change): Scheduled (new) · Active · Completed (closed) · Canceled; scope CIs/services/integrations/team, recurrence, change_id.
- **`runbook`** (versioned) and **`runbook_run`** (RUN): Queued (new) · Awaiting approval (waiting) · Running (active) · Succeeded (resolved) · Failed (closed) · Canceled.
- **On-call:** `ops_team`, `oncall_schedule`, `oncall_rotation`, `oncall_override`, `oncall_forwarding`, `oncall_interval` (materialised final layer with planned and actual person), `escalation_policy`, `escalation_level`, `contact_method` (value field-secured, verified), `notification_rule`, **`page`** (PG: Queued (new) · Sent/Delivered (active) · Acknowledged (resolved) · Timed out/Failed (closed) · Canceled; channel, provider message id, failure reason).
- **Health:** `service_health` (service, status, score, computed_at); P2 `metric_series`, `anomaly`.
- **Relationships:** event N:1 alert; alert N:1 group; alert ↔ incident M:N; alert → CI/service; maintenance_window → change; runbook_run → alert/incident; page → alert/incident and escalation level; schedule → team.
- **Access scoping:** group = owning ops team and service owner group; unit/domain = company, location and support-group anchors copied from the CI; ops roles per team; field classes `ops_sensitive` (payload) and personal (contacts); MSP `domain_id`.

### KPIs
- Compression = raw events ÷ alerts; alert-to-incident ratio = alerts ÷ incidents created from alerts.
- Noise reduction % = 1 − alerts notified ÷ raw events; false-positive rate = alerts closed "no action" ÷ alerts; actionable-page rate = pages leading to action ÷ pages (goal ≈ one incident per page).
- MTTD = avg(first alert − impact start); alert MTTA = avg(ack − created); alert MTTR = avg(closed − created).
- % incidents created by monitoring vs reported by users (goal: majority by monitoring); % critical CIs monitored = monitored critical CIs ÷ critical CIs.
- Auto-remediation rate = alerts resolved by runbook ÷ eligible alerts; runbook success rate; closed-by-AI share; AI grouping correction rate = human splits/merges ÷ groups.
- On-call health: pages per shift; after-hours pages per person per week; ack within target %; escalations past level 1 %; notification delivery success = delivered ÷ sent; on-call time per person and its spread (fairness); heartbeat uptime.

### Beyond the market
- **Connectors for the Iranian stack first:** Zabbix, PRTG, Nagios, Prometheus/Grafana and domestic clouds (e.g. ArvanCloud) through an outbound-only relay that also works in air-gapped networks.
- **Paging that works in Iran:** domestic SMS gateways (e.g. Kavenegar, Ghasedak, SMS.ir, Magfa) and Persian TTS voice calls through local providers or Asterisk/Issabel, two-way SMS ack, and Bale/Eitaa bots with inline ack/escalate buttons, without Twilio or Slack.
- **Iranian calendars in on-call:** Saturday-start weeks, half-day Thursdays, Friday weekends, Nowruz and lunar holidays, Ramadan hours; holiday-shift fairness counted separately.
- **External-dependency signals:** national internet connectivity and the published power-cut schedule per site are ingested as events or maintenance windows, so alerts they explain are grouped and not paged.
- **Windows tray pager** that rings when the browser is closed and buffers acknowledgements offline.
- **All AIOps models run locally** (embeddings, clustering, forecasting, LLM narration) with no SaaS dependency.

- **CON-008 Service subscriptions and proactive notice** (اشتراک سرویس و اطلاع‌رسانی پیش‌دستانه) · P1 — Users, groups, departments, locations and customers subscribe to services; outages and maintenance reach them before they call; proactive cases for affected customers. **Src:** SN subscriptions, SN CSM proactive operations, ITIL4. **Impl:** subscriptions as audiences.

- **CON-010 Reliability gap detection** (کشف شکاف قابلیت اطمینان) · P2 · AI — From post-incident data, AI finds missing SLOs or synthetic checks and opens reliability tasks. **Src:** SN Reliability Domain Agent. **Impl:** PIR + monitoring-coverage analysis.
- **CON-011 Availability risk watchlist** (فهرست پایش ریسک دسترس‌پذیری) · P1 · AI — Risk score per service from recent incident rate, open problems without workaround, risky changes in the next 7 days, SPOFs and capacity risks; AI writes a weekly continuity watchlist. **Src:** ai.md, Atlassian Prevention Center, BigPanda, BMC Change Risk Advisor. **Impl:** nightly scoring + AI narrative.

#### Capacity and performance
- **CON-012 Capacity thresholds and monitoring** (آستانه و پایش ظرفیت) · P1 — Capacity records per CI/service (human, technical, information, financial), utilisation vs warning/exception thresholds from monitoring, linked capacity incidents. **Src:** ISO20k §8.4.3, FitSM PR5, COBIT BAI04, ISO27001 A.8.6, ITIL4. **Impl:** `capacity_record` updated from events/metrics.
- **CON-013 Capacity plan** (برنامهٔ ظرفیت) · P1 — Owned plan with current and forecast capacity from demand (patterns of business activity), effects of service-level and continuity requirements, timescales, thresholds, upgrade costs and plan items; periodic review. **Src:** ISO20k, FitSM PR5, COBIT BAI04, ITIL4. **Impl:** `capacity_plan` + items.
- **CON-014 Capacity forecasting and time-to-exhaustion** (پیش‌بینی ظرفیت و زمان اتمام) · P1 · AI — Holt-Winters or robust regression per metric; exhaustion = first time the upper 80% interval crosses capacity; risk raised when that is sooner than procurement lead time; monthly back-test (MAPE) with seasonal-naive fallback. **Src:** BMC Continuous Optimization, Splunk ITSI, Dynatrace, SDP OpManager, SN. **Impl:** forecasting job on metric snapshots.
- **CON-015 What-if capacity modelling** (مدل‌سازی «اگر-آنگاه» ظرفیت) · P2 · AI — Simulates business growth, events, migrations and deployments against capacity with bottleneck charts. **Src:** BMC Continuous Optimization. **Impl:** driver-based model.
- **CON-016 Rightsizing and idle resources** (بهینه‌سازی اندازهٔ منابع) · P2 — Over/under-allocated VMs, cloud and Kubernetes resources with cost comparison. **Src:** BMC, SN Cloud Cost, FS Device42. **Impl:** with financial/ITAM (→ financial).
- **CON-017 Performance and overload policies** (سیاست کارایی و اضافه‌بار) · P2 — Baselines, load-test records, headroom rule (N+2 for critical services), load-shedding and graceful-degradation policies. **Src:** SRE. **Impl:** policy records per service.

#### Business continuity and disaster recovery
- **CON-018 Continuity requirements on services** (الزامات تداوم روی سرویس‌ها) · P0 — Each service/CI carries criticality tier, RTO, RPO, MTPD, MBCO, DR tier and the covering plan; validation RTO ≤ MTPD. **Src:** ITIL4, ISO22301, ISO27031, ISO20k §8.7.2. **Impl:** fields on service/CI classes (→ service_portfolio, cmdb).
- **CON-019 BCMS governance** (نظام مدیریت تداوم کسب‌وکار) · P1 — BC policy, scope, objectives, roles, competence, documented information, internal audit, management review and the climate-change consideration, with evidence. **Src:** ISO22301 + Amd 1:2024, ISO22313, COBIT DSS04. **Impl:** governance records + document control.
- **CON-020 Business impact analysis (BIA)** (تحلیل اثر کسب‌وکار) · P1 — Questionnaire BIA per service, process and activity: impact ratings by category (financial, operational, regulatory, reputational, customer, safety) over time buckets (1 h, 4 h, 1 d, 3 d, 1 w); MTPD, RTO, RPO, MBCO; vital business functions; dependencies on people, sites, CIs, suppliers and data; approval and periodic review; RTO proposed as the first bucket over tolerance. **Src:** ISO22301 §8.2.2, ISO/TS 22317, ISO27031, ITIL4, SN BCM. **Impl:** `bia`, `bia_impact`, `bia_dependency`.
- **CON-021 RTO/RPO inheritance and ICT readiness** (وراثت RTO/RPO و آمادگی فاوا) · P1 — Requirements flow from activities down the CMDB to ICT services and CIs (required RTO = min of dependents); CIs whose DR tier or tested recovery time is slower are flagged; RPO checked against backup intervals. **Src:** ISO27031 IRBC, standards, SN BCM. **Impl:** graph job writes `required_rto` per CI.
- **CON-022 Continuity risk assessment** (ارزیابی ریسک تداوم) · P1 — Disruption risks identified, analysed and treated at planned intervals on the shared ISO 31000 risk engine. **Src:** ISO22301 §8.2.3, ISO20k §8.7.2, FitSM PR4.2. **Impl:** risk register (→ security).
- **CON-023 BC strategies and solutions** (راهبرد و راهکار تداوم) · P1 — Options per activity (alternate site, remote work, manual workaround, supplier diversification, active-active, hot/warm/cold standby, cloud DR) with cost, capability, RTO fit, rationale and resources. **Src:** ISO22301 §8.3, ITIL4. **Impl:** `bc_strategy` linked to BIA.
- **CON-024 Continuity and DR plans** (طرح‌های تداوم و بازیابی از فاجعه) · P1 — Versioned, approved plans per service, site or scenario: invocation criteria and responsibilities, response structure, recovery teams and call trees, recovery steps with RTO offsets, availability targets while invoked, contacts and return-to-normal; periodic review. **Src:** ISO22301 §8.4, ISO20k §8.7.2, ITIL4, SN BCM, EU DORA Art.11. **Impl:** `continuity_plan` + `plan_step` templates.
- **CON-025 Offline continuity kit** (کیت آفلاین تداوم) · P1 — Plans, call trees, contacts, runbooks and KB available offline in the Windows app (encrypted, per holder) and as watermarked PDFs; the version given to each holder is recorded so stale copies can be recalled. **Src:** ISO22301 (plans usable when sites are unavailable), ISO20k, access.md. **Impl:** offline sync buckets + `plan_distribution`.
- **CON-026 Exercise and test programme** (برنامهٔ تمرین و مانور) · P1 — Annual and post-change tests: tabletop, walkthrough, simulation, DR failover, full; scenario, objectives tied to RTO/RPO, participants; plan steps cloned into the exercise to time real recovery; findings → CAPA, problems or changes; post-exercise report; on-call readiness drills. **Src:** ISO22301 §8.5, ISO20k, COBIT DSS04.04, EU DORA Art.11/24–25, SRE DiRT. **Impl:** `exercise`, `exercise_step`.
- **CON-027 AI exercise scenarios** (سناریوسازی هوشمند مانور) · P2 · AI — Generates tabletop scenarios and timed injects from BIA, risks and past incidents. **Src:** standards. **Impl:** AI skill.
- **CON-028 Invocation and crisis management** (فعال‌سازی طرح و مدیریت بحران) · P1 — Declare a disaster or crisis against criteria (distinct from an MI); invocation record (who, when, criteria met); crisis team roster; activating a plan creates recovery tasks with RTO timers; mass notification with acknowledgement; status board and map of affected sites; decision and communications logs; stand-down and post-resumption review. **Src:** ISO22301 §8.4, ITIL4, COBIT DSS04.03/08, NIST CSF RC.RP, SN crisis management. **Impl:** `crisis_event` + `crisis_task` + paging.
- **CON-029 Emergency notification and safety check-in** (اعلان اضطراری و اعلام سلامت کارکنان) · P2 — Emergency outreach by location with employee check-in answers and site closures. **Src:** SN Emergency Outreach. **Impl:** mass notification + response capture.
- **CON-030 Backup and restore assurance** (اطمینان از پشتیبان‌گیری و بازیابی) · P1 — Backup policy per system (frequency, retention, copies, segregation, encryption), job monitoring (failures open incidents), restore tests with evidence and RPO checks. **Src:** ISO27001 A.8.13–14, COBIT DSS04.07, EU DORA Art.12. **Impl:** `backup_policy`, `restore_test`.
- **CON-031 Security during disruption** (امنیت در زمان اختلال) · P2 — Shows how controls stay at the planned level during disruption and records temporary controls. **Src:** ISO27001 A.5.29. **Impl:** plan section + control links.
- **CON-032 Operational resilience and regulatory testing** (تاب‌آوری عملیاتی و آزمون‌های قانونی) · P2 — Important business services with impact tolerances, scenario tests and resilience dashboards; EU DORA continuity duties (yearly tests, TLPT tracking) and local regulators as configurable checklists. **Src:** SN Operational Resilience, EU DORA Art.11–12, 24–27, UK FCA/PRA. **Impl:** checklists (→ security).
- **CON-033 AI plan drafting and gap analysis** (پیش‌نویس هوشمند طرح و تحلیل شکاف) · P1 · AI — Drafts BIA and DR plan sections from CMDB facts, contacts, runbooks and incident history with citations and explicit TODOs (never guessed); owners attest; checks plans against ISO 22301/27031 and local checklists. **Src:** standards, ai.md, GRC vendors. **Impl:** template-driven AI skill.
- **CON-034 Expiry-driven outage prevention** (پیشگیری از قطعی ناشی از انقضا) · P2 — Certificates, domains and licences nearing expiry open renewal tasks in time. **Src:** SN Certificate Inventory. **Impl:** expiry dates on CIs (→ cmdb, itam).
- **CON-035 Break-glass access and degraded mode** (دسترسی اضطراری و حالت تنزل‌یافته) · P1 — Tenant break-glass accounts independent of SSO (local FIDO2), sealed, alerting and tested quarterly; when the IdP is down, sessions may be extended under an explicit, audited policy. **Src:** access.md (Entra reference). **Impl:** auth service + audit.
- **CON-036 ITSM platform resilience** (تاب‌آوری خود سامانه) · P1 — HA deployment, failover, online backups, latency checks and restore drills for our own installation; platform status shown on the status page. **Src:** SDP failover/HA, Atlassian SLAs. **Impl:** deployment guide + health endpoints.
- **CON-037 Continuity reporting and evidence** (گزارش و شواهد تداوم) · P1 — BIA coverage, plan currency, exercise completion, RTO/RPO achievement, open actions, backup success and restore-test pass rate; audit evidence pack export. **Src:** ISO22301 §9, COBIT DSS04/MEA01. **Impl:** KPI layer + export.

### Data model
- **`outage`** (OUT): Proposed (new) · Ongoing (active) · Ended (resolved) · Validated (closed) · Canceled; type outage/degradation/planned, begin, end, impact_pct, service, offering, CI, cause, task links, customer_minutes.
- **Availability:** `availability_snapshot` (service, period, availability_pct, downtime_min, failures, mtbf, mtrs, target, met), `availability_plan`, `service_subscription`.
- **Status pages:** `status_page`, `status_component`, `status_post` (SPOST: Draft (new) · Awaiting approval (waiting) · Published/Updating (active) · Resolved · Closed), `status_subscriber`.
- **Capacity:** `capacity_record` (CI/service, metric, capacity, thresholds, utilisation, forecast_exhaustion_at, confidence), `capacity_plan` (CAPP: Draft · In review · Approved (resolved) · Superseded (closed)) + items.
- **BIA:** `bia` (BIA: Draft (new) · In assessment/review (active) · Approved (resolved) · Superseded (closed) · Canceled), `bia_impact` (category, bucket, rating), `bia_dependency` (type, ref, required_rto, required_rpo), `business_activity` (criticality, owner, org unit).
- **Plans:** `bc_strategy`, `continuity_plan` (BCP: Draft · In review · Approved/Published (resolved) · Retired (closed); version), `plan_step` (seq, role, action, rto_offset), `call_tree`, `plan_distribution` (holder, version, delivered, acknowledged, recalled).
- **Exercises and crises:** `exercise` (EXR: Planned (new) · In progress (active) · Results recorded (resolved) · Closed · Canceled), `exercise_step` (planned vs actual times), `exercise_finding`; `crisis_event` (CRS: Declared (new) · Invoked/Recovering (active) · Stood down (resolved) · Reviewed (closed) · False alarm (canceled)), `crisis_task` (rto_due_at).
- **Backup:** `backup_policy`, `restore_test` (RST: Planned · Running · Passed/Failed (resolved) · Closed); `bcms_review` (audit/management review).
- **Fields on service/CI:** criticality_tier, rto, rpo, mtpd, mbco, dr_tier, required_rto (computed), tested_recovery_time.
- **Relationships:** outage ↔ incident/change/alert/problem and → service/CI; availability_snapshot ← outages + commitments (slm); bia → services/activities; bia_dependency → CI/supplier/site/person; plan → services/sites; exercise → plan; finding → corrective_action/problem/change; crisis_event → plans, incidents, sites; restore_test → backup_policy → CI.
- **Access scoping:** own = plan owner, service owner, BIA respondent; group = continuity team and recovery teams; unit = org unit of the business activity; location = site; field class personal for contacts and call trees; offline buckets per plan holder; public status pages show published posts only.

### KPIs
- Availability % = (agreed service time − downtime) ÷ agreed service time × 100 (monthly budgets: 99.9% ≈ 43.8 min, 99.95% ≈ 21.9 min, 99.99% ≈ 4.4 min); % services meeting availability targets; composite availability.
- MTBF = uptime ÷ failures; MTRS = downtime ÷ failures; MTBSI = MTBF + MTRS; outage minutes; customer-minutes impacted = Σ(duration × affected users); SPOFs on critical services.
- Capacity: % CIs above threshold; headroom = 1 − peak utilisation ÷ capacity; days to exhaustion; forecast accuracy (MAPE); capacity-related incidents; performance SLA attainment.
- Continuity: BIA coverage = critical services with a current BIA ÷ critical services; plan currency = plans reviewed in cycle ÷ plans; % critical services with a plan tested in 12 months; exercise completion vs programme; RTO achievement = tests with actual recovery ≤ RTO ÷ tests; RPO achievement = tests with data loss ≤ RPO ÷ tests; backup success rate; restore-test pass rate; open continuity actions and age; actual vs expected loss in invocations; awareness/training coverage.
- Reliability (→ slm): error budget remaining = allowed bad events − bad events; burn rate.

### Beyond the market
- **Iran scenario library:** international internet cut-off, sanctions-driven SaaS/vendor cut-off, scheduled rolling power cuts, generator fuel shortage, heat or pollution closures, earthquake (Tehran fault lines) and currency shocks that stretch procurement lead time, each with ready BIA prompts and plan templates.
- **Power-cut aware continuity:** the published outage schedule per site is checked against UPS/generator runtime and plan RTOs, with warnings before the cut.
- **Local frameworks:** Persian BCP templates aligned to passive-defence (پدافند غیرعامل) and Afta expectations alongside ISO 22301; Jalali exercise calendar.
- **Offline continuity kit** on the Windows app with encrypted plans, call trees, runbooks and KB, version recall and local break-glass login, usable with no network at all.
- **Data sovereignty:** DR targets in domestic data centres, RPO checked against real backup logs, fully air-gapped operation possible.
- **AI in Persian:** BIA and DR plan drafts and tabletop scenarios generated in Persian with citations to CMDB facts; nothing leaves the tenant when a local model is used.

## Deliberately excluded
- **Product-specific legacy and migration items** — JSM legacy Opsgenie escalation, SN Problem Management Migration Utility, Agent Workspace → SOW migration, deprecated SN "Suggested steps" and alert clustering definitions: tied to one vendor's history; their current replacements are in the catalog.
- **Vendor metering schemes** (Rovo credits, Freddy sessions, "assists") — replaced by tenant-level AI usage and cost governance in the AI module.
- **A full observability platform** (APM trace store, large-scale log management, a MetricBase/ITSI-class metric database) — out of ITSM scope; we ingest signals from these tools and keep only light baselines (EVT-020 to EVT-022, P2).
- **Endpoint and RMM management** (patching, software deployment, device policies such as Ivanti bots, Atera, Intune/Jamf consoles) — not ITSM core; reached through integrations (INC-078).
- **Our own conferencing media server** (JSM in-app calls with ≤ 50 participants) — we link to self-hosted Jitsi/BigBlueButton or Skyroom and external tools instead (INC-052).
- **Autonomous desktop agents and AI browser/RPA agents** (SN Project Arc, AI web agent) — high security risk and unrelated to these modules.
- **Cloud vendor simulators and reserved-instance advice** (BMC Cloud Migration Simulator, RI recommendations) — FinOps/ITAM topic, not continuity.
- **Twilio/Vonage as built-in paging providers** — unusable for the Iranian market; the provider interface still allows them abroad.
- **Password-reset UI action and walk-up queue** — belong to the request and portal modules.
- **Field-service dispatch** — separate module.

## Engine requirements
- **Metadata records:** tables extending `task`, field types incl. references, M:N links with link types, choice lists with reason codes, per-state required fields and transition guards, state categories (new/active/waiting/resolved/closed/canceled), immutable terminal states, numbering prefixes (INC, ITASK, PIR, REG, PRB, PTASK, KE, PCN, RCA, ACT, ALR, SIT, MNT, RUN, PG, OUT, BIA, BCP, EXR, CRS).
- **Relationship operations:** parent/child cascades, merge/split with redirect pointers, duplicate re-pointing, typed links (caused_by, fix, resolved_by) and counter roll-ups.
- **Versioned lookup matrices** (priority) and versioned, ordered rule sets with first-match semantics, simulation on historical data and a decision log carrying the rule version.
- **Business-time service:** Jalali calendar, Iranian solar and lunar holidays, ad-hoc closure days with recalculation of open deadlines, Ramadan hours, time zones including Iran's fixed UTC+03:30 (no DST after 2022); reused by SLA, auto-close, reminders, on-call and availability.
- **SLA engine:** several timers per record (response, resolution, OLA, UC, regulatory clocks), pause by reason, at-risk thresholds, breach actions, server-side deadlines pushed to clients.
- **Flows and jobs:** event-, time- and condition-triggered flows with waits, loops and parallel branches; durable timers for escalations; scheduled jobs (auto-close, reminders, inactivity, nightly clustering, forecasting); lanes for llm/external/system work.
- **Notifications:** templates with Persian/Jalali placeholders; channels email, SMS gateways, voice/TTS, push, Windows tray, Bale/Eitaa/Telegram, Teams/Slack; per-user rules, aggregation windows, delivery receipts, two-way replies (ack via SMS/chat) and audience-only recipients (stakeholders, subscribers).
- **Journal and audit:** public/internal/restricted entries, back-dating, key-event flags, field-diff audit with actor types (human, rule, integration, AI agent), hash-chained privileged actions.
- **Access model:** own/group/unit/domain/workspace scopes, participant keys, restrictions (security level, restricted group) that outrank grants, snapshotted anchors, field classes (ops_sensitive, personal), audience shares for broadcasts, AI that never exceeds the user.
- **Ingestion pipeline:** authenticated high-volume endpoint, idempotency and rate limits, append-only partitioned tables with retention tiers, atomic dedup upserts, streaming correlation.
- **CMDB graph API:** upstream/downstream traversal, k-hop neighbourhoods, impact rules with redundancy, SPOF detection, requirement inheritance (RTO/RPO).
- **On-prem relay agent:** outbound-only job polling, pull connectors, sandboxed script/runbook execution with approvals, Git-sourced scripts, leases and heartbeats.
- **On-call engine:** layered schedule intervals with overrides and forwarding, materialised final layer and history, escalation state machines, gap detection.
- **Collaboration adapters:** chat channel/bridge creation, message mirroring into the journal, ChatOps commands with signed callbacks, presence/collision over WebSocket.
- **External sync (e-bonding):** correlation ids, field ownership, outbound queue with retries, reconciliation.
- **AI platform:** skill framework (input spec, prompt version, output JSON schema, triggers, roles), `ai_suggestion` with confidence and auto-apply thresholds, agents running as a user with tool allowlists and autonomy levels, provenance on every write, RAG with ACL filtering and Persian normalisation, embeddings and clustering jobs (`cluster_run`), similarity search, local-model support, evaluation and acceptance metrics.
- **Analytics:** time-in-state facts (`fact_ticket_state_interval`), KPI definitions with formulas and clocks, snapshots, dashboards; forecasting library (Holt-Winters, regression) and a light time-series store.
- **Documents and publishing:** PDF/DOCX export with Persian fonts and RTL, public status site with caching, custom domains and subscriptions.
- **Offline replica:** permission-exact sync buckets for the Windows app (incidents, KEs, plans, call trees, runbooks), write queue and conflict handling.
- **Surveys, time tracking, checklists, templates/macros and form UI policies** as shared engine components.
- **APIs and MCP:** REST for every table, config export/import as code, governed MCP tools for outside agents.
