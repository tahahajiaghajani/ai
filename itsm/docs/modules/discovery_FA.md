# منبع‌های داده: دارایی‌ها و وضعیت از ابزارهای پایش و کشف

«منبع‌های داده» پیکربندی‌ها و دارایی‌ها و وضعیت آن‌ها را از ابزارهایی که بانک امروز دارد به کاریز می‌آورد، در کنار ثبت دستی: **Zabbix**، **PRTG**، **VMware vCenter**، هر ابزاری با **API از نوع REST/JSON**، ابزارهایی که خودشان داده را با **API ارسال** می‌فرستند، و **فایل CSV یا JSON** (مانند خروجی سوئیچ خودپردازها). هر چیزی که ابزار گزارش می‌کند با موتور آشتی پایگاه پیکربندی به پیکربندی موجود پیوند می‌خورد یا ساخته می‌شود؛ آنچه روشن نیست به «صف آشتی» می‌رود و وضعیت هر دستگاه در «وضعیت پایش» دیده می‌شود. این راهنما برای تیم فناوری بانک است.

در منو: فضای **پیکربندی**، گروه «منبع‌های داده» ← «منبع‌های داده»، «صف آشتی»، «وضعیت پایش» و «منبع داده تازه». در صفحهٔ هر پیکربندی و دارایی پنل «منبع‌ها و وضعیت پایش» هست و صفحهٔ «ناوگان خودپرداز» به «وضعیت پایش» خودپردازها پیوند دارد.

کجا اجرا می‌شود: در **نسخهٔ سرور** و **نسخهٔ وب**. برنامهٔ ویندوز منبع داده اجرا نمی‌کند و آن را نشان نمی‌دهد. نسخهٔ وب فقط به ابزاری با نشانی عمومی وصل می‌شود؛ ابزار درون شبکهٔ بانک را با نسخهٔ سرور یا با API ارسال وصل کنید.

چه کسی چه می‌کند:
- **مدیر پیکربندی** (مدیر حوزهٔ پایگاه پیکربندی) منبع داده می‌سازد و تنظیم می‌کند. تغییر کلید، «میزبان‌های مجاز دیگر»، «اتصال بدون رمزنگاری»، «معتبرتر از ویرایش دستی»، «سیاست ساخت»، میزبان نشانی و علامت خودکار «مفقود» تأیید دوبارهٔ هویت می‌خواهد و در سابقهٔ منبع ثبت می‌شود.
- **«مسئول»** هر منبع فقط «فعال»، زمان‌بندی و شرح را تغییر می‌دهد و «اجرای اکنون» و «لغو گذر» دارد.
- خوانندگان پایگاه پیکربندی منبع‌ها و «صف آشتی» را می‌بینند. «وضعیت پایش» را خوانندگان پایگاه پیکربندی و دارایی‌ها می‌بینند؛ مسئول اموال یک شعبه فقط دارایی‌های شعبهٔ خود را، بی‌نام ابزارها.
- «ساخت دارایی برای دستگاه‌های تازه» را فقط **مدیر دارایی** روشن و خاموش می‌کند.

## افزودن منبع داده

«منبع داده تازه» پنج گام دارد:
1. **ابزار:** نوع منبع را برگزینید (پایش: Zabbix و PRTG؛ مجازی‌سازی: VMware vCenter؛ خودپردازها و فایل‌ها: فایل CSV یا JSON؛ ورود عمومی: REST/JSON عمومی و «ارسال از ابزار (API)»).
2. **اتصال:** «نشانی ابزار»، «روش ورود» و «کلید یا گذرواژه»؛ سپس «آزمودن اتصال» که نسخهٔ ابزار، حساب و هشدارهای دسترسی را نشان می‌دهد.
3. **چه بیاید:** «فهرست و مشخصات»، «وضعیت پایش» و «مشکل‌ها و هشدارها»؛ گزینه‌های هر ابزار؛ «سیاست ساخت» (ساخت و به‌روزرسانی، ساخت پس از بررسی، یا فقط به‌روزرسانی موجودها) و «کلاس پیش‌فرض».
4. **پیش‌نمایش:** نخستین موردهای ابزار با آنچه بر سرشان می‌آید (ساخته می‌شود، به‌روز می‌شود، بی‌تغییر، تکراری، بی‌همتا، کنار گذاشته می‌شود، خطا)، بی‌آنکه چیزی ذخیره شود. «نگاشت» مسیر هر فیلد را در پاسخ ابزار تغییر می‌دهد و پیش‌نمایش دوباره اجرا می‌شود.
5. **خلاصه** ← «ذخیره و اجرای نخست».

### شبکه، گواهی و کلید

- **نسخهٔ سرور در شبکهٔ بسته** فقط به میزبان‌های فهرست مجاز وصل می‌شود. برای فرستادن کلید، **نام دقیق** میزبان ابزار باید در فهرست باشد (الگو یا بازهٔ IP کافی نیست): `karizctl allow add zabbix.bank.local`، یا «مدیریت سامانه ← سلامت سرور» ([`SERVER_FA.md`](../SERVER_FA.md) بخش ۱۲).
- نام دیگر همان ابزار، مثلاً میزبان رابط وب برای پیوندها، در «میزبان‌های مجاز دیگر» می‌آید. کاریز به نشانی دیگری هدایت نمی‌شود و به خود سرور یا پایگاه داده‌اش وصل نمی‌شود.
- **گواهی:** نسخهٔ سرور به CA بانک که در مخزن گواهی ویندوز است اعتماد می‌کند. اگر گواهی ابزار از جای دیگری است، ریشه را در «گواهی ریشهٔ ابزار (PEM)» بگذارید. «اتصال بدون رمزنگاری (فقط شبکهٔ داخلی)» فقط در نسخهٔ سرور پذیرفته است.
- کلید فقط در «کلید یا گذرواژه» (و برای REST در سرآیندی که برمی‌گزینید) می‌رود، هرگز در نشانی. رمزشده نگه داشته می‌شود، به صفحه برنمی‌گردد و با عوض شدن میزبان نشانی پاک می‌شود.

| ابزار | حساب در ابزار | نشانی |
|---|---|---|
| Zabbix ۵٫۴ یا تازه‌تر | کاربری با نقش فقط‌خواندنی که دسترسی API دارد و در گروه کاربری‌ای است که گروه‌های میزبان لازم را می‌خواند؛ یک کلید API (API token) برای او | نشانی رابط وب Zabbix، مانند `https://zabbix.bank.local/zabbix` (یا `…/api_jsonrpc.php`) |
| PRTG ۲۲ یا تازه‌تر | کاربر فقط‌خواندنی با دسترسی خواندن به گروه‌های لازم؛ یک API key برای او | نشانی رابط وب PRTG |
| VMware vCenter ۷٫۰ U2 یا تازه‌تر | کاربری با نقش Read-only در سطح vCenter که به همهٔ فرزندان می‌رسد | نشانی vCenter |
| REST/JSON عمومی | کاربر یا کلید فقط‌خواندنی که همان فهرست را می‌خواند | نشانی پایهٔ API |
| فایل از نشانی وب | (اختیاری) کلید فقط‌خواندنی | نشانی HTTPS فایل |
| API ارسال | کاربر یکپارچه‌سازی در خود کاریز | ابزار به کاریز وصل می‌شود |

## ابزارها

### Zabbix
- **گزینه‌ها:** «گروه‌های میزبان» و «برچسب‌های میزبان» (خالی یعنی همهٔ میزبان‌هایی که کاربر API می‌بیند)، «کلاس بر پایهٔ گروه یا الگو» (مانند `{"Linux servers": "server"}`)، «میزبان در هر درخواست» (حداکثر ۵۰۰) و «نشانی رابط وب برای پیوندها».
- **می‌آورد:** میزبان‌ها با نشانی‌ها، گروه‌ها، الگوها و برچسب‌ها، و شمارهٔ سریال و سازنده از فهرست موجودی (inventory) Zabbix اگر روشن باشد؛ وضعیت؛ و مشکل‌های باز به مدیریت رویداد.
- **وضعیت:** پینگ ICMP بی‌پاسخ یا مشکل بازی با برچسب `scope: availability` ← «قطع»؛ عامل Zabbix یا SNMP بی‌پاسخ وقتی پینگ هم پاسخ نمی‌دهد ← «بی‌پاسخ» (با پینگ برقرار ← «هشدار»)؛ هر مشکل باز دیگر از شدت Warning به بالا ← «هشدار»؛ دورهٔ نگهداری Zabbix ← «در نگهداری»؛ میزبانی که پایشش خاموش است ← «نامعلوم». «آخرین تماس» آخرین پاسخ پینگ یا عامل است.

### PRTG Network Monitor
- کلید API در سرآیند `Authorization: Bearer` فرستاده می‌شود، هرگز در نشانی.
- **گزینه‌ها:** «حسگر دسترس‌پذیری» (پیش‌فرض `ping`)، «شناسهٔ گروه» (فقط دستگاه‌های زیر یک گروه یا کاوشگر)، «برچسب‌ها»، «کلاس بر پایهٔ گروه یا برچسب» و «اندازهٔ صفحه».
- **می‌آورد:** دستگاه‌ها با نام، نشانی، مکان و برچسب‌ها (PRTG شمارهٔ سریال و سخت‌افزار ندارد)؛ وضعیت؛ و حسگرهای Down، Warning و Unusual به‌عنوان مشکل.
- **وضعیت:** از حسگر دسترس‌پذیری، نه از وضعیت خود دستگاه در PRTG: Down ← «قطع»؛ مکث به سبب قطع بودن والد ← «بی‌پاسخ»؛ مکث (Paused) ← «در نگهداری»؛ Warning، Unusual یا Down (Partial)، یا حسگر دیگری Down یا Warning ← «هشدار»؛ Up ← «برقرار».

### VMware vCenter
- با نام کاربری و گذرواژه نشست می‌سازد (رابط `/api`).
- **گزینه‌ها:** «خوشه‌ها» (خالی یعنی همه)، «بازخوانی جزئیات هر ماشین (روز)» (پیش‌فرض ۷؛ ماشین تازه یا تغییرکرده همان دم خوانده می‌شود) و «شناسهٔ نمونهٔ vCenter برای پیوندها» (instanceUuid، برای پیوند هر مورد به vSphere Client).
- **می‌آورد:** خوشه‌ها، میزبان‌ها و ماشین‌های مجازی هر میزبان، با رابطهٔ «اجرا روی».
- **وضعیت:** میزبان جداشده یا بی‌پاسخ به vCenter ← «بی‌پاسخ»؛ میزبان خاموش یا در حالت آماده‌باش و ماشین مجازی خاموش یا معلق ← «خاموش» (هرگز «قطع»). فهرست میزبان‌های vCenter حالت نگهداری میزبان را نمی‌دهد؛ آن را با پنجرهٔ نگهداری مدیریت رویداد یا تغییرِ در حال اجرا ثبت کنید.

### REST/JSON عمومی
- برای هر ابزاری با API از نوع JSON (NetBox، سامانه‌های داخلی بانک…).
- **گزینه‌ها:** «مسیر فهرست» (مانند `/api/dcim/devices/`)، «مسیر آرایه در پاسخ» (مانند `results`)، «صفحه‌بندی» (بدون صفحه‌بندی، offset/limit، شمارهٔ صفحه، نشانگر، پیوند صفحهٔ بعد) با نام پارامترهایش، «پارامترهای ثابت درخواست» (کلید را این‌جا ننویسید) و «فهرست شدن یعنی تماس» (برای ابزاری که فقط دستگاه‌های روشن را فهرست می‌کند).
- **روش ورود:** بدون کلید، کلید API (در یکی از سرآیندهای `X-API-Key`، `X-Auth-Token`، `Api-Key`، `PRIVATE-TOKEN` یا `Authorization`) یا نام کاربری و گذرواژه.
- **نگاشت:** برای هر فیلد پیکربندی مسیری JSON در هر عنصر پاسخ؛ دست‌کم `external_id` و `name` (پیش‌فرض `$.id` و `$.name`). وضعیتی که رکورد می‌دهد فقط وقتی «قطع» است که بگوید خود دستگاه در دسترس نیست (ستونی که به «قطع یعنی خود دستگاه» نگاشته شده)؛ وگرنه «هشدار».

### API ارسال (ابزار داده را می‌فرستد)

برای ابزاری که خودش داده را می‌فرستد (یا ابزاری درون شبکه که نسخهٔ وب به آن نمی‌رسد):
1. «مرکز اتصال‌ها ← کاربران یکپارچه‌سازی ← کاربر یکپارچه‌سازی تازه» (مثلاً «سامانهٔ پایش مرکز داده»)؛ در «نقش‌ها و کلیدها» نقشی مانند «درخواست‌دهنده» بدهید و کلیدی بسازید که فقط «ساختن» در جدول «موارد منبع داده» را دارد. کلید فقط یک بار نشان داده می‌شود ([`integration_FA.md`](integration_FA.md)).
2. «منبع داده تازه ← ارسال از ابزار (API)» و در «کاربر یکپارچه‌سازیِ ارسال‌کننده» همان کاربر را بگذارید. «الگوی هشدار قطع» (اختیاری، مانند `^ping`) می‌گوید کدام هشدار یعنی خود دستگاه قطع است.
3. نشانی‌ها و نمونهٔ درخواست در زبانهٔ «دریافت هشدار» صفحهٔ منبع است. کلید در سرآیند `Authorization: Bearer …` یا `X-API-Key` می‌رود؛ سقف درخواست در دقیقه و فهرست IP مجاز کاربر یکپارچه‌سازی هم اعمال می‌شود (بیش از سقف: پاسخ ۴۲۹).

| درخواست | کار |
|---|---|
| `POST /api/v1/discovery/<شناسهٔ منبع>/batches` | دسته‌ای از رکوردها (قالب `kariz.discovery/1`): حداکثر ۵۰۰ رکورد و ۱ مگابایت. شناسهٔ دسته در سرآیند `Idempotency-Key` یا `batch_id` لازم است؛ پاسخ ۲۰۲ با `status_url`، و همان شناسه دوباره پاسخ ۲۰۰ با `duplicate` می‌گیرد و دوباره پردازش نمی‌شود. |
| `GET /api/v1/discovery/<شناسهٔ منبع>/batches/<شناسهٔ دسته>` | وضعیت دسته (در صف، در حال ثبت، در حال آشتی، انجام شد، ناموفق) با شمار ساخته، به‌روز، بی‌تغییر، بی‌همتا، تکراری و رد، و خطا و هشدار هر رکورد با شمارهٔ آن. |
| `POST /api/v1/discovery/<شناسهٔ منبع>/status` | فقط وضعیت، حداکثر ۱٬۰۰۰ مورد؛ تا ۲۰۰ مورد همان دم پاسخ می‌گیرد (۲۰۰) و بیشتر در صف می‌رود (۲۰۲). وضعیت هرگز چیزی نمی‌سازد. |

**تصویر کامل:** ابزاری که همهٔ دستگاه‌هایش را در چند دسته می‌فرستد `"snapshot": {"id": "…", "part": 1, "parts": 3}` می‌گذارد. وقتی همهٔ بخش‌ها تا ۲۴ ساعت برسند، موردی که در آن نیست «دیگر گزارش نمی‌شود» می‌شود؛ بی‌تصویر کامل، ارسال هیچ موردی را کنار نمی‌گذارد. **مشکل‌ها:** `"problems": {"complete": true, "items": [{"key": "…", "external_id": "…", "severity": "high", "message": "…"}]}` (حداکثر ۵٬۰۰۰)؛ با `complete` مشکلی که دیگر نیامده بسته می‌شود.

**فیلدهای رکورد:** `external_id` (شناسهٔ پایدار در ابزار، لازم)، `kind` (`device`، `vm`، `host`، `endpoint`، `network`، `atm`، `other`)، `class`، `name`، `hostname`، `fqdn`، `domain`، `ips`، `macs`، `serial_number`، `bios_uuid`، `terminal_id`، `manufacturer`، `model`، `os`، `os_version`، `sw_version`، `cpu_count`، `ram_mb`، `disk_gb`، `url`، `parent_external_id` (میزبان ماشین مجازی)، `last_contact_at` (آخرین تماس خود ابزار با دستگاه)، `status` (`state`، `availability`، `since`، `message`، `device_status`)، `reported` (`user`، `site`، `location`، `asset_tag`) و `attrs` (ویژگی‌های کلاس). فیلد ناشناخته کنار گذاشته می‌شود و هشدار می‌گیرد.

نمونهٔ دسته:

```bash
curl -X POST https://kariz.bank.local/api/v1/discovery/<شناسهٔ منبع>/batches \
  -H "Authorization: Bearer $KARIZ_KEY" -H "Content-Type: application/json" \
  -H "Idempotency-Key: dc1-2026-11-15-0700" \
  -d '{"schema": "kariz.discovery/1", "records": [
        {"external_id": "10452", "kind": "device", "class": "server", "name": "SRV-COREDB-01",
         "hostname": "srv-coredb-01", "domain": "bank.local", "ips": ["10.20.1.15"],
         "serial_number": "CZJ1234ABC", "manufacturer": "HPE", "model": "ProLiant DL380 Gen10",
         "os": "Windows Server 2022", "last_contact_at": "2026-11-15T06:40:00Z", "status": {"state": "up"}}]}'
```

نمونهٔ وضعیت (یک سرور با نام میزبان، یک خودپرداز با شناسهٔ پایانه):

```bash
curl -X POST https://kariz.bank.local/api/v1/discovery/<شناسهٔ منبع>/status \
  -H "Authorization: Bearer $KARIZ_KEY" -H "Content-Type: application/json" \
  -d '{"items": [
        {"match": {"hostname": "srv-coredb-01"}, "state": "down", "availability": true, "message": "ping reply missing"},
        {"match": {"terminal_id": "1021"}, "state": "up", "device_status": "out_of_cash", "since": "2026-11-15T06:35:00Z"}]}'
```

پاسخ: `{"state": "done", "updated": 2, "unmatched": 0, "items": [{"index": 0, "result": "updated", "target": {"table": "ci", "id": "…"}}, …]}`.
- هر مورد با `external_id` (موردی که ابزار پیش‌تر فرستاده) یا `match` (`terminal_id`، `serial_number`، `hostname`، `ip`) پیدا می‌شود؛ `state` یکی از `up`، `warning`، `down`، `unreachable`، `maintenance`، `off`، `unknown` است.
- `down` و `unreachable` فقط با `"availability": true` «قطع» و «بی‌پاسخ» نشان داده می‌شوند (یعنی خود دستگاه در دسترس نیست)؛ بی‌آن «هشدار»اند.
- **وضعیت خودپرداز** (`device_status`) فقط با شناسهٔ پایانه یا شمارهٔ سریال پذیرفته می‌شود، نه با نام میزبان یا IP (شبکهٔ شعبه‌ها نشانی تکراری دارد): `in_service`، `out_of_service`، `out_of_cash`، `offline` یا مقدار خود ابزار که «نگاشت وضعیت خودپرداز» منبع آن را برمی‌گرداند. منبع داده هرگز «در نگهداری» را نمی‌گذارد یا تغییر نمی‌دهد.

### فایل CSV یا JSON
- **محل فایل:** «نشانی وب» (HTTPS، حداکثر ۲۰ مگابایت) یا **«پوشهٔ ورودی سرور»** (فقط نسخهٔ سرور): `<پوشهٔ داده>\discovery\drop\<شناسهٔ منبع>\`، مثلاً `C:\ProgramData\Kariz\discovery\drop\…`؛ «آزمودن اتصال» مسیر دقیق را نشان می‌دهد. به حساب برون‌بری سوئیچ یا ابزار فقط اجازهٔ نوشتن در همین پوشه را بدهید.
- **نام فایل:** فقط حرف و رقم لاتین، `-`، `_` و `.`، حداکثر ۱۲۰ نویسه، با پسوند `.csv` یا `.json`؛ حداکثر ۵۰ مگابایت. فایلی که در ۳۰ ثانیهٔ گذشته تغییر کرده هنوز در حال نوشتن است و در گذر بعدی خوانده می‌شود. فایل خوانده‌شده ۷ روز در `processed` و فایل ردشده یا ناموفق با دلیلش (فایل `.txt`) ۳۰ روز در `failed` می‌ماند، زیر `<پوشهٔ داده>\discovery\kept\<شناسهٔ منبع>\`. حساب سرویس کاریز باید اجازهٔ تغییر (Modify) فایل‌های پوشه را داشته باشد تا آن‌ها را بردارد.
- **گزینه‌ها:** «قالب»، «جداکنندهٔ ستون‌ها» (خودکار، `,`، `;`، Tab، `|`)، «نویسه‌گذاری فایل» (UTF-8 یا Windows-1256؛ UTF-16 از نشانهٔ آغازش شناخته می‌شود)، «مسیر آرایه در JSON»، «ستون‌ها»، «گونهٔ موردها»، «هر فایل» (تصویر کامل که نیامده‌ها را «دیگر گزارش نمی‌شود» می‌کند، یا فقط تغییرها) و «آمدن در فایل یعنی تماس».
- **ستون‌ها** می‌گوید هر فیلد رکورد در کدام ستون CSV (یا کدام مسیر JSON) است. بی‌آن، ستون‌هایی که نام فیلد رکورد را دارند (`external_id`، `name`، `status.state`…) خوانده می‌شوند و هر عنصر JSON به قالب API ارسال.

نمونهٔ خروجی سوئیچ خودپردازها، با «گونهٔ موردها» = خودپرداز:

```
TerminalID,Serial,State,LastSeen
1021,GRG-H68N-55021,IN SERVICE,2026-11-15T06:40:00Z
1022,GRG-H68N-55022,CASH OUT,2026-11-15T06:38:00Z
```

- «ستون‌ها»: `{"external_id": "TerminalID", "terminal_id": "TerminalID", "serial_number": "Serial", "status.device_status": "State", "last_contact_at": "LastSeen"}`
- «نگاشت وضعیت خودپرداز» (بخش «خودپردازها» در تنظیمات منبع): `{"IN SERVICE": "in_service", "OUT OF SERVICE": "out_of_service", "CASH OUT": "out_of_cash", "OFFLINE": "offline"}`

## پس از ساخت: صفحهٔ منبع

صفحهٔ هر منبع «اجرای اکنون»، «لغو گذر» و در «کارهای دیگر» «آزمودن اتصال»، «پیش‌نمایش»، «اعمال دوباره روی همه»، «روشن کردن» یا «خاموش کردن» و «حذف» دارد (حذف منبع موارد آن را «دیگر گزارش نمی‌شود» می‌کند و هیچ پیکربندی‌ای را بازنشسته نمی‌کند). زبانه‌ها:
- **خلاصه:** شمار موارد، «پیوسته»، «بی‌همتا»، «بی‌تماس ≥ ۱۴ روز» و خطاهای اجرای آخر، گذر در جریان و اجرای آخر.
- **اجراها:** هر گذر با آغاز، مدت، شمارها و خطاها.
- **موارد:** هرچه ابزار گزارش کرده، با وضعیت آشتی (پیوسته، بی‌همتا، تکراری، خطا، در انتظار آشتی، نادیده، دیگر گزارش نمی‌شود)، پیکربندی پیوسته و پیوند به صفحهٔ همان مورد در ابزار.
- **نگاشت:** کدام مسیر در پاسخ ابزار کدام فیلد پیکربندی را پر می‌کند، با «پیش‌نمایش با این نگاشت» روی نمونهٔ آخرین مورد.
- **تنظیمات:** همهٔ گزینه‌ها در بخش‌های «اتصال»، «چه بیاید»، «زمان‌بندی و آشتی»، «تماس و کهنگی»، «خودپردازها» و «دارایی و نرم‌افزار».
- **دریافت هشدار:** برای ابزارهایی که مشکل می‌فرستند، «منبع رویداد»ی که نخستین گذر وضعیت می‌سازد تا مشکل‌ها به‌صورت هشدار به مدیریت رویداد برسند؛ و برای API ارسال، نشانی‌ها و نمونهٔ درخواست.

**زمان‌بندی و بار روی ابزار:** «فهرست هر چند دقیقه» (پیش‌فرض ۶۰؛ صفر یعنی فقط دستی)، «وضعیت هر چند دقیقه» (صفر یعنی همراه فهرست)، «سقف درخواست در ثانیه» (پیش‌فرض ۵)، «بازآشتی موارد پیوسته هر چند روز» (۷) و «تلاش دوباره برای موارد بی‌همتا هر چند ساعت» (۲۴). Zabbix میزبان‌ها را تکه‌تکه (حداکثر ۵۰۰ در هر درخواست) و vCenter جزئیات ماشین‌ها را به نوبت در «بازخوانی جزئیات» می‌خواند، تا گذرها بار سنگینی روی ابزار نگذارند. موردی که تغییری نکرده دوباره به پایگاه پیکربندی فرستاده نمی‌شود.

## وضعیت پایش

هر پیکربندی و دارایی یکی از این وضعیت‌ها را می‌گیرد: **برقرار**، **هشدار**، **قطع**، **بی‌پاسخ**، **در نگهداری**، **خاموش** یا **نامعلوم**. وضعیت از همهٔ منبع‌های تازهٔ آن جمع می‌شود؛ پنجرهٔ نگهداری مدیریت رویداد یا تغییرِ در حال اجرا روی پیکربندی آن را «در نگهداری» نشان می‌دهد.
- هشدار یا مشکل فقط وقتی «قطع» است که قاعدهٔ همان ابزار بگوید **خود دستگاه** در دسترس نیست (بخش «ابزارها»)؛ دیسک پر «هشدار» است و ماشین مجازی خاموش «خاموش».
- هشدارهایی که ابزار پایش به «منبع رویداد» مدیریت رویداد می‌فرستد هم بی‌منبع داده وضعیت می‌سازند: هشدار دسترس‌پذیری «قطع» و هر هشدار دیگری جز اطلاع «هشدار».
- **«وضعیت پایش»:** فهرست پیکربندی‌ها و دارایی‌ها با نام، کلاس یا دسته، شعبه یا مکان، وضعیت، «از»، آخرین تماس و شمار منبع‌ها؛ با پالایه‌های «قطع»، «بی‌پاسخ»، «هشدار»، «در نگهداری»، «خاموش»، «بی‌تماس بیش از ۱۴ روز» و «خودپردازها» و جست‌وجوی نام، میزبان یا برچسب.
- پنل **«منبع‌ها و وضعیت پایش»** در صفحهٔ هر پیکربندی و دارایی وضعیت هر منبع، آخرین تماس، پیام، «باز کردن در ابزار» و هشدارهای باز را دارد.
- **خودپرداز:** وضعیت عملیاتی دارایی (در سرویس، خارج از سرویس، بدون وجه نقد، در نگهداری، قطع ارتباط) پس از «درنگ پیش از ثبت وضعیت (دقیقه)» (پیش‌فرض ۱۰) و به زمان خود ابزار ثبت می‌شود، پس دسترس‌پذیری ناوگان درست حساب می‌شود؛ اصلاح دستی تا «احترام به اصلاح دستی (ساعت)» (۲۴) نگه داشته می‌شود. خودپرداز با شناسهٔ پایانه و بعد سریال به دارایی‌اش پیوند می‌خورد و هرگز از منبع داده دارایی یا پیکربندی تازه نمی‌گیرد؛ خودپرداز ناشناخته در «صف آشتی» می‌ماند.

**تماس و کهنگی** (بخش «تماس و کهنگی» تنظیمات): فهرست شدن به‌تنهایی تماس نیست؛ «آخرین تماس» زمانی است که خود ابزار دستگاه را دیده است.
- «کهنه پس از چند روز بی‌تماس» (۱۴): پیکربندی «کهنه» می‌شود و در صف «دادهٔ کهنه»ی پایگاه پیکربندی و پالایهٔ «بی‌تماس بیش از ۱۴ روز» می‌آید.
- «مفقود پس از چند روز بی‌تماس» (۴۵) برای دارایی در استفاده، با «دارایی بی‌تماس»: «کار برای مدیر دارایی» (پیش‌فرض) یا «علامت «مفقود» خودکار».
- «بازنشستگی پیکربندی پس از چند روز بی‌تماس» (صفر: خاموش) پیکربندی را فقط وقتی بازنشسته می‌کند که «پیکربندی‌های گزارش‌نشده»ی منبع دادهٔ آن در پایگاه پیکربندی «بازنشسته شوند» باشد و دارایی در استفاده‌ای پشتش نباشد. منبع داده هرگز دارایی را بازنشسته یا اسقاط نمی‌کند.
- **کاهش ناگهانی:** اگر گذر کاملی کمتر از ۷۰٪ گذر کامل پیشین یا هیچ موردی بیاورد، هیچ موردی «دیگر گزارش نمی‌شود» نمی‌شود و مسئول منبع باخبر می‌شود؛ اگر کاهش درست است، «پذیرش اندازهٔ تازه» را در «خلاصه» بزنید.

## صف آشتی

آنچه منبع‌ها آوردند و پایگاه پیکربندی خودش تکلیفش را روشن نکرد، از همهٔ منبع‌هایی که می‌خوانید، با پالایهٔ منبع و جست‌وجو:
- **بی‌همتا:** با هیچ پیکربندی‌ای جور نشد (مثلاً «سیاست ساخت» = ساخت پس از بررسی). «ساخت پیکربندی»، «پیوند به…» (پیکربندی را برمی‌گزینید و گذر بعدی منبع آن را آشتی می‌کند) یا «نادیده گرفتن» (تا ابزار آن را دیگرگونه گزارش نکند، دوباره در صف نمی‌آید).
- **تکراری:** با چند پیکربندی جور است؛ یکی را در «بررسی تکراری‌ها»ی پایگاه پیکربندی برگزینید.
- **خطا:** رکورد ابزار خوانده نشد یا ساخت پیکربندی رد شد؛ پیام هر مورد علت را می‌گوید.
- **ناهمخوانی:** مقدار ابزار با دفتر دارایی فرق دارد (کاربر، مکان، برچسب اموال، شمارهٔ سریال…). «به‌روزرسانی دارایی با مقدار ابزار» (با دسترسی خود مدیر دارایی) یا «نادیده گرفتن» (تا مقدارهای گزارش‌شده تغییر نکنند). هیچ چیزی خودکار در دارایی نوشته نمی‌شود.

کارها روی یک ردیف یا با «کار دسته‌جمعی» روی چند ردیف انجام می‌شوند.

**اعتبار منبع‌ها و آنچه ابزارها تغییر نمی‌دهند:**
- هر منبع داده یک «منبع داده»ی پایگاه پیکربندی با اولویت دارد (عدد کمتر معتبرتر): ثبت دستی ۲۰، vCenter ۴۰، فایل ۵۰، Zabbix و PRTG ۷۰، REST و API ارسال ۹۰. مقدار منبع معتبرتر با منبع کم‌اعتبارتر بازنویسی نمی‌شود و ویژگی قفل‌شدهٔ پیکربندی دست نمی‌خورد ([`cmdb_FA.md`](cmdb_FA.md)).
- ثبت دستی پیش‌فرض بر همهٔ منبع‌ها برتری دارد؛ «معتبرتر از ویرایش دستی» را فقط مدیر پیکربندی با تأیید دوبارهٔ هویت روشن می‌کند.
- کاربر، مکان، برچسب اموال، مرکز هزینه و وضعیت‌هایی که مدیریت دارایی نگه می‌دارد را ابزارها هرگز تغییر نمی‌دهند؛ مقدار ابزار در فیلدهای «گزارش‌شده» می‌ماند و اگر فرق کند «ناهمخوانی» می‌شود.

**ساخت دارایی برای دستگاه‌های تازه:** مدیر دارایی نخست در «داشبورد دارایی‌ها» «دارایی برای سخت‌افزار کشف‌شده» را می‌زند؛ سپس در بخش «دارایی و نرم‌افزار» هر منبع «ساخت دارایی برای دستگاه‌های تازه» را روشن می‌کند. روزانه تا «سقف روزانهٔ ساخت دارایی» (پیش‌فرض ۵٬۰۰۰) دارایی «تأییدنشده» ساخته می‌شود؛ هرگز برای خودپرداز، CRS یا کیوسک، حتی وقتی ابزار پایش آن را دستگاه معمولی گزارش کند.

## آنچه به ۱٫۲ رفت

- ابزارهای دیگر: Microsoft MECM (SCCM)، رایانه‌های Active Directory، Kaspersky Security Center، ManageEngine Endpoint Central، GLPI و نمای SQL Server. در ۱٫۱ در «منبع داده تازه» پیشنهاد نمی‌شوند.
- رلهٔ کاریز، که نسخهٔ وب را به ابزارهای درون شبکهٔ سازمان می‌رساند؛ تا آن زمان این ابزارها را با نسخهٔ سرور یا API ارسال وصل کنید.
- نرم‌افزارهای نصب‌شده از منبع‌ها، خوراک مدیریت مجوز نرم‌افزار و زبانهٔ «نرم‌افزار یکسان‌نشده» در صف آشتی.

## عیب‌یابی

پیام‌ها در «آزمودن اتصال»، «پیش‌نمایش»، «اجراها»، خطای هر مورد و پاسخ API ارسال می‌آیند. بیشتر آن‌ها کار لازم را خودشان می‌گویند؛ ستون دوم هر جا لازم است نکته‌ای می‌افزاید. «…» جای نام، نشانی یا عدد است.

### اتصال و شبکه

| پیام | چه کنید |
|---|---|
| «نام کاربری یا کلید پذیرفته نشد» | کلید یا گذرواژه را در ابزار بسازید و دوباره وارد کنید؛ حساب در ابزار فعال باشد |
| ««…» پاسخ نداد» | ابزار روشن است؟ دیوارهٔ آتش میان سرور کاریز و ابزار باز است؟ کاریز خودش دوباره تلاش می‌کند |
| «پاسخ به نشانی دیگری هدایت شد؛ نشانی منبع را اصلاح کنید» | نشانی نهایی (مثلاً با `https://` یا مسیر کامل) را بنویسید |
| «کلید را در بخش «کلید» وارد کنید، نه در نشانی» | نام کاربری، گذرواژه یا کلید را از نشانی بردارید |
| «این نشانی به خود سرور کاریز یا پایگاه داده‌اش می‌رسد و پذیرفته نمی‌شود» | نشانی ابزار را درست بنویسید |
| «اتصال بدون رمزنگاری فقط در نسخهٔ سرور و با تیک «اتصال بدون رمزنگاری (فقط شبکهٔ داخلی)» پذیرفته است» | HTTPS را به کار ببرید؛ در نسخهٔ سرور فقط اگر ناچارید تیک را بزنید |
| «این نشانی بیرون از میزبان منبع است و پذیرفته نمی‌شود؛ میزبان را در «میزبان‌های مجاز دیگر» بیفزایید» | نام دیگر ابزار را به «میزبان‌های مجاز دیگر» بیفزایید |
| «نشانی ابزار وارد نشده است» | «نشانی ابزار» را پر کنید |
| «پاسخ ابزار JSON معتبر نیست» | نشانی و مسیر به API می‌رسد، نه به صفحهٔ وب یا صفحهٔ ورود؟ |
| «پاسخ ابزار بزرگ‌تر از ۲۰ مگابایت است؛ اندازهٔ صفحه را کوچک‌تر کنید» | «اندازهٔ صفحه» یا «میزبان در هر درخواست» را کم کنید |
| «ابزار پاسخ … داد» | کد پاسخ HTTP ابزار است: ۴۰۱/۴۰۳ کلید یا دسترسی، ۴۰۴ مسیر، ۵۰۰ گزارش خود ابزار |
| «منبع «…» هنوز ساخته نشده است» | این ابزار در ۱٫۱ نیست (بخش «آنچه به ۱٫۲ رفت») |
| «منبع «…» در این نسخهٔ کاریز اجرا نمی‌شود» | این نوع منبع در این نسخه (وب یا سرور) کار نمی‌کند؛ مثلاً پوشهٔ ورودی فقط در نسخهٔ سرور است |
| «سرآیند «…» برای این نوع منبع مجاز نیست» | یکی از سرآیندهای فهرست «سرآیند کلید» را برگزینید |
| «میزبان … در فهرست مجاز سرور نیست؛ مدیر سرور باید آن را در پیکربندی سرور (network.allow) بیفزاید» | `karizctl allow add <میزبان>` یا «مدیریت سامانه ← سلامت سرور» |
| «برای فرستادن کلید، نام دقیق این میزبان باید در فهرست مجاز سرور باشد» | به‌جای الگو یا بازهٔ IP، نام کامل میزبان را بیفزایید |
| «نسخهٔ وب فقط به ابزارهایی با نشانی عمومی وصل می‌شود؛ برای ابزار درون شبکهٔ سازمان رلهٔ کاریز یا ارسال از ابزار را به کار ببرید» | رله با ۱٫۲ می‌آید؛ ابزار را با API ارسال یا نسخهٔ سرور وصل کنید |
| «نام میزبان … پیدا نشد؛ نشانی ابزار را بررسی کنید» | نام را در DNS سرور کاریز بیازمایید (`nslookup`) |

## جزئیات فنی

- **جدول‌ها** (`src/shared/tables/discovery.ts`، حوزهٔ `cmdb`، همه محلی و بی‌همگام‌سازی با برنامهٔ ویندوز): `discovery_connector` (منبع داده)، `discovery_item` (هر چیزی که ابزار گزارش کرده؛ نقشهٔ شناسه به پیکربندی و دارایی)، `discovery_state` (وضعیت و تماس هر پیکربندی یا دارایی)، `discovery_problem`، `discovery_run` (هر گذر)، `discovery_batch` (دسته‌های API ارسال).
- **نوع‌ها:** `src/shared/discovery/kinds/*` (توصیف هر ابزار و قاعدهٔ دسترس‌پذیری آن) و `src/server/modules/discovery/connectors/*`؛ قالب رکورد `kariz.discovery/1` در `src/shared/discovery/types.ts`.
- **API** (`/api/o/:org/discovery`): منبع‌ها، آزمودن، پیش‌نمایش، اجرا و لغو، موارد، صف آشتی، `status` (تابلو) و `panel/:table/:id`؛ API ارسال در `/api/v1/discovery/:connector/{batches,status}` با کلید کاربر یکپارچه‌سازی.
- **آزمون‌ها:** `tests/discovery-*.test.ts` (از جمله `discovery-push`، `discovery-status`، `discovery-device`، `discovery-kinds-zabbix|prtg|vcenter|feed`، `discovery-docs` که پیام‌های این راهنما را با کد می‌سنجد)، `tests/integration-itam-discovery.test.ts` و سناریوی ۱۳ شبیه‌سازی بانک ([`qa/BANK_SIM_FA.md`](../qa/BANK_SIM_FA.md)).
