# مسیر مالک با کلیک روی صفحه‌ها — `scripts/e2e-owner-path.mjs`

گزارش «برای «مرحلهٔ فرم» کسی پیدا نشد» نسخهٔ ۱٫۱٫۵ را با Playwright روی خود صفحه‌ها، از پایگاه دادهٔ تازه تا پس از «حذف کامل داده‌های نمایشی»، دوباره اجرا می‌کند؛ روی هر یک از سه نسخه جدا. همه‌چیز با کلیک و نوشتن در صفحه‌ها انجام می‌شود؛ API فقط برای سنجیدن وضعیت و با نشست خود هر فرد خوانده می‌شود. یادداشت‌های انتشار: [`../RELEASE_FA.md`](../RELEASE_FA.md) (۱٫۱٫۵).

## ۱. گام‌ها

| گام | آنچه می‌کند |
|---|---|
| `setup`، `owner-signin` | راه‌اندازی نخست با صفحه‌های خود نسخه (برنامهٔ ویندوز: «شروع روی همین رایانه»؛ سرور: `/setup?token=…`؛ وب: ثبت‌نام و ساخت سازمان) و ورود مالک |
| `demo-load`، `demo-signin` | «داده‌های نمایشی» ← بارگذاری بستهٔ «کوچک» و روشن کردن «ورود با حساب‌های نمایشی» |
| `members` | شش عضو واقعی در «کاربران و دسترسی‌ها» |
| `fields-A` … `workflow-A` | گونهٔ الف (نام‌های گزارش مالک): شش فیلد کتابخانه، فرمی با دو زبانه، «مدیر گروه» و «کارشناس ارشد» هر کدام با دو دارندهٔ نمایشی، و گردش‌کاری با فرم در دو مرحله («مرحلهٔ فرم» با «کجا»ی پیش‌فرض طراح، سپس تأیید «کارشناس ارشد»)؛ انتشار |
| `fields-B` … `workflow-B` | گونهٔ ب: همان، با نام‌های «(ب)» و دارندگان واقعی |
| `run-A`، `run-B` | حساب نمایشی (الف) و عضو واقعی (ب) پرونده را از «گردش‌کارها» آغاز می‌کنند و دارندگان آن را از «کارتابل» تا پایان می‌برند؛ «کسی پیدا نشد» نباید دیده شود |
| `run-C` | مالک (عضو واقعی) پروندهٔ گردش‌کار الف را آغاز می‌کند: صفحهٔ پرونده دلیل منتظر ماندن را می‌گوید؛ دارنده‌ای واقعی افزوده می‌شود و «دوباره پیدا کردن انجام‌دهنده» مرحله را به او می‌دهد |
| `purge`، `after-purge`، `after-purge-run-B` | پیش‌نمایش و «حذف کامل داده‌های نمایشی»؛ سپس گردش‌کارها، فرم‌ها، فیلدها، نقش‌ها، اعضا و صفحهٔ داده‌های نمایشی بی خطای کنسول، پاسخ ۴xx/۵xx (جز ۴۰۳) یا صفحهٔ خطا، گردش‌کار ب سالم، و پروندهٔ تازهٔ ب تا پایان |

## ۲. پیش‌نیازها

- در پوشهٔ `itsm`: `npm ci` و `npm run build:ui` (اسکریپت `public/` را سرو می‌کند و رابط کاربری را نمی‌سازد).
- Playwright و Chromium، ابزار اسکریپت و نه وابستگی برنامه، همان‌گونه که کار `clickthrough` در CI می‌گیرد: `npm install --no-save --no-audit --no-fund playwright@1.63.0` و `npx playwright install --with-deps chromium`.
- نسخهٔ سرور و وب: برنامه‌های PostgreSQL 16 (`--pg-bin`، پیش‌فرض `/usr/lib/postgresql/16/bin`)، درگاهی آزاد (`--pg-port`، پیش‌فرض `55550`) و پوشه‌ای دورریختنی (`--pg-dir`؛ پوشهٔ موجود را فقط وقتی خالی می‌کند که از اجرای پیشین باشد — نشان `.e2e-owner-path` یا `kariz.json` نسخهٔ سرور — و اگر چیز دیگری در آن باشد دست نگه می‌دارد؛ در پایان فقط پوشهٔ نشان‌دار را برمی‌دارد). اگر اسکریپت با root اجرا شود، PostgreSQL با کاربر `--pg-user` (پیش‌فرض `nobody`) اجرا می‌شود. روی Linux آزموده شده است.

## ۳. اجرا

از پوشهٔ `itsm`، هر نسخه جدا (هر اجرا سرور و پایگاه دادهٔ خودش را می‌سازد و در پایان برمی‌دارد):

```bash
# برنامهٔ ویندوز: سرور محلی برنامه (src/desktop/server.ts) روی PGlite در پوشهٔ داده‌ای تازه، بی پوستهٔ Electron
node scripts/e2e-owner-path.mjs --edition desktop --out /tmp/e2e/desktop

# نسخهٔ سرور: karizctl init / db-init / pg-start / db-bootstrap / migrate روی خوشه‌ای دورریختنی،
# سپس src/server-edition/main.ts --standalone با HTTPS و گواهی خودساخته‌اش
node scripts/e2e-owner-path.mjs --edition server --out /tmp/e2e/server --pg-dir /tmp/e2e/pg-server --pg-port 55550

# نسخهٔ وب: next build (یک بار؛ --rebuild دوباره می‌سازد) و next start با DATABASE_URL از راه شبیه‌ساز
# pooler تراکنشی Supabase (tests/web-db-pooler.ts)؛ پایگاه داده با scripts/migrate-db.mts و تپش دقیقه‌ای /api/cron/tick
node scripts/e2e-owner-path.mjs --edition web --out /tmp/e2e/web --pg-dir /tmp/e2e/pg-web --pg-port 55551
```

گزینه‌های دیگر: `--port` (پیش‌فرض ۴۴۷۱ برنامهٔ ویندوز، ۴۴۷۲ سرور، ۴۴۷۳ وب)، `--size small|medium` (اندازهٔ بستهٔ نمایشی، پیش‌فرض `small`)، `--keep` (سرور و داده‌ها پس از اجرا می‌مانند)، `--base <نشانی>` (سروری که از پیش اجرا می‌شود؛ راه‌اندازی و داده همان است که دارد)، `--from <گام>` / `--until <گام>` (با `--base` و فایل وضعیت اجرای پیشین در `--out`، برای تکرار گام‌های پسین)، `--timeout <ms>` (سقف هر انتظار در صفحه، پیش‌فرض ۹۰٬۰۰۰) و `--static <پوشه>` (ساخت رابط کاربری، پیش‌فرض `public`).

## ۴. خروجی

در `--out`: تصویر هر گام (`NN-*.png`، پهنای ۱۴۴۰ با deviceScaleFactor 2)، `REPORT.md` (گام، نسخه، گذشت یا شکست، آنچه دیده شد، یافته‌ها با شاهدشان)، `summary.json`، `server.log`، و برای تکرار با `--from` فایل `state.json` و پوشهٔ `sessions`؛ نسخهٔ وب `postgres.log` را هم دارد. کد خروج ۰ یعنی همهٔ گام‌ها گذشت و یافته‌ای ثبت نشد؛ ۱ یعنی گامی شکست خورد یا یافته‌ای از محصول ثبت شد.

یک اجرا روی ماشینی مشترک ۱۷ تا ۲۷ دقیقه طول کشید؛ بیشترش بارگذاری بستهٔ نمایشی است. زمان‌ها سنجش کارایی نیستند ([`PERFORMANCE_E2E_FA.md`](PERFORMANCE_E2E_FA.md) برای آن است).

## ۵. آنچه نمی‌آزماید

- برنامهٔ ویندوز بی پوستهٔ Electron، نصب‌کننده و ورود ویندوز اجرا می‌شود (کار `desktop-e2e` در CI آن‌ها را می‌آزماید)؛ نسخهٔ سرور بی MSI و سرویس‌های ویندوز (کار `bank-sim`).
- نسخهٔ وب سقف‌های تابع Vercel را ندارد (`after()` در همان فرایند اجرا می‌شود) و `pg_cron` Supabase را اسکریپت با فراخوانی دقیقه‌ای `/api/cron/tick` جانشین می‌کند.
- فقط بستهٔ «کوچک»؛ پس از حذف فقط صفحه‌های گردش‌کار، فرم، فیلد، نقش، اعضا و داده‌های نمایشی سنجیده می‌شوند، نه همهٔ ماژول‌ها (برای آن [`CLICKTHROUGH.md`](CLICKTHROUGH.md)).

## ۶. نتیجهٔ ۱٫۱٫۵

۱ آذر ۱۴۰۵، شاخهٔ یکپارچه‌سازی ۱٫۱٫۵ پیش از اصلاح‌های پایانی: در هر سه نسخه هر ۱۹ گام گذشت و «کسی پیدا نشد» در الف و ب دیده نشد. چهار یافته، همه در همین نسخه درست شده‌اند: نسخهٔ سرور خود را «نسخهٔ وب» می‌نامید؛ فیلد نمایشی و فیلد مالک با یک برچسب در طراح فرم از هم جدا نمی‌شدند؛ پیش‌نمایش حذف دارندگان نقش را با شناسه نام می‌برد؛ و پس از حذف، پروندهٔ منتظرِ مالک دلیلی را نگه می‌داشت که حساب‌های نمایشیِ حذف‌شده را نام می‌برد. دو یافتهٔ دیگر از تصویرهای همین دور هم درست شده‌اند: گزینهٔ دکمه‌ای فرم مرحله در کنار صفحهٔ پرونده از لبهٔ آن بیرون می‌زد («دسترسی» در «نوع درخواست»)، و مرحلهٔ منتظری که کسی آن را در دست نداشت روی نمودار «در جریان» می‌گفت، نه «منتظر انجام‌دهنده».
