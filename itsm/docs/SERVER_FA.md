# نسخهٔ سرور — نصب و نگهداری در شبکهٔ داخلی بانک

این راهنما برای تیم فناوری اطلاعات بانک است: نصب برنامه روی یک **ویندوز سرور** در **شبکهٔ بسته (بدون اینترنت)**، راه‌اندازی، پشتیبان‌گیری، ارتقا، پایش و امن‌سازی. پس از نصب، همهٔ کارکنان با مرورگر به نشانی سرور (مثلاً `https://kariz.bank.local`) وصل می‌شوند. نام برنامه در رابط کاربری همان نام محصول است؛ نام‌های ویندوزی این نسخه (بستهٔ نصب «Kariz Server»، سرویس‌های `KarizDB` و `KarizApp`، پوشه‌های `C:\Program Files\Kariz` و `C:\ProgramData\Kariz`) در یک جا تعریف شده‌اند: `packaging/server/edition.json`.

راهنمای فنی (انگلیسی، برای مهندسان): `docs/spec/SERVER.md`.

---

## ۱. سه نسخه در یک نگاه

| | نسخهٔ وب | برنامهٔ ویندوز | **نسخهٔ سرور** |
|---|---|---|---|
| کجا اجرا می‌شود | Vercel + Supabase (اینترنت) | رایانهٔ هر کاربر یا یک رایانهٔ دفتر | ویندوز سرور در شبکهٔ داخلی سازمان |
| پایگاه داده | PostgreSQL ابری | PostgreSQL درون‌برنامه‌ای (PGlite) | PostgreSQL 17 نصب‌شده روی همان سرور (+ pgvector) |
| کاربران همزمان | بسته به طرح ابری | چند نفر | صدها تا هزاران نفر (بخش ۳) |
| اینترنت | لازم | اختیاری | **لازم نیست** (نصب و کار بدون اینترنت) |
| پیوست‌ها | در پایگاه داده | در پایگاه داده | روی دیسک یا مسیر شبکه (UNC)، با ضدویروس اختیاری |
| ورود | حساب‌های برنامه | حساب‌های برنامه | حساب‌های برنامه + Active Directory (بخش ۹) |
| هوش مصنوعی | سرویس‌های ابری | ابری یا محلی | **فقط محلی** (Ollama، vLLM …) + جست‌وجوی معنایی پایه و پیش‌بینی‌ها |
| کارهای پس‌زمینه | زمان‌بند ابری | همان رایانه | یک زمان‌بند برای همهٔ فرایندها (انتخاب خودکار) |

همهٔ ماژول‌ها، دسترسی‌ها و صفحه‌ها در هر سه نسخه یکی‌اند. برنامهٔ ویندوز کارشناسان می‌تواند مثل نسخهٔ وب با نسخهٔ سرور همگام شود (بخش ۱۶).

## ۲. ساختار نصب

| بخش | جزئیات |
|---|---|
| سرویس `KarizDB` | PostgreSQL 17 فقط روی `127.0.0.1` (درگاه ۵۴۳۲)؛ حساب مجازی `NT SERVICE\KarizDB` |
| سرویس `KarizApp` | سرور برنامه (Node.js): یک ناظر و به تعداد هسته‌ها فرایند کاری؛ HTTPS روی ۴۴۳ و انتقال HTTP ۸۰ به HTTPS؛ حساب مجازی `NT SERVICE\KarizApp`؛ پس از `KarizDB` روشن می‌شود |
| `C:\Program Files\Kariz` | برنامه، Node.js، PostgreSQL، `karizctl.cmd`، اسکریپت‌های نصب |
| `C:\ProgramData\Kariz` | `kariz.json` (پیکربندی، کلید رمزنگاری، رمز حساب برنامه در پایگاه داده)، `kariz-admin.json` (رمز مدیر PostgreSQL؛ فقط مدیران ویندوز)، `db` (پایگاه داده)، `blobs` (پیوست‌ها)، `backups`، `logs`، `tls`، `quarantine` |
| بازیابی خودکار | هر دو سرویس پس از خطا تا سه بار دوباره روشن می‌شوند؛ فرایند کاریِ ازکارافتاده را ناظر بی‌درنگ جایگزین می‌کند |

## ۳. اندازهٔ سخت‌افزار

> اعداد این جدول **برآورد اولیه** است و پس از آزمون بار نهایی می‌شود: **«بر اساس آزمون بار — PERFORMANCE_FA.md»**. تنظیمات PostgreSQL را `karizctl pg-conf` از روی سخت‌افزار خود سرور حساب می‌کند.

| کارکنان | کارشناسان همزمان | رکورد در سال | پردازنده | حافظه | دیسک (SSD) | فرایند کاری | اتصال هر فرایند |
|---|---|---|---|---|---|---|---|
| تا ۲٬۰۰۰ | تا ۱۰۰ | ۲۰۰ هزار | ۴ هسته | ۱۶ گیگابایت | ۲۰۰ گیگابایت | ۴ | ۸ |
| ۲٬۰۰۰ تا ۱۰٬۰۰۰ | تا ۳۰۰ | ۱ میلیون | ۸ هسته | ۳۲ گیگابایت | ۵۰۰ گیگابایت | ۸ | ۱۰ |
| ۱۰٬۰۰۰ تا ۳۰٬۰۰۰ | تا ۸۰۰ | ۳ میلیون | ۱۶ هسته | ۶۴ گیگابایت | ۱ ترابایت | ۱۲ | ۱۲ |
| بیش از ۳۰٬۰۰۰ | بیش از ۸۰۰ | ۱۰ میلیون | ۳۲ هسته | ۱۲۸ گیگابایت | ۲ ترابایت + دیسک جدا برای پشتیبان | ۱۶ | ۱۲ |

«بر اساس آزمون بار — PERFORMANCE_FA.md»: ستون‌های حافظه، فرایند کاری و اتصال پس از آزمون بار مهندس کارایی به‌روز می‌شوند. قاعدهٔ اتصال‌ها همیشه برقرار است: `فرایندها × (اتصال هر فرایند + ۱) + ۱ ≤ max_connections − ذخیره` (برنامه خودش اندازهٔ استخر را با این قاعده کم می‌کند و در گزارش هشدار می‌دهد).

- پیوست‌ها جدا حساب می‌شوند: میانگین حجم پیوست × تعداد سالانه (مثلاً ۲۰۰ هزار پیوست ۵۰۰ کیلوبایتی ≈ ۱۰۰ گیگابایت در سال).
- دیسک چرخان (HDD) برای پایگاه داده توصیه نمی‌شود.
- پایگاه داده و برنامه روی یک سرورند؛ تنظیم خودکار ۶۰٪ حافظه را به PostgreSQL می‌دهد.

## ۴. پیش‌نیازها

- Windows Server 2019، 2022 یا 2025 (۶۴ بیتی؛ برای آزمایشگاه: Windows 10/11)، دسترسی مدیر.
- حافظهٔ دست‌کم ۴ گیگابایت (توصیه: بخش ۳)، دست‌کم ۲۰ گیگابایت فضای آزاد روی دیسک داده.
- درگاه‌های ۴۴۳ و ۸۰ آزاد (یا درگاه‌های دیگر با `PORT` و `HTTPPORT`).
- یک نام DNS برای سرور (مثلاً `kariz.bank.local`) و ترجیحاً گواهی صادرشده از CA بانک (بخش ۶).
- **اینترنت لازم نیست**: Node.js، PostgreSQL، pgvector، WinSW و محیط اجرای Visual C++ همه درون بستهٔ نصب‌اند.

## ۵. نصب

### با رابط گرافیکی
فایل `Kariz-Server-x.y.z.msi` را با حساب مدیر اجرا کنید، پوشهٔ نصب را تأیید کنید و صبر کنید تا پایان. در صفحهٔ آخر نشانی راه‌اندازی نخست را از فایل `C:\ProgramData\Kariz\setup-url.txt` بردارید (بخش ۸).

### بی‌صدا (توزیع با ابزارهای سازمان)
```
msiexec /i Kariz-Server-1.0.0.msi /qn /l*v C:\Temp\kariz-install.log HOSTNAME=kariz.bank.local PORT=443 DATADIR=D:\Kariz CERTPATH=C:\certs\kariz.pfx CERTPASSWORD=********
```

| ویژگی | پیش‌فرض | توضیح |
|---|---|---|
| `HOSTNAME` | نام کامل رایانه | نامی که کارکنان می‌زنند؛ نشانی سامانه `https://HOSTNAME` |
| `PORT` | `443` | درگاه HTTPS؛ در نصب دوباره و ارتقا، اگر داده نشود، همان درگاه پیکربندی می‌ماند |
| `HTTPPORT` | `80` | درگاه HTTP که به HTTPS منتقل می‌کند؛ `0` = خاموش؛ در ارتقا مانند `PORT` نگه داشته می‌شود |
| `DATADIR` | `C:\ProgramData\Kariz` | پوشهٔ داده‌ها (پایگاه داده، پیوست‌ها، پشتیبان‌ها)؛ پوشه‌ای تازه یا خالی، نه ریشهٔ دیسک (`D:\`) و نه پوشهٔ سیستمی؛ در ارتقا، اگر داده نشود، همان پوشهٔ قبلی به کار می‌رود |
| `CERTPATH` / `CERTPASSWORD` | — | فایل PFX گواهی بانک و گذرواژهٔ آن (گذرواژه و خروجی اسکریپت‌های نصب در گزارش MSI نوشته نمی‌شود) |
| `AIRGAPPED` | `1` | `1` = شبکهٔ بسته (فقط میزبان‌های مجاز)؛ `0` = بدون محدودیت خروجی |
| `WORKERS` | `0` | تعداد فرایندهای کاری (`0` = به تعداد هسته‌ها، دست‌کم ۲) |
| `REMOVEDATA` | `0` | فقط هنگام حذف: `1` داده‌ها را هم پاک می‌کند (فقط پوشه‌ای که نشان `.kariz-data` یا `kariz.json` دارد) |

گزارش کامل هر نصب در `DATADIR\logs\install-<زمان>.log` است (فقط مدیران و SYSTEM)؛ در هر گام زمان و نتیجه نوشته می‌شود. گزارش MSI (`/l*v`) فقط نتیجهٔ هر گام نصب را دارد، نه خروجی اسکریپت‌ها را؛ نشانی راه‌اندازی نخست هرگز در گزارش‌ها نوشته نمی‌شود و فقط در `setup-url.txt` است. پوشهٔ داده پیش از نوشتن هر رمز یا کلیدی به مدیران و SYSTEM محدود می‌شود.

نصب‌کننده این کارها را می‌کند: بررسی پیش‌نیازها، ساخت `kariz.json` با کلید رمزنگاری و گذرواژه‌های تصادفی پایگاه داده، ثبت سرویس‌ها با حساب‌های مجازی، محدود کردن دسترسی پوشه‌ها، ساخت پایگاه داده (UTF8، ترتیب‌بندی فارسی ICU `fa-IR`، checksum صفحه‌ها)، تنظیم خودکار `postgresql.conf`، افزونه‌های `pg_stat_statements` و `vector`، اجرای مراحل ساختار پایگاه داده، باز کردن درگاه در دیوارهٔ آتش، روشن کردن سرویس‌ها و صبر تا آماده شدن، و ساخت نشانی یک‌بارمصرف راه‌اندازی.

## ۶. نام DNS و گواهی از CA بانک

۱. در DNS داخلی رکورد `A` برای `kariz.bank.local` به نشانی IP سرور بسازید.
۲. از CA سازمان (مثلاً AD CS) گواهی **Server Authentication** با نام `kariz.bank.local` در Subject Alternative Name بگیرید و آن را **با کلید خصوصی** به‌صورت PFX صادر کنید.
۳. گواهی را یکی از این سه راه نصب کنید:
   - هنگام نصب: `CERTPATH=… CERTPASSWORD=…`
   - در راه‌اندازی نخست (گام «نشانی و گواهی»)
   - بعداً: `karizctl rotate-cert --pfx C:\certs\kariz.pfx --password ********` (یا `--cert server.crt --key server.key`)؛ فرایندها یکی‌یکی و **بدون قطعی** با گواهی تازه راه‌اندازی می‌شوند.
۴. تا وقتی گواهی بانک نصب نشده، سرور یک گواهی **خودامضای موقت** برای همان نام می‌سازد و مرورگرها هشدار می‌دهند.

حداقل TLS 1.2 است و فقط رمزهای امن (ECDHE + AES-GCM/ChaCha20) پذیرفته می‌شوند. HSTS روشن است و کوکی‌ها `Secure` و `HttpOnly`اند.

## ۷. دیوارهٔ آتش

نصب‌کننده قاعدهٔ ورودی «Kariz HTTPS» را برای درگاه‌های HTTPS و HTTP (پروفایل‌های Domain و Private) می‌سازد. PostgreSQL فقط به `127.0.0.1` گوش می‌دهد و نباید درگاه ۵۴۳۲ را باز کنید. ترافیک **خروجی** سرور را می‌توانید در دیوارهٔ آتش بانک به‌کلی ببندید، جز به میزبان‌های داخلی‌ای که در فهرست مجاز گذاشته‌اید (Exchange، Active Directory، سرور مدل هوش مصنوعی).

## ۸. راه‌اندازی نخست

۱. نشانی را از `C:\ProgramData\Kariz\setup-url.txt` بردارید (فقط مدیران آن را می‌خوانند) و در مرورگر باز کنید. نشانی را گم کرده‌اید یا منقضی شده (۱۴ روز)؟ `karizctl setup-token`.
۲. **سازمان و مدیر**: نام سازمان و نخستین حساب (این حساب مدیر سامانه و **حساب اضطراری** سازمان می‌شود: حتی اگر بعداً ورود محلی را برای همه جز حساب‌های اضطراری ببندید، این حساب با رمز خودش وارد می‌شود و اگر کنترل‌کنندهٔ دامنه در دسترس نبود بانک قفل نمی‌ماند).
۳. **نشانی و گواهی**: نشانی‌ای که کارکنان می‌زنند و نصب گواهی بانک.
۴. **ایمیل و هوش مصنوعی**: سرور SMTP سازمان (Exchange) به‌عنوان کانال ایمیل پیش‌فرض، و نشانی سرورهای مدل محلی؛ این میزبان‌ها خودکار به فهرست مجاز افزوده می‌شوند.
۵. **پشتیبان‌گیری**: پوشهٔ پشتیبان‌ها (ترجیحاً روی دیسک یا سرور دیگر).
۶. کد بازیابی حساب مدیر را جای امنی نگه دارید. صفحهٔ پایان دو پیوند دارد: «فهرست کاربران (LDAP و SCIM)» برای ورود با Active Directory و «امنیت ورود و نشست‌ها» برای سیاست نشست و حساب‌های اضطراری.

تا پیش از پایان راه‌اندازی، همهٔ بخش‌های برنامه (از جمله ورود خودکار ویندوز و ورود با حساب سازمانی) بسته‌اند و هیچ‌کس در شبکه نمی‌تواند خودش حساب بسازد. پس از راه‌اندازی نشانی یک‌بارمصرف دیگر کار نمی‌کند و ثبت‌نام آزاد خاموش است: حساب‌ها را مدیران می‌سازند یا از Active Directory می‌آیند. نسخهٔ سرور سقف طرح‌های SaaS را ندارد (طرح «سازمانی» پیش‌فرض می‌شود).

## ۹. ورود با Active Directory

راهنمای کامل تیم شبکه و AD: [AD_FA.md](AD_FA.md) (حساب خدمت، LDAPS، نگاشت گروه‌ها، SSO، GPO مرورگرها، سیاست نشست).

پس از راه‌اندازی، از «یکپارچه‌سازی ← فهرست کاربران (LDAP و SCIM)» (`/<سازمان>/integrations/directory`) سرور AD را تعریف کنید؛ همگام‌سازی کاربران و گروه‌ها و ورود با حساب دامنه همان‌جا تنظیم می‌شود.

- **فهرست مجاز**: هر اتصال به کنترل‌کنندهٔ دامنه (ورود، همگام‌سازی و «آزمایش اتصال») از فهرست مجاز شبکه می‌گذرد. نام هر کنترل‌کننده (یا بازهٔ IP آن‌ها) را بیفزایید: `karizctl allow add dc1.bank.local`، یا در «مدیریت سامانه ← سلامت سرور» (پس از تأیید دوبارهٔ هویت). اگر میزبانی در فهرست نباشد، «آزمایش اتصال» نام همان میزبان و این دو راه را نشان می‌دهد؛ سامانه هیچ میزبانی را خودکار مجاز نمی‌کند.
- **ورود خودکار ویندوز روی همین سرور (Negotiate/Kerberos)**: ماژول `node-expose-sspi` همراه بستهٔ نصب است. SPN را برای نام سامانه ثبت کنید: سرویس `KarizApp` با حساب مجازی `NT SERVICE\KarizApp` اجرا می‌شود و از شبکه با حساب رایانه دیده می‌شود، پس `setspn -S HTTP/kariz.bank.local KARIZ-SRV01$` (یا اگر سرویس را با حساب دامنه‌ای مانند `BANK\svc-kariz-web` اجرا می‌کنید، روی همان حساب). بررسی بلیت Kerberos کار خود ویندوز (LSA) با کلید همان حساب است و **هیچ اتصال خروجی** از برنامه نمی‌خواهد؛ فقط یافتن شخص در AD برای نگاشت نقش‌ها از راه LDAP و فهرست مجاز انجام می‌شود.
- **IIS روی همین سرور**: IIS با Windows Authentication روی درگاه ۴۴۳ و نسخهٔ سرور روی loopback (`listen.address: 127.0.0.1`، مثلاً `listen.https_port: 8443`)؛ در منبع، «نشانی‌های پراکسی معتمد» = `127.0.0.1`. IIS روی سرور دیگر: نشانی آن را هم در `trusted_proxies` همین فایل و هم در «نشانی‌های پراکسی معتمد» منبع بنویسید — سرآیند کاربر فقط از پراکسی‌ای پذیرفته می‌شود که در هر دو فهرست باشد.
- GPO مرورگرها (`AuthServerAllowlist`، Local intranet) برای `kariz.bank.local`: [AD_FA.md](AD_FA.md) بخش ۵.

## ۱۰. هوش مصنوعی در شبکهٔ بسته

- سرویس‌های اینترنتی (Claude، ChatGPT، Gemini …) در این نسخه **در دسترس نیستند** و تنظیمات هوش مصنوعی همین را نشان می‌دهد.
- یک سرور مدل در شبکهٔ بانک بسازید (مثلاً Ollama یا vLLM روی سرور GPU) و در «تنظیمات ← هوش مصنوعی ← اتصال تازه» نوع «Ollama» یا «سازگار با OpenAI» را با نشانی آن ثبت کنید (مثلاً `http://ollama.bank.local:11434/v1`).
- نشانی سرور مدل باید در فهرست مجاز باشد (راه‌اندازی نخست خودش می‌افزاید؛ بعداً: `karizctl allow add ollama.bank.local`).
- **بدون هیچ مدلی هم** کار می‌کنند: جست‌وجوی معنایی پایه (بردارساز محلی بدون دانلود وزن)، پیش‌بینی‌های کلاسیک (دسته، گروه، اولویت، زمان حل)، گزارش‌ها و شاخص‌ها.
- اگر pgvector در بسته نباشد (فایل `pgsql\PGVECTOR-NOT-INCLUDED.txt`)، بازیابی از ذخیره‌گاه برداری قابل‌حمل خود برنامه استفاده می‌کند؛ نتیجه یکی است و فقط در حجم‌های خیلی بزرگ کندتر است.

## ۱۱. ایمیل و پیامک

- ایمیل: سرور Exchange (SMTP) را در راه‌اندازی نخست یا «تنظیمات ← اعلان‌ها ← کانال‌های ایمیل» ثبت کنید. خواندن صندوق (IMAP) هم پشتیبانی می‌شود.
- پیامک: درگاه پیامک داخلی بانک (HTTP) را در کانال‌های پیام‌رسان ثبت کنید و میزبانش را به فهرست مجاز بیفزایید.
- وب‌هوک‌ها، اتصال‌های جریان کار و درگاه یکپارچه‌سازی هم فقط به میزبان‌های مجاز وصل می‌شوند.

## ۱۲. فهرست مجاز شبکه (شبکهٔ بسته)

در حالت شبکهٔ بسته (پیش‌فرض)، سرور فقط به این‌ها وصل می‌شود: خودِ سرور (loopback)، پایگاه داده، و میزبان‌های فهرست مجاز. هر تلاش دیگری با پیام فارسی رد و در گزارش و «سلامت سرور» ثبت می‌شود. این محدودیت در دو لایه اعمال می‌شود: لایهٔ درخواست‌های برنامه (پیام روشن به کاربر) و لایهٔ اتصال‌های شبکه (هیچ کتابخانه‌ای نمی‌تواند دورش بزند).

```
karizctl allow list
karizctl allow add mail.bank.local        (نام میزبان)
karizctl allow add *.svc.bank.local       (همهٔ زیردامنه‌ها)
karizctl allow add 10.20.0.0/16           (بازهٔ IP)
karizctl allow remove mail.bank.local
```
تغییر فهرست بی‌درنگ و بدون راه‌اندازی دوباره اعمال می‌شود. مدیر سامانه می‌تواند همین کار را در «مدیریت سامانه ← سلامت سرور» هم انجام دهد (افزودن و برداشتن، و «مجاز کن» کنار هر تلاش ردشده)؛ این کار تأیید دوبارهٔ هویت می‌خواهد و در ممیزی سامانه ثبت می‌شود.

## ۱۳. پشتیبان‌گیری و بازگردانی

- هر شب (پیش‌فرض ساعت ۰۱:۳۰؛ `backup.time` در `kariz.json`) پشتیبان کامل گرفته می‌شود: `pg_dump -Fc` پایگاه داده + فایل‌های پیوست. پیوست‌ها چون با هش نام‌گذاری می‌شوند فقط یک بار کپی می‌شوند (پوشهٔ `backups\blobs`).
- هر پشتیبان بررسی می‌شود (`pg_restore --list` کل بایگانی را می‌خواند و هر محتوای پیوستی که روی سرور هست باید در پشتیبان هم باشد)؛ نتیجه در «سلامت سرور» دیده می‌شود. پیوستی که محتوایش هرگز به سرور نرسیده (بارگذاری ردشده یا قرنطینه‌شده از برنامهٔ ویندوزی) فقط هشدار «پیوست‌های بی‌محتوا» می‌دهد و پشتیبان یا ارتقا را ناموفق نمی‌کند؛ فهرستش: `karizctl orphans`.
- پشتیبان خودکار ناموفق (مثلاً دیسک پر) پشت سر هم تکرار نمی‌شود: تلاش بعدی پس از ۱، ۲، ۴، ۸ و حداکثر ۱۶ ساعت است و در هر حال در زمان روزانهٔ بعدی دوباره امتحان می‌شود؛ زمان تلاش بعدی در «سلامت سرور» دیده می‌شود.
- ۱۴ پشتیبان خودکار آخر نگه داشته می‌شود (`backup.keep`)؛ پشتیبان‌های دستی و پیش از ارتقا را خودتان پاک کنید.
- **پشتیبان را بیرون از سرور هم نگه دارید**: `backup.dir` را مسیر یک سرور دیگر بگذارید (مثلاً `\\backup01\kariz`؛ حساب `NT SERVICE\KarizApp`، یعنی `DOMAIN\SERVERNAME$`، باید روی آن اجازهٔ نوشتن داشته باشد) یا پوشه را با ابزار پشتیبان‌گیری بانک بردارید.

```
karizctl backup                                   پشتیبان همین حالا
karizctl backups                                  فهرست
karizctl orphans                                  پیوست‌هایی که محتوایشان به سرور نرسیده است
karizctl restore D:\Kariz\backups\itsm-auto-20261110-013000 --yes
```
بازگردانی: نخست یک پشتیبان ایمنی می‌گیرد، سرویس برنامه را می‌بندد، پشتیبان را در یک پایگاه دادهٔ **تازه** بازمی‌گرداند و فقط اگر کامل موفق شد آن را جایگزین می‌کند (پایگاه دادهٔ قبلی با نام `kariz_before_restore_<زمان>` می‌ماند تا پس از اطمینان حذفش کنید)، پیوست‌های جاافتاده را برمی‌گرداند و سرویس را روشن می‌کند.

اگر زمان‌بند ویندوز را ترجیح می‌دهید: `install.ps1 -RegisterBackupTask` وظیفهٔ `KarizBackup` را می‌سازد (پشتیبان خودکار درون برنامه را با `backup.enabled: false` خاموش کنید).

## ۱۴. ارتقا

MSI نسخهٔ تازه را مثل نصب اجرا کنید (گرافیکی یا `msiexec /i … /qn`). نصب‌کننده:
۱. سرویس برنامه را می‌بندد و **پشتیبان ایمنی** `pg_dump -Fc` می‌گیرد (`backups\itsm-pre-upgrade-<زمان>`)؛ اگر پشتیبان ناموفق باشد ارتقا متوقف می‌شود و نسخهٔ فعلی کار می‌کند.
۲. فایل‌ها را جایگزین می‌کند (داده‌ها، پیکربندی، رمزها و درگاه‌ها می‌مانند). اگر ارتقا در میانه ناموفق شود، MSI نسخهٔ قبلی را برمی‌گرداند و سرویس‌هایش را دوباره روشن می‌کند.
۳. تنظیمات PostgreSQL را دوباره حساب می‌کند، مراحل تازهٔ ساختار پایگاه داده را اجرا می‌کند و سرویس‌ها را روشن می‌کند.

**بازگشت به نسخهٔ قبل**: MSI نسخهٔ قبلی را نصب کنید (پیش از آن نسخهٔ تازه را حذف کنید؛ داده‌ها می‌مانند) و پشتیبان ایمنی را بازگردانید: `karizctl restore D:\Kariz\backups\itsm-pre-upgrade-<زمان> --yes`.

## ۱۶. برنامهٔ ویندوز کارشناسان

برنامهٔ ویندوز کارشناسان با همان API به نسخهٔ سرور وصل و همگام می‌شود (کار آفلاین در شعبه، همگام‌سازی پس از اتصال):
۱. در برنامهٔ ویندوز «اتصال به حساب ابری» را انتخاب کنید و نشانی `https://kariz.bank.local` را با حساب خود وارد کنید.
۲. رایانه باید به گواهی سرور اعتماد کند: اگر گواهی از CA بانک است و ریشهٔ آن با GPO در «Trusted Root Certification Authorities» رایانه‌ها نصب است، کاری لازم نیست — برنامهٔ ویندوز بخش همگام‌سازی خود را با `--use-system-ca` اجرا می‌کند و فهرست CAهای ویندوز را می‌خواند. فقط در نسخه‌های قدیمی برنامه (Node پیش از ۲۲٫۱۵) متغیر محیطی سیستمی `NODE_EXTRA_CA_CERTS` را به فایل PEM ریشهٔ CA بانک (مثلاً `C:\ProgramData\BankCA\root.pem`) بگذارید (با GPO).
۳. اگر گواهی خودامضا است، پیش از هر چیز گواهی بانک را نصب کنید؛ گواهی خودامضا برای استفادهٔ عادی مناسب نیست.

## ۱۷. چک‌لیست امن‌سازی بانک

- [ ] گواهی از CA بانک نصب شده، نام سرور در SAN است، تاریخ انقضا در «سلامت سرور» پایش می‌شود.
- [ ] HTTP (درگاه ۸۰) فقط برای انتقال به HTTPS باز است یا با `HTTPPORT=0` بسته است.
- [ ] سرویس‌ها با حساب‌های مجازی `NT SERVICE\KarizDB` و `NT SERVICE\KarizApp` اجرا می‌شوند (نه LocalSystem).
- [ ] دسترسی پوشهٔ `C:\ProgramData\Kariz`: فقط Administrators، SYSTEM و حساب‌های سرویس؛ `kariz.json` را فقط مدیران و حساب برنامه می‌خوانند و `kariz-admin.json` (رمز مدیر PostgreSQL، که برنامه هرگز لازم ندارد) را فقط مدیران.
- [ ] PostgreSQL فقط روی `127.0.0.1`، `pg_hba.conf` فقط loopback با SCRAM.
- [ ] شبکهٔ بسته روشن است (`network.air_gapped: true`) و فهرست مجاز فقط میزبان‌های لازم را دارد؛ دیوارهٔ آتش بانک هم خروجی را محدود می‌کند.
- [ ] ثبت‌نام آزاد خاموش است؛ حساب‌ها از AD می‌آیند؛ حساب مدیر سامانه رمز قوی و کد بازیابیِ نگه‌داری‌شده دارد.
- [ ] «امنیت ورود و نشست‌ها» تنظیم شده (پیشنهاد بانک: بیکاری ۱۵ دقیقه، عمر ۱۰ ساعت، یک نشست برای هر نفر، تأیید دوباره پیش از کارهای حساس، کوکی فقط تا بستن مرورگر).
- [ ] ورود محلی فقط برای **حساب‌های اضطراری** باز است و دست‌کم دو حساب اضطراری (یکی مدیر راه‌اندازی) با رمز قوی در گاوصندوق نگه‌داری می‌شود؛ ورود با آن‌ها بررسی می‌شود.
- [ ] قفل پس از تلاش‌های ناموفق روشن است (آستانهٔ نام و نشانی) و هشدارهای قفل به مدیران می‌رسد.
- [ ] «گزارش ورودها» (هر سازمان) و بخش «ورود کاربران» در «سلامت سرور» مرور می‌شوند؛ کنترل‌کننده‌های دامنه با LDAPS و گواهی ریشهٔ بانک تعریف شده‌اند.
- [ ] `trusted_proxies` فقط پراکسی‌های بانک را دارد (یا خالی است) و کوکی نشست `Secure` است (`auth.cookie_secure: always`).
- [ ] رویدادهای امنیتی و ممیزی («مدیریت سامانه ← رویدادهای امنیتی»، «رویدادهای سازمان‌ها») مرور می‌شوند.
- [ ] پشتیبان‌ها هر شب گرفته و بررسی می‌شوند و نسخه‌ای **بیرون از سرور** دارند؛ بازگردانی دست‌کم هر فصل روی سرور آزمایشی تمرین می‌شود.
- [ ] ضدویروس روی پیوست‌ها روشن است (بخش ۲۰، `antivirus`) و پوشهٔ `quarantine` پایش می‌شود.
- [ ] به‌روزرسانی‌های امنیتی ویندوز و نسخه‌های تازهٔ برنامه طبق روال تغییرات بانک نصب می‌شوند.
- [ ] بستهٔ عیب‌یابی (`karizctl diagnostics`) بدون رمز و کلید است و فقط از همین راه بیرون فرستاده می‌شود.

## ۱۹. حذف

```
msiexec /x Kariz-Server-1.0.0.msi /qn                (داده‌ها می‌مانند)
msiexec /x Kariz-Server-1.0.0.msi /qn REMOVEDATA=1   (داده‌ها هم پاک می‌شوند)
```
حذف عادی سرویس‌ها، قاعدهٔ دیوارهٔ آتش، میان‌بر و متغیرهای محیطی را برمی‌دارد و پوشهٔ داده (پایگاه داده، پیوست‌ها، پشتیبان‌ها، پیکربندی) را نگه می‌دارد؛ نصب دوباره همان داده‌ها را به کار می‌گیرد.

## ۲۰. پیکربندی `kariz.json`

فایل در `C:\ProgramData\Kariz\kariz.json` است (مسیر دیگر با متغیر `ITSM_SERVER_CONFIG`). هر مقدار نامعتبر با مقدار پیش‌فرض جایگزین و در گزارش هشدار داده می‌شود. پس از تغییر دستی: `karizctl restart --rolling`.

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `public_url` | `https://<نام سرور>` | نشانی سامانه |
| `listen.https_port` / `http_port` / `redirect_http` | ۴۴۳ / ۸۰ / روشن | درگاه‌ها |
| `tls.pfx` + `tls.passphrase` یا `tls.cert` + `tls.key` | — | گواهی بانک (بدون آن: خودامضا) |
| `tls.hsts_max_age` | ۳۱۵۳۶۰۰۰ | HSTS (ثانیه) |
| `workers` / `pool_per_worker` | ۰ / ۰ | ۰ = خودکار (بخش ۳) |
| `db.max_connections` / `db.reserve` | ۲۰۰ / ۱۰ | سقف اتصال‌ها و ذخیرهٔ مدیران |
| `network.air_gapped` / `network.allow` | روشن / خالی | شبکهٔ بسته و فهرست مجاز |
| `uploads.max_mb` / `request_max_mb` | ۲۵ / ۱۰ | سقف پیوست و سقف هر درخواست دیگر |
| `antivirus.command` / `args` | خالی / آرگومان‌های Defender | مثلاً `C:\Program Files\Windows Defender\MpCmdRun.exe` با `-Scan -ScanType 3 -File {file} -DisableRemediation` |
| `antivirus.infected_codes` / `on_error` | `[2]` / `reject` | کد خروج «آلوده» و رفتار هنگام خطای ضدویروس |
| `backup.enabled` / `time` / `keep` / `dir` / `verify` | روشن / ۰۱:۳۰ / ۱۴ / `backups` / روشن | پشتیبان‌گیری |
| `log.level` / `max_mb` / `keep` / `slow_ms` | info / ۲۰ / ۱۰ / ۱۵۰۰ | گزارش‌ها و آستانهٔ درخواست کند |
| `trusted_proxies` | خالی | نشانی‌ها/بازه‌های IP پراکسی‌های معکوس (IIS، توزیع‌کنندهٔ بار). یک فهرست برای همه‌چیز: سرآیندهای `X-Forwarded-*` و `X-Real-IP` فقط از این‌ها (و خود سرور) پذیرفته می‌شوند و از بقیه دور ریخته می‌شوند؛ نشانی کاربر در ممیزی و قفل‌ها، HTTPS، و سرآیند کاربر SSO از راه پراکسی هم فقط از همین‌ها باور می‌شود. نام میزبان پذیرفته نیست. (`trust_proxy` قدیمی دیگر به کار نمی‌رود.) |
| `auth.directory_lan` | روشن | دسترسی به کنترل‌کننده‌های دامنه در شبکهٔ بانک (از راه فهرست مجاز) |
| `auth.cookie_secure` / `auth.cookie_samesite` | `always` / `Lax` | پرچم Secure کوکی نشست (`auto` فقط برای آزمایشگاه) و SameSite |

متغیرهای محیطی همین کلیدها (بر فایل مقدم‌اند): `ITSM_TRUSTED_PROXIES`، `ITSM_DIRECTORY_LAN`، `ITSM_COOKIE_SECURE`، `ITSM_COOKIE_SAMESITE` — همان متغیرهایی که نسخه‌های دیگر هم می‌خوانند.
