# ITSM (provisional name) — notes for Claude

Fully independent project in a sub-folder of this repository (own package.json and lockfile, Vercel project with Root Directory `itsm`, own Supabase project, own Windows installer). A Persian (RTL) enterprise IT service management application with AI, running as a **web app** (Vercel + Supabase) and a **Windows app** (Electron + embedded PostgreSQL/PGlite) kept in sync. This version is the platform foundation only — accounts, organisations, members and roles, AI, integrations, the platform owner's console, desktop ↔ cloud sync, the Windows app and CI; the ITSM modules come later. Read `docs/ARCHITECTURE_FA.md`, `docs/SETUP_FA.md`, `docs/DESKTOP_FA.md`, `docs/AI_FA.md` and `src/ui/ds/README.md` before larger changes.

- **Name.** The product's name is provisional. Use `APP_NAME`, `APP_NAME_EN`, `APP_TAGLINE`, `APP_TAGLINE_EN`, `APP_DESCRIPTION` from `src/shared/constants.ts`; never hard-code it (index.html and manifest.webmanifest are filled by `vite.config.ts`, the splash gets it in its query string, NSIS uses `${PRODUCT_NAME}`; `desktop/electron-builder.yml` repeats `APP_NAME_EN` and `tests/desktop.test.ts` checks it). Internal identifiers never derive from the name and stay when it changes: tables `sm_*`, PostgreSQL settings `itsm.*`, environment variables `ITSM_*`, IPC channels `itsm:*`, `window.itsm`, storage keys `itsm.*`, appId `app.itsm.desktop`, data dir `%APPDATA%\ITSM`. The mark is a placeholder monogram (`src/ui/components/brand.tsx`, rasterised into every icon by `desktop/scripts/make-icons.cjs`).
- **One codebase, two runtimes.** UI: `src/ui` (React 19, Ant Design 6 RTL, Tailwind 4; the design system in `src/ui/ds` — read its README before touching UI: `--ds-*` tokens only, no raw hex, Dusk used sparingly, type in Arad with every digit from «DS Num» and weights only from `--ds-weight-*`, tabular numbers that never ellipsize, `lucide-react` icons, Vite → `public/`). API: one Hono app (`src/server/app.ts`) mounted by Next.js on Vercel (`src/server/cloud.ts`, postgres.js) and by the desktop local server (`src/desktop/server.ts`, PGlite). Shared logic in `src/shared` (exact numbers with decimal.js — never floats for stored values; Jalali dates; validators; entity definitions; permissions; AI contracts).
- **Database:** tables `sm_*`, RLS on with no policies. Migrations are TS modules in `src/server/db/migrations` (idempotent SQL: `if not exists`, `create or replace`, `drop … if exists`; never edit a shipped one, add a new file and register it in `index.ts`), applied automatically on both runtimes; `npm run schema` regenerates `supabase/schema.sql` + `supabase/migrations/*.sql` (CI checks with `npm run check:schema`, `tests/schema.test.ts` runs every migration twice).
- **Sync:** engine tables sync automatically (pushes judged by the access provider and the engine's values, pulls filtered with tombstones, `bumpScopeEpoch` when what a member may read changes). Other aggregate roots carry `rev/updated_at/deleted_at/origin`; trigger `sm_sync_touch('<entity>')` assigns per-organisation revisions (cloud) or queues `sm_outbox` (desktop, `itsm.mode = 'desktop'`; nothing is queued while `itsm.applying = 'on'`). New synced roots need the trigger in a migration and an entry in `src/server/sync/registry.ts` (`tests/sync-registry.test.ts` checks both; deliberately local tables are listed there). Changing children must update the root row. Soft-delete roots. Numbered records keep `no` with a unique index named `*_no_*` (`nextNo` under the write lock); codes use an index whose name contains the column. Bump `SYNC_PROTOCOL` when a synced table gains a column or a new synced kind appears.
- **Record engine** (read `docs/spec/ENGINE.md` before touching records): every ITSM table — incidents, CIs, KB, and configuration like SLA definitions — is a `TableDef` in `src/shared/tables/<module>.ts` (listed in `MODULE_TABLES`); the engine generates its DDL (no migration for new tables/fields: `reconcileSchema`; run `npm run schema` after changing a TableDef), sync root, validation, history, events and the generic API `/api/o/:org/r/:table…` + `/meta/tables`. Server code uses `@server/engine` (`list/get/create/update/transition/remove/aggregate`, inside a transaction `createIn/updateIn/transitionIn/removeIn`, `systemCtx` for jobs) — never raw SQL writes to engine tables. Behaviour goes into `registerHooks(table, { beforeWrite, afterWrite, validateTransition, guards })` (same transaction, no model or network calls), reactions into `onRecordEvent(name, fn)` and background work into the job queue (`enqueue` inside the write's tx, `registerJobHandler`). Filters are conditions (`@shared/model/conditions`: one JSON language, `evaluate` ↔ `toSql` parity); every read path of your own starts from `readable(ctx, def, alias, params, env)` and strips fields with `visibleFields` — all security goes through the access provider (`src/server/access/provider.ts`). Concurrency token is `version` (not `rev`); `number` for people, `id` for machines.
- **Record UI** (read `docs/spec/UI_RECORDS.md` before building a module's screens): `src/ui/records` renders any engine table — `RecordList` (views, filters, columns, bulk, inline edit, board/calendar/timeline), `RecordPage` (header, form with UI policies, conflicts, side panel, activity stream and composer), `FieldInput`/`FieldValue`, `FilterBuilder`. A module registers its tables with `recordModule()` (`records/module.tsx`) and adds behaviour through `registerRecordExtensions` (presets, header/side-panel/tab widgets, composer slots `cannedResponses`/`aiDraft`, UI policies); every table also works at `r/:table`. Pure logic lives in `records/model` (tests `tests/ui-records-*.test.ts`).
- **Flows** (no-code automation; read `docs/spec/services/flows.md` before touching it): flows, versions, HTTP connections and schedules are engine tables (`src/shared/tables/flows.ts`, area `flows`); runs, step logs, waits and timers are runtime tables of the executing runtime (`sm_flow_*`, never synced). The executor (`src/server/modules/flows`) persists every step (record steps inside their write transaction), resumes waits through jobs and guards steps per run and the depth of flows started by flows. Other services plug in with `registerFlowStepHandler` (the `notify` and `approval` stand-ins are replaced by registering), `registerFlowSkill`, `setFlowBusinessClock`, `resumeFlowWait`, `startCatalogFlows`; the shared model (`src/shared/flows`: node catalogue, data pills, Jalali schedules, validator) serves the designer (`src/ui/modules/flows`, @xyflow/react + dagre) and the server alike.
- **Writes** only inside `ctx.write(async (tx) => …)` using `tx` (PGlite is single-connection; the organisation's write lock and its platform status — read-only, suspended — are enforced there). Check permissions with `ctx.need(area, level)` on the server and `can()` in the UI. Record security-relevant actions with `securityEvent()` and organisation changes with `audit()`.
- **Access model (provisional):** AREAS `settings`, `users`, `integrations`, `ai`, `reports`, `work` (generic records: «کار», saved views); roles owner, admin («مدیر», the owner's deputy), member, viewer, with per-area overrides (`src/shared/permissions.ts`, one rule `memberChangeRule` for the members API, pushed member rows and the members page). A platform admin (`is_platform_admin`) who is not a member has NO access except through an audited support session (`src/server/modules/platform`, `context.ts`). `tests/permissions.test.ts` checks every area named on the server, in the sync registry and in the UI. A new ITSM access model replaces this later.
- **ITSM access model** (read `docs/spec/ACCESS.md` before touching access; admin guide `docs/ACCESS_FA.md`): installed as the engine's provider everywhere (`src/server/access`, `installAccessModel()` in `routes/modules.ts`). Org structure, groups, workspaces, member profiles and roles are engine tables (`src/shared/tables/access.ts`); roles grant read/create/write/delete/approve/admin per area (`@shared/access`: `registerArea` for a module's area) with scopes none < own < group < unit < unit_tree < domain < all; built-in roles live in code (an org row replaces one). Declare a table's scope columns in `TableDef.scope` (own, requester, group, watchers, requesterWritable, requesterTransitions, confidentialGroup, public) and field groups on fields. The SQL form (`readSql`) and the JS form (`canReadRow`/`writeMode`) must stay equal (`tests/access-parity.test.ts`). Notifications use `readersOf`/`memberCtx`, retrieval `readableIds`; never read engine tables around the provider. Members without ITSM roles keep their membership role's access («حالت پیشین»); the membership role still governs the platform's own pages (`ctx.can`).
- **UI conventions:** every page starts with `PageHeader`; use the kit in `src/ui/components/*` (`ServerTable`, `EntityPage`, `NumberInput`, `DateInput` (Jalali), `RefSelect`, `JDate`, `StatusTag`, `Card`, `Note`, `EmptyState`); all text Persian; Persian digits via `faDigits`/`formatNumber`; logical spacing utilities; AntD v6 props (`Drawer size`, `destroyOnHidden`, `Alert title`, `Tag variant`). Explanations live in «راهنما» (`src/ui/modules/settings/Help.tsx`), not on the pages.
- **Modules** register nav groups, spaces, routes and palette searches in `src/ui/modules/<module>/index.tsx` (assembled in `src/ui/modules/registry.tsx`), API routes in `src/server/routes/<module>.ts` (mounted in `src/server/routes/modules.ts`), master data in `ENTITIES` (`src/shared/entities.ts`, generic CRUD and spreadsheet import), synced aggregates with `registerAggregate`, AI tools with `registerTool` and proposal executors with `registerProposalExecutor`, webhook topics with `registerTopicHandler`, live query keys with `registerLiveQueries`, assistant starters in `src/ui/ai/assistant/prompts.ts` and page context in `context.ts`. `tests/fixtures/module.ts` is a stand-in module registered exactly this way; tests of the generic machinery use it.
- **Desktop:** Electron main/preload/splash in `desktop/src` (`main.ts` sets `%APPDATA%\ITSM` explicitly, runs the local server in a utility process, `--smoke-test` with `ITSM_SMOKE`/`ITSM_SMOKE_OUT`/`ITSM_DATA_DIR`; `preload.ts` exposes only `window.itsm` and `itsm:*` IPC; `splash.html` is the 520×320 frameless splash driven through `itsm.step/progress/status/version/ready`), Windows art in `desktop/build` (`cd desktop && npm run icons`), packaging `desktop/electron-builder.yml` (NSIS, Persian, `ITSM-Setup-x.y.z.exe`, installs to `%LOCALAPPDATA%\Programs\ITSM\ITSM.exe`), build `node scripts/build-desktop.mjs` then `cd desktop && npx electron-builder --win`. CI `.github/workflows/itsm.yml` (repository root) builds on Windows, smoke-tests and publishes to Releases (`itsm-vX.Y.Z` from `main`, `itsm-preview` otherwise).
- **AI** (docs/AI_FA.md): per-organisation connections and keys (encrypted, never returned) in `src/server/modules/ai`; Claude only through `@anthropic-ai/sdk` 1.x (no temperature/top_p/top_k, adaptive thinking, no forced tool_choice, replay native content unchanged, append-only history); never call a model inside `ctx.write`/`db.tx`. Assistant tools (`modules/ai/tools`) must repeat their route's permission and module checks, return bounded data with units and Jalali periods, and never write — writes are proposals confirmed by a person (`tools/proposals.ts`). Numbers come from code (`analytics`), the model only narrates. AI tables are LOCAL_ONLY (each runtime has its own keys). Shared contracts: `src/shared/ai/{types,api}.ts`. Test mode: `ITSM_AI_FAKE=1`.
- **Outbound calls** go through `ctx.cfg.fetch` with a timeout and a Persian message naming the service; on the web version AI calls go through the SSRF guard (`modules/ai/net.ts`).
- Commands: `npm run typecheck` · `npm test` · `npm run check:schema` · `npm run build` (must pass with no env vars) · `npm run start:local` (desktop flavour without Electron) · `node scripts/ui-shots.mjs` (screenshots of every page in light/dark/phone with an error report; `--base <url>` for a running server).
