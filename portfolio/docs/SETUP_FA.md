# راه‌اندازی پورتفولیو (فقط GitHub + Vercel + Google AI Studio — همه رایگان)

پورتفولیو در پوشه‌ی `portfolio` همین مخزن است و یک پروژه‌ی مستقل Next.js به حساب می‌آید؛ به Task Flow، سایت پارس یا سلین وابسته نیست.

**پایگاه داده ندارد.** هر چه سایت باید نگه دارد در یک **مخزن خصوصی GitHub** است:

| چه چیزی | کجا |
|---|---|
| محتوای سایت، پروژه‌ها و دانش اصلی دستیار | همین مخزن کد (`src/content/`) |
| درخواست‌های همکاری و دمو | هر درخواست یک **Issue** در مخزن داده؛ هر پیام یک دیدگاه |
| تنظیمات پنل «اتصالات» (کلید هوش مصنوعی، ربات تلگرام یا بله) | فایل `settings.json` در مخزن داده؛ کلیدها رمز شده |
| دانش اضافه‌ی دستیار | فایل `knowledge.md` در مخزن داده |
| پرسش‌هایی که دستیار پاسخشان را نداشت | یک Issue با برچسب `assistant-unanswered` |

سایت بدون هیچ تنظیمی هم build می‌شود و بالا می‌آید؛ پنل، درخواست‌ها و دستیار با گام‌های زیر روشن می‌شوند. کل کار حدود ۱۵ دقیقه است.

---

## ۱. مخزن خصوصی داده در GitHub

1. [github.com/new](https://github.com/new) را باز کنید.
2. **Repository name:** مثلاً `portfolio-data`.
3. حتماً **Private** را انتخاب کنید. نام و اطلاعات تماس بازدیدکننده‌ها اینجا ذخیره می‌شود.
   > **هرگز این مخزن را عمومی نکنید، حتی برای چند دقیقه.** با عمومی شدن، همه‌ی درخواست‌های قبلی (نام، ایمیل، تلفن، متن) فوراً برای همه دیده می‌شوند و این را نمی‌شود پس گرفت. سایت حداکثر یک دقیقه بعد نوشتن در مخزن و نمایش صفحه‌های پیگیری را متوقف می‌کند، ولی آنچه قبلاً ذخیره شده دیگر محرمانه نیست. اگر اشتباهی پیش آمد: فوراً Private کنید، در GitHub ببینید کسی fork نکرده باشد، و به بازدیدکننده‌هایی که اطلاعاتشان دیده شده خبر بدهید.
4. **Create repository**. لازم نیست README یا فایلی بسازید؛ پنل سایت بعداً خودش فایل‌ها و برچسب‌ها را می‌سازد.

## ۲. توکن محدود GitHub (Fine-grained)

این توکن فقط به همان مخزن داده دسترسی دارد، نه به بقیه‌ی مخزن‌هایتان.

1. [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new) را باز کنید (Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token).
2. **Token name:** مثلاً `portfolio-site`.
3. **Expiration:** یک سال (یا بیشتر، اگر GitHub اجازه بدهد). تاریخ انقضا در پنل «اتصالات» نمایش داده می‌شود و دو هفته مانده به انقضا هشدار می‌دهد.
4. **Repository access:** گزینه‌ی **Only select repositories** و فقط `portfolio-data`.
5. **Permissions → Repository permissions:**
   - **Contents:** Read and write
   - **Issues:** Read and write
   - **Metadata:** Read-only (خودکار)
6. **Generate token** و توکن (`github_pat_…`) را کپی کنید. فقط همین یک بار نمایش داده می‌شود.

## ۳. پروژه‌ی Vercel

1. [vercel.com/new](https://vercel.com/new) → مخزن `tahahajiaghajani/ai` را **Import** کنید. اگر مخزن را نمی‌بینید: **Adjust GitHub App Permissions** و دسترسی Vercel به این مخزن را بدهید.
2. **Project Name:** مثلاً `taha-portfolio`. این نام نشانی اولیه را می‌سازد (`taha-portfolio.vercel.app`).
3. **Root Directory** → **Edit** → پوشه‌ی `portfolio` را انتخاب کنید. **این مهم‌ترین گام است.** Framework Preset خودکار Next.js می‌شود؛ Build و Install Command را دست نزنید.
4. **Environment Variables** را اضافه کنید و برای همه، در ستون Environments **فقط Production** را نگه دارید (تیک Preview و Development را بردارید):

| نام | مقدار | |
|---|---|---|
| `GITHUB_TOKEN` | توکن گام ۲ (`github_pat_…`) | ضروری |
| `GITHUB_REPO` | `tahahajiaghajani/portfolio-data` (نام کاربری/نام مخزن داده) | ضروری |
| `ADMIN_PASSWORD` | یک رمز قوی برای پنل `/admin` | ضروری |
| `APP_SECRET` | یک رشته‌ی **تصادفی** دست‌کم ۳۲ نویسه‌ای، مثلاً خروجی `openssl rand -hex 32` یا یک گذرواژه‌ساز. کوتاه‌تر از ۳۲ نویسه پذیرفته نمی‌شود | ضروری |
| `NEXT_PUBLIC_SITE_URL` | نشانی نهایی سایت (بعد از گام ۷) | بعداً |
| `GEMINI_API_KEY` | لازم نیست؛ کلید را در پنل «اتصالات» وارد کنید | اختیاری |

5. **Deploy**. چند دقیقه بعد سایت روی `https://<نام پروژه>.vercel.app` بالا است.

> **چرا فقط Production:** Vercel برای هر شاخه‌ای از این مخزن که پوشه‌ی `portfolio` را تغییر دهد یک Preview می‌سازد. اگر متغیرها در Preview هم باشند، کدِ هنوز بازبینی‌نشده‌ی آن شاخه با توکن واقعی روی درخواست‌های واقعی می‌نویسد. Previewها بدون این متغیرها بالا می‌آیند و فقط فرم، پنل و دستیارشان خاموش است. اگر Preview کامل لازم دارید، یک مخزن داده‌ی خصوصی و توکن جدا (مثلاً `portfolio-data-test`) بسازید و فقط آن‌ها را برای Preview بگذارید. Deployment Protection پروژه (Settings → Deployment Protection) را هم روشن نگه دارید.

> **APP_SECRET را گم نکنید و بی‌دلیل عوض نکنید.** کلیدهایی که در پنل ذخیره می‌کنید با آن رمز می‌شوند و پیوندهای پیگیری درخواست با آن امضا می‌شوند. اگر مجبور شدید عوضش کنید، مقدار قبلی را در `APP_SECRET_PREVIOUS` بگذارید: کلیدهای ذخیره‌شده خوانده می‌شوند و پیوندهای پیگیری قدیمی هم کار می‌کنند. همه‌ی نشست‌های پنل بسته می‌شوند و باید دوباره وارد شوید.

**پیشنهاد (اختیاری):** این مخزن چند سایت دارد و Vercel با هر push همه را می‌سازد. برای اینکه پروژه‌ی پورتفولیو فقط با تغییر پوشه‌ی خودش ساخته شود: پروژه → `Settings → Build and Deployment → Ignored Build Step` → **Custom** و این دستور را بگذارید:

```bash
git diff --quiet "${VERCEL_GIT_PREVIOUS_SHA:-HEAD^}" HEAD -- .
```

این دستور داخل همان Root Directory (یعنی `portfolio`) اجرا می‌شود؛ پس پوشه `.` است، نه `portfolio`. اگر چیزی در این پوشه عوض نشده باشد ساخت لغو می‌شود، و اگر Vercel نتواند مقایسه کند ساخت انجام می‌شود (بی‌خطر).

## ۴. پنل «اتصالات»: وصل کردن و آزمایش همه‌چیز

1. `https://<سایت>/admin` را باز کنید و با `ADMIN_PASSWORD` وارد شوید. این صفحه در منو نیست و در موتورهای جست‌وجو نمایه نمی‌شود.
2. به **اتصالات** بروید. بالای صفحه نوشته چند مورد از شش مورد آماده است. هر کارت وضعیت خودش را دارد: «آماده»، «نیاز به توجه»، «مشکل دارد» یا «خاموش / اختیاری».
3. **مخزن داده (GitHub):** بررسی می‌کند توکن معتبر است، مخزن پیدا می‌شود، **خصوصی** است و Issues در آن روشن است. سپس روی **آماده‌سازی مخزن** بزنید تا این‌ها ساخته شوند:
   - `settings.json`
   - `knowledge.md`
   - یک README
   - برچسب‌ها (`request`، `status:*`، `kind:*`، `priority:*`، `assistant-unanswered`)

   اجرای دوباره‌اش بی‌خطر است.
4. **هوش مصنوعی (Google AI Studio):**
   1. در [aistudio.google.com/apikey](https://aistudio.google.com/apikey) با حساب Google وارد شوید، **Create API key** بزنید و کلید را کپی کنید. کلیدهای تازه با `AQ.` و کلیدهای قدیمی‌تر با `AIza` شروع می‌شوند؛ هر دو کار می‌کنند. لایه‌ی رایگان برای این سایت کافی است.
      > **حریم خصوصی در لایه‌ی رایگان:** طبق شرایط Gemini API، Google محتوای فرستاده‌شده به سرویس‌های رایگان (پیام‌های چت و متن درخواست‌ها) را برای بهبود محصولاتش به کار می‌برد و ممکن است بازبین انسانی آن را بخواند. سایت برای همین نام و سازمان بازدیدکننده را به مدل نمی‌فرستد و در فرم و چت می‌نویسد «اطلاعات محرمانه ننویسید». اگر این برایتان پذیرفتنی نیست، در AI Studio برای همان پروژه Billing را روشن کنید (Paid tier)؛ آن‌وقت Google محتوا را برای بهبود محصولاتش استفاده نمی‌کند.
   2. کلید را در کادر «کلید API» بچسبانید و **آزمایش اتصال** بزنید. یک درخواست واقعی کوچک فرستاده می‌شود و نام مدلی که پاسخ داد و زمان پاسخ نمایش داده می‌شود؛ اگر خطا بدهد، دلیلش به فارسی می‌آید.
   3. **ذخیره**. کلید پیش از ذخیره با `APP_SECRET` رمز می‌شود و فقط چهار نویسه‌ی آخرش در پنل دیده می‌شود.
   4. «مدل‌های ترجیحی» اختیاری است. بدون آن، این زنجیره‌ی رایگان به ترتیب امتحان می‌شود و اگر یکی شلوغ یا تمام‌شده باشد سراغ بعدی می‌رود: `gemini-3.5-flash-lite` ← `gemini-3.1-flash-lite` ← `gemini-3.6-flash` ← `gemini-3.8-flash`.
   5. با برداشتن تیک «دستیار روشن باشد»، دستیار پیام «در دسترس نیست» می‌دهد و درخواست‌ها بی‌تحلیل ثبت می‌شوند.
5. **اعلان درخواست‌ها (تلگرام / بله):** گام ۵ را ببینید. پس از ذخیره، **ارسال پیام آزمایشی** را بزنید.
6. کارت‌های هوش مصنوعی و اعلان هر بار که صفحه باز می‌شود **بررسی زنده** هم می‌کنند (بی‌آنکه سهمیه یا پیامی مصرف شود): کلید با Google سنجیده می‌شود، ربات با `getMe` و شناسه‌ی گفتگو با `getChat`. موارد اختیاری که تنظیم نکرده‌اید «خاموش / اختیاری» نشان داده می‌شوند، نه خطا.
7. **امنیت پنل**، **نشانی سایت** و **میزبانی (Vercel)** فقط وضعیت را نشان می‌دهند:
   - محیط و منطقه‌ی اجرا
   - نسخه‌ی منتشرشده (commit و شاخه)
   - تنظیم بودن `NEXT_PUBLIC_SITE_URL`

پس از هر تغییر در Vercel (متغیر تازه یا تغییر مقدار)، یک بار **Redeploy** کنید و در پنل **بررسی دوباره** بزنید. تغییرهای خود پنل فوری اثر می‌کنند و Redeploy لازم ندارند.

## ۵. ربات تلگرام یا بله (اختیاری)

هر درخواست تازه و هر پیام بازدیدکننده، همراه خلاصه‌ی فارسی هوش مصنوعی و پیوند پنل، برایتان فرستاده می‌شود.

**تلگرام:**
1. با [@BotFather](https://t.me/BotFather) گفتگو کنید، `/newbot` بزنید و توکن (`123456789:AA…`) را بگیرید.
2. به ربات تازه یک پیام بدهید (مثلاً `/start`).
3. `https://api.telegram.org/bot<TOKEN>/getUpdates` را در مرورگر باز کنید و عدد `chat.id` را بردارید.
4. در پنل → اتصالات → اعلان، کانال «تلگرام»، توکن و شناسه‌ی گفتگو را وارد و **ذخیره** کنید.

**بله:**
1. در بله به **@botfather** پیام بدهید، «ساخت بازوی جدید» را بزنید، نام و نام کاربری بازو را بدهید (نام کاربری باید به `bot` ختم شود) و توکن را کپی کنید.
2. به بازوی تازه یک پیام بدهید.
3. `https://tapi.bale.ai/bot<TOKEN>/getUpdates` را باز کنید و عدد `chat.id` را بردارید.
4. در پنل کانال «بله» را انتخاب کنید و توکن و شناسه را ذخیره کنید.

> **چرا ربات لازم است:** Issueها و دیدگاه‌ها را سایت با توکن خود شما می‌سازد، و GitHub برای کارهای خودتان اعلان (وب یا موبایل) نمی‌فرستد، حتی اگر مخزن را Watch کرده باشید. تنها راه نیمه‌کاره ایمیل است: در GitHub → `Settings → Notifications` گزینه‌ی «Include your own updates» را روشن کنید. برای باخبر شدن فوری، ربات تلگرام یا بله بهترین راه است.

## ۶. کار روزانه با پنل

- **درخواست‌ها** (`/admin`): فهرست با فیلتر وضعیت. هر درخواست کد `TA-XXXXXX` دارد و این‌ها را نشان می‌دهد:
  - تحلیل هوش مصنوعی: نوع، اولویت، تناسب با کار شما و خلاصه‌ی فارسی
  - پیش‌نویس پاسخ آماده
  - گفتگو با بازدیدکننده

  پاسخی که از پنل می‌فرستید در صفحه‌ی پیگیری بازدیدکننده دیده می‌شود. وضعیت را عوض کنید (تازه، در حال بررسی، پاسخ داده شد، جلسه هماهنگ شد، بسته) یا «تحلیل دوباره» بزنید. «بسته» Issue را هم در GitHub می‌بندد.
- **یادداشت خصوصی:** هر دیدگاهی که مستقیم در GitHub زیر Issue بنویسید فقط در پنل (با برچسب «یادداشت خصوصی») دیده می‌شود و هرگز به بازدیدکننده نمی‌رسد.
- **پرسش‌های بی‌پاسخ:** فقط پرسش‌هایی نگه داشته می‌شوند که دستیار پاسخشان را نداشت. گفتگوهای کامل ذخیره نمی‌شوند. پنل تازه‌ترین ۱۰۰ مورد را نشان می‌دهد؛ وقتی issue آن به ۱۵۰۰ دیدگاه برسد بسته و issue تازه‌ای شروع می‌شود و پنل پیوند هر دو را می‌دهد.
- **دانش دستیار:** نکته‌های اضافه، مثل پروژه‌ی تازه یا زمان در دسترس بودن، را اینجا یا مستقیم در `knowledge.md` مخزن داده بنویسید. افزودن و حذف از پنل فوری اثر می‌کند. اگر فایل را مستقیم در GitHub ویرایش کردید، در همین صفحه **تازه‌سازی از GitHub** را بزنید. دانش اصلی دستیار همیشه از محتوای خود سایت ساخته می‌شود.

## ۷. دامنه‌ی اختصاصی (اختیاری)

1. Vercel → پروژه → **Settings → Domains** → **Add** → دامنه را وارد کنید و رکوردهای DNS را که Vercel نشان می‌دهد نزد ثبت‌کننده‌ی دامنه بگذارید.
2. پس از سبز شدن، `NEXT_PUBLIC_SITE_URL` را روی نشانی دامنه (مثلاً `https://taha-aghajani.ir`) بگذارید و **Redeploy** کنید. پیوندهای اشتراک، نقشه‌ی سایت و پیوندهای اعلان از آن ساخته می‌شوند.

## ۸. محدودیت‌ها (صادقانه)

- **محدودیت نرخ** در حافظه‌ی همان نمونه‌ی سرور نگه داشته می‌شود:
  - هر بازدیدکننده: ۲۰ پیام در ۱۰ دقیقه و ۸۰ پیام در روز
  - کل سایت: `AI_DAILY_LIMIT` فراخوان در روز در هر نمونه (پیش‌فرض ۱۰۰۰)

  این جلوی سیل درخواست را می‌گیرد، ولی سقف واقعی همان سهمیه‌ی رایگان کلید Google است.
- **سقف GitHub:** حدود ۵۰۰۰ درخواست در ساعت برای **کل حساب GitHub شما**، که با توکن‌ها و اپ‌های دیگرتان مشترک است. برای یک پورتفولیو بسیار بیشتر از نیاز است و پنل مقدار باقی‌مانده را نشان می‌دهد. پیوندهای پیگیری جعلی پیش از هر درخواست به GitHub رد می‌شوند، بازدید هر نفر محدود است، و صفحه‌ی پیگیری هر درخواست تا ۵ دقیقه کش می‌شود (هر پاسخ یا تغییر وضعیت از سایت آن را فوراً تازه می‌کند؛ فقط ویرایش مستقیم در GitHub تا ۵ دقیقه دیرتر دیده می‌شود).
- **تأخیر تنظیمات:** تنظیمات و دانش اضافه کش می‌شوند. هر چه از خود پنل ذخیره شود فوری اثر می‌کند. ویرایش مستقیم در GitHub اما تا وقتی «تازه‌سازی از GitHub» را نزنید، چند دقیقه یا تا پرسش‌های بعدی طول می‌کشد.
- **گفتگوها:** گفتگوهای کامل نگه داشته نمی‌شوند؛ فقط پرسش‌های بی‌پاسخ، تا دانش دستیار را کامل کنید.
- **انقضای توکن:** پیش از انقضا، توکن تازه بسازید، در Vercel جایگزین کنید و Redeploy کنید.

| «توکن GitHub نامعتبر یا منقضی است» | توکن تازه بسازید (گام ۲)، در Vercel عوض و Redeploy کنید |
| «GitHub نوشتن را نپذیرفت (403)» | دسترسی‌های Contents و Issues توکن باید **Read and write** باشند |
| «مخزن عمومی است!» | فوراً GitHub → مخزن داده → Settings → Danger Zone → Change visibility → Private. درخواست‌های قبلی در این مدت عمومی بوده‌اند (گام ۱ را ببینید) |
| «settings.json خوانده نشد» | فایل را در GitHub درست کنید (JSON معتبر). تا آن موقع سایت با آخرین تنظیماتی که خوانده کار می‌کند، و پس از راه‌اندازی دوباره دستیار و اعلان خاموش می‌مانند. پاک کردن فایل همه‌چیز را به پیش‌فرض برمی‌گرداند و کلید و توکن ذخیره‌شده را هم پاک می‌کند |
| آزمایش هوش مصنوعی: «کلید پذیرفته نشد» | کلید تازه در AI Studio بسازید؛ کلیدی که جایی منتشر شده باشد را Google غیرفعال می‌کند |
| «به سقف درخواست‌های GitHub رسیده‌ایم» | چند دقیقه صبر کنید؛ سقف هر ساعت دوباره پر می‌شود |
| امنیت پنل: «APP_SECRET کوتاه است» | یک رشته‌ی تصادفی دست‌کم ۳۲ نویسه‌ای بگذارید و Redeploy کنید |
| اعلان: «شناسه‌ی گفتگو اشتباه است…» | به ربات `/start` بدهید و `chat.id` را دوباره از `getUpdates` بردارید |
| اعلان: «توکن ذخیره‌شده مال ربات تلگرام/بله است» | با عوض کردن کانال، توکن ربات همان سرویس را هم وارد کنید؛ توکن یک سرویس هرگز به سرویس دیگر فرستاده نمی‌شود |

| فرم درخواست: «هنوز راه‌اندازی نشده» | `GITHUB_TOKEN`، `GITHUB_REPO` و `APP_SECRET` (دست‌کم ۳۲ نویسه) باید در Vercel برای Production باشند و پس از افزودن Redeploy شده باشد |
| صفحه‌ی ورود پنل به‌جای فرم، پیام تنظیمات نشان می‌دهد | همان پیام می‌گوید کدام کم است: `ADMIN_PASSWORD`، `APP_SECRET`، یا کوتاه بودن `APP_SECRET` |
| ورود به پنل: «رمز درست نیست…» | رمز را با `ADMIN_PASSWORD` در Vercel مقایسه کنید؛ پس از تغییرش Redeploy لازم است |

## ۱۰. امنیت پنل

- **خروج از همه‌ی دستگاه‌ها:** `ADMIN_PASSWORD` را در Vercel عوض و Redeploy کنید؛ همه‌ی نشست‌های قبلی همان لحظه باطل می‌شوند (نشست‌ها به رمز گره خورده‌اند). «خروج» فقط همان مرورگر را بیرون می‌برد.
- **اگر فکر می‌کنید `APP_SECRET` لو رفته:**
  1. مقدار فعلی را در `APP_SECRET_PREVIOUS` بگذارید و یک `APP_SECRET` تازه بسازید.
  2. Redeploy کنید.
  3. در پنل → اتصالات، در کارت هوش مصنوعی و کارت اعلان یک بار **ذخیره** بزنید (کادرها را خالی بگذارید)؛ کلید و توکن ذخیره‌شده با رمز تازه دوباره رمز می‌شوند. تا این کار انجام نشود، کارت «امنیت پنل» هشدار می‌دهد. اگر خود کلید یا توکن هم ممکن است لو رفته باشد، در AI Studio و BotFather آن‌ها را هم عوض کنید و مقدار تازه را وارد کنید.
  4. وقتی هشدار کارت امنیت رفت، و ترجیحاً پس از چند هفته، `APP_SECRET_PREVIOUS` را پاک کنید (پیوندهای پیگیری قدیمی از آن به بعد کار نمی‌کنند).
- **توکن GitHub** فقط به مخزن داده دسترسی دارد. اگر لو رفت، در GitHub → Settings → Developer settings آن را Revoke کنید، توکن تازه بسازید و در Vercel بگذارید.

## ۱۱. افزودن یا ویرایش پروژه‌ها

- هر پروژه یک فایل در `src/content/projects/` است (فارسی و انگلیسی کنار هم) و در `src/content/projects/index.ts` به فهرست اضافه می‌شود؛ ترتیب همان ترتیب نمایش است. `tier: "lab"` پروژه را از ریل اصلی بیرون می‌برد و فقط در فهرست کامل نشان می‌دهد.
- تصویرها در `public/media/work/<پروژه>/` (WebP، عرض حداکثر ۱۹۲۰) و ویدئوها H.264 بدون صدا با پوستر.
- دستیار هوش مصنوعی پروژه‌ی تازه را خودکار یاد می‌گیرد؛ دانشش از همین فایل‌ها ساخته می‌شود.
- پیش از push: `npm run typecheck` · `npm test` · `npm run build` (آزمون‌ها کامل بودن هر دو زبان و وجود همه‌ی فایل‌های رسانه را بررسی می‌کنند).

## ۱۲. اجرای محلی

```bash
cd portfolio
npm ci
npm run dev          # http://localhost:3000 و http://localhost:3000/en
```

برای پنل، درخواست‌ها و دستیار، یک فایل `.env.local` از روی `.env.example` بسازید و همان چهار متغیر ضروری را بگذارید. برای آزمایش، همیشه یک مخزن خصوصی جدا و توکن جدا بسازید، نه مخزن داده‌ی واقعی. به همین دلیل متغیرهای Vercel فقط برای Production هستند و `vercel env pull` چیزی از آن‌ها روی رایانه‌تان نمی‌آورد.
