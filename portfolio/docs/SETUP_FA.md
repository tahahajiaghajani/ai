# راه‌اندازی پورتفولیو (فقط GitHub + Vercel + Google AI Studio — همه رایگان)

پورتفولیو در پوشه‌ی `portfolio` همین مخزن است و یک پروژه‌ی مستقل Next.js به حساب می‌آید؛ به Task Flow، سایت پارس یا سلین وابسته نیست.

**پایگاه داده ندارد.** هر چه سایت باید نگه دارد در یک **مخزن خصوصی GitHub** است:

| چه چیزی | کجا |
|---|---|
| محتوای سایت، پروژه‌ها و دانش اصلی دستیار | همین مخزن کد (`src/content/`) |
| درخواست‌های همکاری و دمو | هر درخواست یک **Issue** در مخزن داده؛ هر پیام یک دیدگاه |
| تنظیمات پنل «اتصالات» (کلید هوش مصنوعی، ربات تلگرام یا بله) | فایل `settings.json` در مخزن داده؛ کلیدها رمز شده |
| دانش اضافه‌ی دستیار | فایل `knowledge.md` در مخزن داده |
| پرسش‌هایی که دستیار پاسخشان را نداشت | یک Issue با برچسب `assistant-unanswered` |

سایت بدون هیچ تنظیمی هم build می‌شود و بالا می‌آید؛ پنل، درخواست‌ها و دستیار با گام‌های زیر روشن می‌شوند. کل کار حدود ۱۵ دقیقه است.

---

## ۱. مخزن خصوصی داده در GitHub

1. [github.com/new](https://github.com/new) را باز کنید.
2. **Repository name:** مثلاً `portfolio-data`.
3. حتماً **Private** را انتخاب کنید. اطلاعات تماس بازدیدکننده‌ها اینجا ذخیره می‌شود؛ سایت اگر مخزن عمومی باشد هیچ درخواستی در آن نمی‌نویسد.
4. **Create repository**. لازم نیست README یا فایلی بسازید؛ پنل سایت بعداً خودش فایل‌ها و برچسب‌ها را می‌سازد.

## ۲. توکن محدود GitHub (Fine-grained)

این توکن فقط به همان مخزن داده دسترسی دارد، نه به بقیه‌ی مخزن‌هایتان.

1. [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new) را باز کنید (Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token).
2. **Token name:** مثلاً `portfolio-site`.
3. **Expiration:** یک سال (یا بیشتر، اگر GitHub اجازه بدهد). تاریخ انقضا در پنل «اتصالات» نمایش داده می‌شود و دو هفته مانده به انقضا هشدار می‌دهد.
4. **Repository access:** گزینه‌ی **Only select repositories** و فقط `portfolio-data`.
5. **Permissions → Repository permissions:**
   - **Contents:** Read and write
   - **Issues:** Read and write
   - **Metadata:** Read-only (خودکار)
6. **Generate token** و توکن (`github_pat_…`) را کپی کنید. فقط همین یک بار نمایش داده می‌شود.

## ۳. پروژه‌ی Vercel

1. [vercel.com/new](https://vercel.com/new) → مخزن `tahahajiaghajani/ai` را **Import** کنید. اگر مخزن را نمی‌بینید: **Adjust GitHub App Permissions** و دسترسی Vercel به این مخزن را بدهید.
2. **Project Name:** مثلاً `taha-portfolio`. این نام نشانی اولیه را می‌سازد (`taha-portfolio.vercel.app`).
3. **Root Directory** → **Edit** → پوشه‌ی `portfolio` را انتخاب کنید. **این مهم‌ترین گام است.** Framework Preset خودکار Next.js می‌شود؛ Build و Install Command را دست نزنید.
4. **Environment Variables** را اضافه کنید (برای هر سه محیط Production، Preview و Development):

| نام | مقدار | |
|---|---|---|
| `GITHUB_TOKEN` | توکن گام ۲ (`github_pat_…`) | ضروری |
| `GITHUB_REPO` | `tahahajiaghajani/portfolio-data` (نام کاربری/نام مخزن داده) | ضروری |
| `ADMIN_PASSWORD` | یک رمز قوی برای پنل `/admin` | ضروری |
| `APP_SECRET` | یک رشته‌ی تصادفی دست‌کم ۳۲ نویسه‌ای، مثلاً خروجی `openssl rand -hex 32` | ضروری |
| `NEXT_PUBLIC_SITE_URL` | نشانی نهایی سایت (بعد از گام ۷) | بعداً |
| `GEMINI_API_KEY` | لازم نیست؛ کلید را در پنل «اتصالات» وارد کنید | اختیاری |

5. **Deploy**. چند دقیقه بعد سایت روی `https://<نام پروژه>.vercel.app` بالا است.

> **APP_SECRET را گم نکنید و بی‌دلیل عوض نکنید.** کلیدهایی که در پنل ذخیره می‌کنید با آن رمز می‌شوند و پیوندهای پیگیری درخواست با آن امضا می‌شوند. اگر روزی مجبور شدید عوضش کنید، مقدار قبلی را در `APP_SECRET_PREVIOUS` بگذارید تا کلیدهای ذخیره‌شده خوانده شوند. پیوندهای پیگیری قدیمی در این حالت از کار می‌افتند.

**پیشنهاد (اختیاری):** این مخزن چند سایت دارد و Vercel با هر push همه را می‌سازد. در پروژه‌ی پورتفولیو → **Settings → Build and Deployment → Ignored Build Step** گزینه‌ی **Only build if there are changes in a folder** را بگذارید (یا دستور `git diff --quiet HEAD^ HEAD ./`)، تا فقط تغییرات پوشه‌ی `portfolio` آن را دوباره بسازد.

## ۴. پنل «اتصالات»: وصل کردن و آزمایش همه‌چیز

1. `https://<سایت>/admin` را باز کنید و با `ADMIN_PASSWORD` وارد شوید. این صفحه در منو نیست و در موتورهای جست‌وجو نمایه نمی‌شود.
2. به **اتصالات** بروید. بالای صفحه نوشته چند مورد از شش مورد آماده است. هر کارت وضعیت خودش را دارد: «آماده»، «نیاز به توجه»، «وصل نیست» یا «خاموش / اختیاری».
3. **مخزن داده (GitHub):** بررسی می‌کند توکن معتبر است، مخزن پیدا می‌شود، **خصوصی** است و Issues در آن روشن است. سپس روی **آماده‌سازی مخزن** بزنید تا این‌ها ساخته شوند:
   - `settings.json`
   - `knowledge.md`
   - یک README
   - برچسب‌ها (`request`، `status:*`، `kind:*`، `priority:*`، `assistant-unanswered`)

   اجرای دوباره‌اش بی‌خطر است.
4. **هوش مصنوعی (Google AI Studio):**
   1. در [aistudio.google.com/apikey](https://aistudio.google.com/apikey) با حساب Google وارد شوید، **Create API key** بزنید و کلید (`AIza…`) را کپی کنید. لایه‌ی رایگان کافی است.
   2. کلید را در کادر «کلید API» بچسبانید و **آزمایش اتصال** بزنید. یک درخواست واقعی کوچک فرستاده می‌شود و نام مدلی که پاسخ داد و زمان پاسخ نمایش داده می‌شود؛ اگر خطا بدهد، دلیلش به فارسی می‌آید.
   3. **ذخیره**. کلید پیش از ذخیره با `APP_SECRET` رمز می‌شود و فقط چهار نویسه‌ی آخرش در پنل دیده می‌شود.
   4. «مدل‌های ترجیحی» اختیاری است. بدون آن، این زنجیره‌ی رایگان به ترتیب امتحان می‌شود و اگر یکی شلوغ یا تمام‌شده باشد سراغ بعدی می‌رود: `gemini-3.5-flash-lite` ← `gemini-3.1-flash-lite` ← `gemini-3.6-flash` ← `gemini-3.8-flash`.
   5. با برداشتن تیک «دستیار روشن باشد»، دستیار پیام «در دسترس نیست» می‌دهد و درخواست‌ها بی‌تحلیل ثبت می‌شوند.
5. **اعلان درخواست‌ها (تلگرام / بله):** گام ۵ را ببینید. پس از ذخیره، **ارسال پیام آزمایشی** را بزنید.
6. **امنیت پنل**، **نشانی سایت** و **میزبانی (Vercel)** فقط وضعیت را نشان می‌دهند:
   - محیط و منطقه‌ی اجرا
   - نسخه‌ی منتشرشده (commit و شاخه)
   - تنظیم بودن `NEXT_PUBLIC_SITE_URL`

پس از هر تغییر در Vercel (متغیر تازه یا تغییر مقدار)، یک بار **Redeploy** کنید و در پنل **بررسی دوباره** بزنید. تغییرهای خود پنل فوری اثر می‌کنند و Redeploy لازم ندارند.

## ۵. ربات تلگرام یا بله (اختیاری)

هر درخواست تازه و هر پیام بازدیدکننده، همراه خلاصه‌ی فارسی هوش مصنوعی و پیوند پنل، برایتان فرستاده می‌شود.

**تلگرام:**
1. با [@BotFather](https://t.me/BotFather) گفتگو کنید، `/newbot` بزنید و توکن (`123456789:AA…`) را بگیرید.
2. به ربات تازه یک پیام بدهید (مثلاً `/start`).
3. `https://api.telegram.org/bot<TOKEN>/getUpdates` را در مرورگر باز کنید و عدد `chat.id` را بردارید.
4. در پنل → اتصالات → اعلان، کانال «تلگرام»، توکن و شناسه‌ی گفتگو را وارد و **ذخیره** کنید.

**بله:** ربات را در بله بسازید (از «بازوی» ساخت ربات) و به آن پیام بدهید. سپس `https://tapi.bale.ai/bot<TOKEN>/getUpdates` را باز کنید و شناسه را بردارید. در پنل کانال «بله» را انتخاب کنید.

GitHub هم برای هر Issue تازه اعلان می‌دهد (ایمیل یا اپ موبایل GitHub)، به شرط اینکه مخزن داده را **Watch** کرده باشید.

## ۶. کار روزانه با پنل

- **درخواست‌ها** (`/admin`): فهرست با فیلتر وضعیت. هر درخواست کد `TA-XXXXXX` دارد و این‌ها را نشان می‌دهد:
  - تحلیل هوش مصنوعی: نوع، اولویت، تناسب با کار شما و خلاصه‌ی فارسی
  - پیش‌نویس پاسخ آماده
  - گفتگو با بازدیدکننده

  پاسخی که از پنل می‌فرستید در صفحه‌ی پیگیری بازدیدکننده دیده می‌شود. وضعیت را عوض کنید (تازه، در حال بررسی، پاسخ داده شد، جلسه هماهنگ شد، بسته) یا «تحلیل دوباره» بزنید. «بسته» Issue را هم در GitHub می‌بندد.
- **یادداشت خصوصی:** هر دیدگاهی که مستقیم در GitHub زیر Issue بنویسید فقط در پنل (با برچسب «یادداشت خصوصی») دیده می‌شود و هرگز به بازدیدکننده نمی‌رسد.
- **پرسش‌های بی‌پاسخ:** فقط پرسش‌هایی نگه داشته می‌شوند که دستیار پاسخشان را نداشت. گفتگوهای کامل ذخیره نمی‌شوند.
- **دانش دستیار:** نکته‌های اضافه، مثل پروژه‌ی تازه یا زمان در دسترس بودن، را اینجا یا مستقیم در `knowledge.md` مخزن داده بنویسید. حداکثر تا ۵ دقیقه بعد در پاسخ‌ها اثر می‌کنند. دانش اصلی دستیار همیشه از محتوای خود سایت ساخته می‌شود.

## ۷. دامنه‌ی اختصاصی (اختیاری)

1. Vercel → پروژه → **Settings → Domains** → **Add** → دامنه را وارد کنید و رکوردهای DNS را که Vercel نشان می‌دهد نزد ثبت‌کننده‌ی دامنه بگذارید.
2. پس از سبز شدن، `NEXT_PUBLIC_SITE_URL` را روی نشانی دامنه (مثلاً `https://taha-aghajani.ir`) بگذارید و **Redeploy** کنید. پیوندهای اشتراک، نقشه‌ی سایت و پیوندهای اعلان از آن ساخته می‌شوند.

## ۸. محدودیت‌ها (صادقانه)

- **محدودیت نرخ** در حافظه‌ی همان نمونه‌ی سرور نگه داشته می‌شود:
  - هر بازدیدکننده: ۲۰ پیام در ۱۰ دقیقه و ۸۰ پیام در روز
  - کل سایت: `AI_DAILY_LIMIT` فراخوان در روز در هر نمونه (پیش‌فرض ۱۰۰۰)

  این جلوی سیل درخواست را می‌گیرد، ولی سقف واقعی همان سهمیه‌ی رایگان کلید Google است.
- **سقف GitHub:** ۵۰۰۰ درخواست در ساعت برای هر توکن. برای یک پورتفولیو بسیار بیشتر از نیاز است و پنل مقدار باقی‌مانده را نشان می‌دهد.
- **تأخیر تنظیمات:** تنظیمات و دانش اضافه تا ۵ دقیقه کش می‌شوند. ذخیره از خود پنل فوری اثر می‌کند، ولی ویرایش مستقیم در GitHub حداکثر ۵ دقیقه طول می‌کشد.
- **انقضای توکن:** پیش از انقضا، توکن تازه بسازید، در Vercel جایگزین کنید و Redeploy کنید.

## ۹. رفع اشکال

| پیام در پنل یا رفتار سایت | کار لازم |
|---|---|
| «مخزن پیدا نشد یا توکن به آن دسترسی ندارد» | `GITHUB_REPO` را دقیقاً به شکل `owner/name` بنویسید و در تنظیمات توکن همین مخزن را انتخاب کنید |
| «توکن GitHub نامعتبر یا منقضی است» | توکن تازه بسازید (گام ۲)، در Vercel عوض و Redeploy کنید |
| «GitHub نوشتن را نپذیرفت (403)» | دسترسی‌های Contents و Issues توکن باید **Read and write** باشند |
| «مخزن عمومی است!» | GitHub → مخزن داده → Settings → Danger Zone → Change visibility → Private |
| آزمایش هوش مصنوعی: «کلید پذیرفته نشد» | کلید تازه در AI Studio بسازید؛ کلیدی که جایی منتشر شده باشد را Google غیرفعال می‌کند |
| آزمایش هوش مصنوعی: «منطقه را نپذیرفت» | Vercel → Settings → Functions → Function Region را روی یک منطقه‌ی آمریکا یا اروپا (مثلاً Washington, D.C.) بگذارید و Redeploy کنید |
| فرم درخواست: «هنوز راه‌اندازی نشده» | `GITHUB_TOKEN` و `GITHUB_REPO` در Vercel نیستند یا پس از افزودن Redeploy نشده |
| ورود به پنل: «رمز درست نیست…» | `ADMIN_PASSWORD` و `APP_SECRET` هر دو باید تنظیم شده و Redeploy شده باشند |

## ۱۰. افزودن یا ویرایش پروژه‌ها

- هر پروژه یک فایل در `src/content/projects/` است (فارسی و انگلیسی کنار هم) و در `src/content/projects/index.ts` به فهرست اضافه می‌شود؛ ترتیب همان ترتیب نمایش است. `tier: "lab"` پروژه را از ریل اصلی بیرون می‌برد و فقط در فهرست کامل نشان می‌دهد.
- تصویرها در `public/media/work/<پروژه>/` (WebP، عرض حداکثر ۱۹۲۰) و ویدئوها H.264 بدون صدا با پوستر.
- دستیار هوش مصنوعی پروژه‌ی تازه را خودکار یاد می‌گیرد؛ دانشش از همین فایل‌ها ساخته می‌شود.
- پیش از push: `npm run typecheck` · `npm test` · `npm run build` (آزمون‌ها کامل بودن هر دو زبان و وجود همه‌ی فایل‌های رسانه را بررسی می‌کنند).

## ۱۱. اجرای محلی

```bash
cd portfolio
npm ci
npm run dev          # http://localhost:3000 و http://localhost:3000/en
```

برای پنل، درخواست‌ها و دستیار، یک فایل `.env.local` از روی `.env.example` بسازید و همان چهار متغیر ضروری را بگذارید. برای آزمایش بی‌خطر، یک مخزن خصوصی جدا و توکن جدا بسازید.
