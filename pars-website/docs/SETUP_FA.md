# راه‌اندازی سایت پارس (GitHub + Vercel + Supabase + Google AI Studio — همه رایگان)

سایت در پوشه‌ی `pars-website` همین مخزن است و یک پروژه‌ی مستقل Next.js به حساب می‌آید؛ به Task Flow وابسته نیست.

**بدون هیچ تنظیمی هم build می‌شود و بالا می‌آید.** هر قابلیت با تنظیم متغیر مربوط روشن می‌شود:

| قابلیت | نیازمند |
|---|---|
| صفحه‌های سایت، فارسی و انگلیسی | هیچ |
| دستیار هوش مصنوعی | کلید Google AI Studio (در پنل مدیریت یا `GEMINI_API_KEY`) |
| تیکت، دانش، دموها، گزارش گفتگوها، تنظیمات | Supabase |
| پنل مدیریت پنهان (`/admin`) | `ADMIN_PASSWORD` و `APP_SECRET` |
| اعلان تلگرام یا بله | پنل مدیریت → محتوای سایت |
| ایمیل به مشتری | `RESEND_API_KEY` و `MAIL_FROM` (اختیاری) |

---

## ۱. پایگاه داده (Supabase)

همه‌ی جدول‌ها با پیشوند `pars_` ساخته می‌شوند؛ پس **می‌توانید از همان پروژه‌ی Supabase اپ Task Flow استفاده کنید** (پلن رایگان دو پروژه دارد).

1. در [supabase.com](https://supabase.com) وارد پروژه شوید (یا پروژه‌ی تازه بسازید).
2. **SQL Editor** → New query → محتوای **همه‌ی فایل‌های** پوشه‌ی `supabase/migrations` را **به‌ترتیب نام**، هر کدام جدا، بچسبانید → **Run** (اکنون `20261022090000_pars_site.sql`، `20261022120000_pars_admin_counts.sql` و `20261022140000_pars_posts.sql`). اجرای دوباره بی‌خطر است. اگر سایت از قبل راه‌اندازی شده، فقط فایل‌های تازه را اجرا کنید (پس از هر به‌روزرسانی کد هم همین‌طور).
   **ساده‌ترین راه:** وارد پنل مدیریت شوید → **اتصالات**. آن‌جا هر جدول یا تابعی که ساخته نشده باشد قرمز است و دکمه‌ی «کپی SQL» دقیقاً همان فایل‌های لازم را کپی می‌کند؛ با «باز کردن SQL Editor» مستقیم به Supabase می‌روید.
3. **Project Settings → API** (یا **API Keys**):
   - **Project URL** → متغیر `SUPABASE_URL`
   - کلید **service_role** (یا کلید Secret جدید `sb_secret_…`) → متغیر `SUPABASE_SERVICE_ROLE_KEY`

> کلید service_role فقط روی سرور استفاده می‌شود و هرگز به مرورگر نمی‌رسد. همه‌ی جدول‌ها RLS فعال و بدون Policy دارند؛ یعنی با کلید عمومی (anon) هیچ داده‌ای خوانده نمی‌شود.

## ۲. انتشار روی Vercel

1. [vercel.com/new](https://vercel.com/new) → مخزن GitHub را Import کنید.
2. **Root Directory** را روی `pars-website` بگذارید (مهم). Framework خودکار Next.js تشخیص داده می‌شود.
3. در **Environment Variables** این‌ها را اضافه کنید:

| نام | مقدار |
|---|---|
| `SUPABASE_URL` | از مرحله‌ی ۱ |
| `SUPABASE_SERVICE_ROLE_KEY` | از مرحله‌ی ۱ |
| `ADMIN_PASSWORD` | یک رمز قوی برای ورود به `/admin` |
| `APP_SECRET` | یک رشته‌ی تصادفی ۳۲ نویسه‌ای یا بیشتر (برای امضای نشست و رمزنگاری کلیدهای API) |
| `NEXT_PUBLIC_SITE_URL` | آدرس نهایی سایت، مثلاً `https://pars-xxx.vercel.app` (بعداً دامنه‌ی اصلی) |
| `GEMINI_API_KEY` | اختیاری؛ کلید پیش‌فرض اگر در پنل کلیدی ذخیره نشده باشد |
| `AI_DAILY_LIMIT` | اختیاری؛ سقف روزانه‌ی مشترک همه‌ی بازدیدکننده‌ها برای استفاده از هوش مصنوعی (گفتگو، پیشنهاد پاسخ و تحلیل تیکت)، پیش‌فرض ۱۵۰۰. وقتی پر شود، تا روز بعد دستیار پیام «شلوغ است» می‌دهد و تیکت‌ها بدون تحلیل هوش مصنوعی ثبت می‌شوند؛ «تحلیل دوباره»ی دستی در پنل شمرده نمی‌شود. با این سقف، سهمیه‌ی رایگان کلید شما از سوءاستفاده در امان می‌ماند. |
| `CRON_SECRET` | اختیاری؛ فقط Vercel بتواند نشانی بیدار ماندن Supabase را صدا بزند |
| `RESEND_API_KEY` و `MAIL_FROM` | اختیاری؛ ایمیل به مشتری. ساده‌تر: از پنل مدیریت → «اتصالات» وارد کنید |

4. **Deploy**. چند دقیقه بعد سایت روی زیردامنه‌ی Vercel آماده است.

> **بیدار ماندن Supabase:** پروژه‌ی رایگان Supabase پس از یک هفته بی‌استفاده‌ماندن متوقف می‌شود. فایل `vercel.json` هر روز یک بار نشانی `/api/keepalive` را صدا می‌زند تا یک خواندن کوچک از پایگاه داده انجام شود؛ نیازی به کار اضافه نیست. اگر خواستید فقط خود Vercel بتواند این نشانی را صدا بزند، متغیر `CRON_SECRET` را با یک رشته‌ی تصادفی بگذارید.
>
> `APP_SECRET` کلیدهای API، توکن ربات و کلید دسترسی تیکت‌ها را رمزنگاری می‌کند. اگر آن را بعداً اضافه کنید، داده‌های قبلی (که با کلید Supabase رمز شده‌اند) خوانا می‌مانند. **برای تعویض:** مقدار فعلی را در `APP_SECRET_PREVIOUS` بگذارید، مقدار تازه را در `APP_SECRET` و Redeploy کنید؛ `APP_SECRET_PREVIOUS` را پاک نکنید، چون داده‌های قدیمی همچنان با آن خوانده می‌شوند (فقط یک مقدار قبلی پذیرفته می‌شود). اگر `APP_SECRET` جداگانه ندارید و کلید service_role را در Supabase عوض می‌کنید، مقدار قبلی آن کلید را در `APP_SECRET_PREVIOUS` بگذارید. پس از هر تعویض، مدیر باید دوباره وارد پنل شود.
>
> برای این‌که پروژه‌ی Task Flow با تغییرات این پوشه دوباره ساخته نشود: در پروژه‌ی Task Flow → Settings → Git → **Ignored Build Step** این دستور را بگذارید:
> `git diff HEAD^ HEAD --quiet -- . ':(exclude)pars-website'`

## ۳. دستیار هوش مصنوعی (رایگان با Google AI Studio)

1. از [aistudio.google.com/apikey](https://aistudio.google.com/apikey) یک کلید بسازید.
2. وارد `https://<سایت>/admin` شوید → **هوش مصنوعی** → کلید را وارد کنید → **ذخیره** → **آزمایش اتصال**.
3. مدل پیش‌فرض `gemini-flash-latest` است و اگر سهمیه‌ی رایگانش تمام شود، خودکار به `gemini-flash-lite-latest` و `gemini-2.5-flash-lite` می‌رود.
4. **دانش پارس** → «بارگذاری دانش اولیه برای ویرایش» → مدخل‌ها را بازبینی و کامل کنید. دستیار فقط از همین دانش پاسخ می‌دهد.

**ارتقا به API قوی (پولی):** در همان صفحه سرویس‌دهنده را عوض کنید (Claude با `claude-sonnet-5-5`، یا OpenAI و هر سرویس سازگار با OpenAI)، کلید را وارد و ذخیره کنید. نیازی به تغییر کد یا انتشار دوباره نیست.

## ۴. دامنه‌ی اختصاصی

1. پروژه در Vercel → **Settings → Domains** → **Add** → دامنه را وارد کنید (مثلاً `parspmi.ir` و `www.parspmi.ir`).
2. Vercel رکوردهای لازم را نشان می‌دهد؛ همان‌ها را در پنل DNS ثبت‌کننده‌ی دامنه وارد کنید (معمولاً رکورد `A` برای دامنه‌ی اصلی و `CNAME` برای `www`). گواهی SSL خودکار صادر می‌شود.
3. متغیر `NEXT_PUBLIC_SITE_URL` را به دامنه‌ی جدید تغییر دهید و یک بار **Redeploy** کنید.

## ۵. اعلان‌ها (اختیاری)

- **تلگرام:** با @BotFather ربات بسازید، آن را به گروه تیم اضافه کنید و `chat_id` گروه را بردارید.
- **بله:** از «بازو»ی بله ربات بسازید (همان API تلگرام).
- پنل مدیریت → **محتوای سایت** → «اعلان تیکت‌ها» → کانال، توکن و `chat_id` → ذخیره → «ارسال پیام آزمایشی».
- **ایمیل به مشتری** هنگام پاسخ تیم: در [resend.com](https://resend.com) (پلن رایگان) دامنه را تأیید کنید و `RESEND_API_KEY` و `MAIL_FROM` (مثلاً `پشتیبانی پارس <support@parspmi.ir>`) را در Vercel بگذارید.

## ۶. پنل مدیریت

نشانی: `https://<سایت>/admin` با رمز `ADMIN_PASSWORD`. برای بازدیدکننده‌ها هیچ پیوندی به آن نیست و موتورهای جستجو آن را ایندکس نمی‌کنند؛ ولی پس از یک بار ورود، روی همان مرورگر دکمه‌ی کوچک «پنل مدیریت» در گوشه‌ی صفحه‌های سایت نمایش داده می‌شود.

| بخش | کار |
|---|---|
| پیشخوان | وضعیت تیکت‌ها، مهلت پاسخ (SLA)، رضایت، آمار دستیار و سلامت سامانه |
| تیکت‌ها | فیلتر و جستجو، تحلیل هوش مصنوعی (دسته، اولویت، لحن، خلاصه)، پاسخ با پیش‌نویس هوشمند، یادداشت داخلی، پیوند مشتری |
| گفتگوهای دستیار | پرسش‌ها و پاسخ‌ها، پرسش‌های بی‌پاسخ و بازخورد منفی، «افزودن به دانش» با یک کلیک |
| دانش پارس | ویرایش، ورود و خروجی JSON، آزمایش دستیار با دانش فعلی |
| هوش مصنوعی | سرویس‌دهنده، کلید، مدل و مدل‌های جایگزین، دستورهای تکمیلی، پیام خوشامد، پرسش‌های پیشنهادی و محدودیت استفاده |
| دموها | هر تعداد پیوند دمو با ترتیب‌دهی |
| وبلاگ | نوشتن و ویرایش نوشته‌ها (Markdown با پیش‌نمایش)، پیش‌نویس با هوش مصنوعی، انتشار فارسی در `/blog` و انگلیسی در `/en/blog` |
| محتوای سایت | مدیرعامل، تماس، شبکه‌های اجتماعی، آمار صفحه‌ی اول و اعلان‌ها |
| اتصالات | وضعیت سبز/زرد/قرمز Supabase (و جدول‌های ساخته‌نشده با SQL آماده)، هوش مصنوعی (ثبت کلید و آزمایش)، اعلان تلگرام/بله، ایمیل Resend (ثبت کلید و ارسال آزمایشی)، امنیت، نشانی سایت و اجرای روزانه‌ی بیدار ماندن Supabase |

## ۷. دسترسی از داخل ایران

- دامنه‌های `vercel.app` گاهی در ایران محدود می‌شوند؛ با دامنه‌ی اختصاصی وضعیت بهتر است، اما تضمینی نیست. برای دسترسی پایدار داخلی، می‌توانید یک CDN داخلی (مثل ابرآروان) جلوی دامنه بگذارید یا سایت را روی سرور داخلی اجرا کنید:
  ```bash
  cd pars-website && npm ci && npm run build && npm start   # پورت 3000
  ```
- سرورهای Vercel خارج از ایران‌اند و به Google AI Studio دسترسی دارند. **اگر سایت را روی سرور داخل ایران میزبانی کنید**، APIهای Google، Anthropic و OpenAI از ایران در دسترس نیستند؛ در پنل → هوش مصنوعی، یک «آدرس پایه‌ی API» واسط (Relay) یا سرویس سازگار با OpenAI وارد کنید.
- فونت‌ها و همه‌ی فایل‌ها روی خود سایت میزبانی می‌شوند و بازدیدکننده به هیچ CDN خارجی درخواست نمی‌فرستد.

## ۸. توسعه‌ی محلی

```bash
cd pars-website
npm install
cp .env.example .env.local   # مقادیر را پر کنید (اختیاری)
npm run dev                   # http://localhost:3000
npm run typecheck && npm test && npm run build
```
